The Agent Platform is provider-neutral. Your agents can use models from multiple LLM providers, and you can switch between them without changing your agent definitions. This page covers how to add provider credentials, register models, configure model settings, and set the credential policy for your workspace.

- Required role: Owner or Admin

- Navigate to AI Configuration > LLM Providers in the Studio sidebar. The page is organized into three tabs:

* Credentials - Add and manage provider API credentials
* Model Catalog - Register models, set defaults, and configure model settings
* Policy - Configure the credential policy for your workspace

## How LLM Providers Work

Model configuration in the Agent Platform follows a layered approach:

* Workspace-level credentials - You register API credentials for each provider. These credentials become available to models across all projects in the workspace.
* Model Catalog - Each registered model is linked to a credential, assigned to a tier (Fast, Balanced, Powerful, or Voice), and configured with hyperparameters. Agents reference tiers, not specific models, which lets you swap underlying models without changing agent definitions.
* Model resolution chain - When the Runtime executes an agent, it resolves the model through a 5-level priority cascade, stopping at the first match:

| Priority | Source             | Description                                                                 |
|----------|--------------------|-----------------------------------------------------------------------------|
| 0        | Deployment override| Model pinned to a specific deployment (for example, an A/B test)           |
| 1        | Agent DSL          | Model or operation_models declared in the `.agent.abl` file                 |
| 2        | Agent DB config    | Per-agent model override in the agent settings UI                           |
| 3        | Project DB config  | Project-level `ModelConfig` with tier-to-model mapping                       |
| 4        | Tenant model       | Workspace-level default model for the resolved tier                         |

If no model is resolved at any level, the request fails with a clear error. The platform never falls back to a hard-coded default.

### Fallback Chains

Configure fallback models to handle provider outages or rate limits. When the primary model fails (timeout, rate limit, or provider error), the Runtime automatically retries with each fallback in order. Fallback is transparent to the agent - it receives a response regardless of which model served it.

When the primary model fails, the Runtime retries with each fallback in the order listed. The platform tracks which model served the request, and this is visible in analytics.

#### Configuring Fallback Models

To configure fallback models:

1. Go to Settings > AI Configuration > Models.
2. Select a registered model.
3. In the Fallback section, add one or more fallback models in priority order.
4. Click Save.

#### Cost and Token Tracking

Every LLM call tracks token usage and estimated cost, broken down by agent, project, model, and time period:

| Metric         | Description                                                                 |
|----------------|-----------------------------------------------------------------------------|
| Input tokens   | Tokens sent to the model (system prompt, conversation history, tool definitions) |
| Output tokens  | Tokens generated by the model (response text and tool calls)                |
| Estimated cost | Calculated from token counts and the model's known pricing                  |
| Model used     | Which model served the request (important when fallbacks are in play)       |
| Latency        | Time-to-first-token and total request duration                              |

### Context Window Management

The Runtime automatically manages the context window to stay within model limits:

* Tool result compression - Large tool results are compressed before being added to the conversation.
* Prior turn truncation - Tool results from previous turns are replaced with short placeholders.
* Conversation compaction - When conversation history grows beyond a threshold (configured via Compaction Threshold), older messages are summarized to reduce token usage while preserving important context.

## Credentials

The Credentials tab lists all provider credentials registered in your workspace, grouped by provider. Each credential card shows the credential name, provider tag, creation date, and the number of models using that credential.

**Adding a Credential**

1. Go to AI Configuration > LLM Providers > Credentials.
2. Click + Add Credential.
3. Fill in the following fields:
    * Name - A descriptive label for this credential (for example, Production OpenAI).
    * Provider - Select the LLM provider from the dropdown.
    * API Key - Enter the provider's API key.
4. Click Add Credential.

<Note>API keys are encrypted at rest and never displayed in plaintext after the initial entry.</Note>

**Delete a Credential**

Click the delete icon on the credential card. Deleting a credential disconnects all models linked to it. Those models display a No Keys status in the Model Catalog until a new credential is connected.

## Model Catalog

The Model Catalog tab lists all models registered in your workspace. Each row shows the provider, model name, model ID, connections (credentials linked), and status.

The top of the page shows the current DEFAULT MODEL with a Change Default button.

### Setting the Default Model

The default model is used when no other model is resolved through the model resolution chain. To change it, click the star icon on any model row, or click Change Default in the default model banner.

#### Add a Model from the Catalog

1. Go to AI Configuration > LLM Providers > Model Catalog.
2. Click **+ Add Model**, browse or search for a provider model, review and configure the available model settings, and then click **Add to Workspace**. 

#### Add a Custom Model

1. Go to AI Configuration > LLM Providers > Model Catalog.
2. Click + Add Model.
3. Select the Custom Model tab.
4. Fill in the following fields:
    * Display Name - A label for this model in the platform.
    * Model ID - The model identifier (for example, gpt-4o or claude-sonnet-4-20250514).
    * Provider - Select the provider this model belongs to.
    * Tier - Assign the model to a tier: Fast, Balanced, Powerful, or Voice.
    * Temperature - Controls response randomness (default: 0.7).
    * Max Tokens - Maximum tokens the model can generate per response (default: 4096).
    * Endpoint URL (optional) - For custom or self-hosted endpoints.
5. Click Add to Workspace.

**Configuring Model Settings**

Expand any model row in the Model Catalog to view and edit its settings.

Connections section:

* Shows credentials currently linked to this model.
* Click + Add Key to connect a credential from the Credentials tab.
* If no credentials are configured, the model shows a "No Keys" status and cannot serve requests.

**Settings section:** Configure **Temperature**, **Max Output Tokens**, **Top P**, **Compaction Threshold**, **Tier**, and **Response Mode** based on your requirements. 

Capabilities (checkboxes): Enable the capabilities supported by the model - **Default for Tier**, **Tools**, **Vision**, **Streaming**, and **Realtime Voice** - then click **Save** to apply, or **Delete** to remove the model from the workspace. 

**Model Tiers**

Model tiers decouple agent definitions from specific model choices. Agents reference tiers, and the platform resolves the tier to a specific model at runtime.

| Tier      | Intended use                                   | Typical models                                      |
|-----------|-----------------------------------------------|-----------------------------------------------------|
| Fast      | Classification, routing, quick responses       | Claude 3.5 Haiku, GPT-4o mini, Gemini 2.0 Flash     |
| Balanced  | General-purpose tasks balancing quality and cost | Claude 4 Sonnet, GPT-4o, Gemini 2.5 Flash           |
| Powerful  | Complex reasoning, analysis, content generation | Claude 4 Opus, o3, Gemini 2.5 Pro                   |
| Voice     | Real-time voice interaction                    | GPT-4o Realtime, Gemini 2.0 Flash (Live)            |

### Project-Level Overrides

Projects inherit the workspace's model configuration but can customize how tiers map to operations. Go to Project > Settings > LLM Configuration and select the tier override for each operation:

| Operation        | Default tier | Description                                   |
|------------------|--------------|-----------------------------------------------|
| `extraction`     | Balanced     | Parsing structured data from user input       |
| `validation`     | Fast         | Input validation and format checking          |
| `tool_selection` | Balanced     | Choosing which tool to invoke                 |
| `response_gen`   | Balanced     | Generating user-facing responses              |
| `summarization`  | Balanced     | Summarizing conversations or documents        |
| `reasoning`      | Powerful     | Multi-step reasoning and analysis             |
| `coordination`   | Balanced     | Supervisor routing and orchestration          |
| `realtime_voice` | Voice        | Real-time voice interactions                  |

These overrides apply only to the current project. Other projects continue using the workspace defaults.

## Policy

The Policy tab controls how the platform resolves credentials when multiple credential sources are available.

### Credential Policy

Select one of the following options and click Save Policy:

| Option             | Description                                                                 |
|--------------------|-----------------------------------------------------------------------------|
| Organization First | Try organization-managed credentials first; fall back to user-provided keys if no org credentials are available. |
| User First         | Try user-provided credentials first; fall back to organization-managed keys. |
| Organization Only  | Only organization-managed credentials are allowed. Users cannot bring their own keys. |
| User Only          | Only user-provided credentials are allowed. The organization does not centrally manage keys. |

### Troubleshooting

| Issue                                | Potential Causes                                                   | Resolution                                                                                                                         |
|--------------------------------------|--------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------|
| Model shows **No Keys** status       | No credential linked to the model                                  | Expand the model row and click **+ Add Key** in the *Connections* section to connect a credential.                                |
| Model validation fails               | Invalid API key, incorrect endpoint URL, or blocked outbound connections | • Confirm the API key is valid by testing it directly with the provider’s API. <br /> • For Azure deployments, verify the endpoint URL includes the deployment name. <br /> • Check that your workspace network or proxy configuration allows outbound HTTPS connections to the provider. |
| Agent cannot find a model for the requested tier | No active model assigned to the tier, or linked credential is inactive | • Verify that at least one active model is assigned to the tier and shows a **Ready** status. <br /> • Check that the model’s linked credential is active. |
| Token budget exceeded                | High token consumption across operations                           | • Review current consumption in *Account > Billing & Usage*. <br /> • Consider switching high-volume operations to a **Fast-tier** model to reduce token usage. |
