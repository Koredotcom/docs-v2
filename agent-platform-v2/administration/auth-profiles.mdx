**Workspace Auth Profiles:** Manage tenant-level authentication credentials shared across all projects.

**Navigation:** Settings > AI Configuration > Auth Profiles 

**Required role:** Owner or Admin

Auth profiles store authentication configurations that agent tools use to call external services securely. Profiles are managed centrally at the workspace level and reused across all projects. The page is organized into two tabs: 

* All Profiles
* Integrations

**All Profiles**

The All Profiles tab lists all auth profiles configured for the workspace. Use the toolbar to find and filter profiles:

| Property        | Description                               |
|-----------------|-------------------------------------------|
| Search profiles | Search by profile name.                   |
| All Types       | Filter profiles by authentication type.   |
| All Statuses    | Filter profiles by status (active or inactive). |

**Add a Profile**

Click Add Profile to create a new auth profile. Two profile types are available:

| Property            | Description                                                                 |
|---------------------|-----------------------------------------------------------------------------|
| Custom Profile      | Configure a custom authentication scheme with manually specified credentials and settings. |
| Integration Profile | Configure authentication for a supported third‑party integration.            |

**Supported Auth Types**

| Property     | Description                                                                 |
|--------------|-----------------------------------------------------------------------------|
| OAuth 2.0    | Authorization code, client credentials, and implicit flows                  |
| API key      | Header or query parameter injection                                         |
| Bearer token | Static or dynamically refreshed bearer tokens                               |
| Basic auth   | Username and password combinations                                          |
| Custom       | Arbitrary header or body injection for non‑standard auth schemes            |

Auth profile credentials are encrypted at rest and never exposed in logs or agent responses.

<Note>: Guardrail providers that require credentials must reference an auth profile. Raw API keys are not accepted directly in the guardrail provider configuration.</Note>

**Integrations**

The Integrations tab lists auth profiles configured for supported third-party integrations. Integration profiles are created using the Integration Profile option from the Add Profile menu.

**Using Auth Profiles**

Once created, an auth profile can be referenced by name in tool configurations and guardrail provider settings. The platform resolves the profile at runtime and injects the correct credentials without exposing them in agent definitions, logs, or traces.
