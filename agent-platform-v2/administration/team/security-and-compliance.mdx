Security in the Agent Platform is a structural property of the system. Every query, every session, and every piece of data is scoped to its owner. This page covers authentication configuration, MFA, SSO, and audit logging for your workspace.

Navigation: Go to **Team** > **Security & Compliance** in the Studio sidebar. The page is organized into the following tabs:

- **MFA** - Configure multi-factor authentication for your workspace.
- **SSO** - Set up single sign-on and domain verification.
- **Audit Logs** - View and filter workspace activity logs.

Required role: **Owner** or **Admin**

## Multi-Factor Authentication (MFA)

MFA adds an additional verification step using a time-based one-time password (TOTP).

### Enabling MFA

Go to **Team** > **Security & Compliance**, click **Enable MFA**, complete the authenticator app setup, enter the verification code, and then click **Verify & Enable**.

### Recovery Codes

Recovery codes are generated during MFA setup and can be used to access your account if you lose access to your authenticator app.

- Each recovery code can only be used once.
- Store recovery codes securely.
- Regenerating recovery codes invalidates previously issued codes.

### Enforcing MFA for the Workspace

Workspace Owners and Admins can require MFA for all members from the **MFA** tab by enabling **Require MFA for all members** and selecting a grace period.

When enabled:

- New members must configure MFA before accessing the workspace.
- Existing members must complete MFA setup within the grace period.
- Members who don't complete setup are locked out until MFA is configured.

## Single Sign-On (SSO)

SSO allows users to authenticate using an external identity provider (IdP).

Plan requirement: **Enterprise plan only**

Supported protocols:

- **SAML 2.0** - Supports providers such as Okta, Azure AD, and OneLogin.
- **OpenID Connect (OIDC)** - Supports OAuth 2.0-based providers such as Auth0 and Keycloak.

### Setting up SAML SSO

Go to **Team** > **Security & Compliance** > **SSO**, select **SAML 2.0**, enter the required SAML configuration details, and click **Save Configuration**.

### Setting up OIDC SSO

Go to **Team** > **Security & Compliance** > **SSO**, select **OpenID Connect**, enter the required OIDC configuration details, and click **Save Configuration**.

### Domain Verification

Use the **Domain Verification** section in the **SSO** tab to claim and verify your organization’s email domain before enforcing SSO.

### Force SSO

Enable **Force SSO** from the **SSO** tab to require users with verified domain email addresses to authenticate through SSO.

When enabled:

- Password-based login is disabled for verified domain users.
- Users outside the verified domain are unaffected.
- Workspace Owners retain password-based login access as a fallback.

### Google Authentication Fallback

Enable **Allow Google fallback** to allow users to sign in with Google if the configured SSO provider is unavailable.

## Audit Logs

Audit logs provide a record of workspace activity for security monitoring and compliance tracking.

### Viewing Audit Logs

Go to **Team** > **Security & Compliance** and open the **Audit Logs** tab to view activity records.

The log includes the following details:

| Column | Description |
| --- | --- |
| Action | Type of operation performed |
| Timestamp | Time the action occurred |
| IP Address | IP address of the request |
| Details | Additional event information |

### Filtering Audit Logs

Use the filter controls above the log table to filter logs by action type or date range, and click **Apply** to update the results.
