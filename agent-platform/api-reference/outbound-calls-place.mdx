Places an outbound call through the given channel connection. Returns immediately once the call has been accepted for submission. This does not wait for the call to ring or connect. The response returns the `outboundCallId`, the initial `phase` (`accepted`), and the `initiationState`. The request needs the `outbound_calls.initiate` scope.

Returns `201` on a genuinely new call. Repeating the exact same `idempotencyKey` and body returns `200` with the original call instead of placing a duplicate one. Reusing a key with a different body returns `409 IDEMPOTENCY_CONFLICT`.

The request requires `channelConnectionId`, `to`, and `idempotencyKey`. Set `to` to a phone number in E.164 format or to a SIP URI. Optional fields are `clientReferenceId` to correlate the call with your own records, `amdMode` (`off`, `continue`, or `disconnect`) for answering-machine detection, and `sessionMetadata` to attach to the session that starts when the call connects. A `502` error means the call could not be submitted to the telephony provider. If the error code is `OUTBOUND_PROVIDER_REQUEST_UNKNOWN`, check the call's `initiationState` shortly after instead of resubmitting. To track the call, use [Look up a call by ID](/agent-platform/api-reference/outbound-calls-id) or [Events of outbound calls](/agent-platform/api-reference/outbound-calls-events).
