---
title: List session summaries
description: List one summary row per conversation session in a project, with its channel, outcome, message count, token usage, and cost.
openapi: "/agent-platform/api-specs/sessions.yaml get /api/public/analytics/projects/{projectId}/sessions"
---

<Badge icon="arrow-left" color="gray">[Back to the Analytics APIs overview](/agent-platform/api-reference/analytics-overview)</Badge>

Use this endpoint to retrieve session-level analytics for a project. Each result represents one conversation session and includes summary information such as the channel, environment, status, containment outcome, message and trace-event counts, token usage, cost, and session duration. The response doesn't include the individual messages or trace details. Use [List conversation messages](/agent-platform/api-reference/analytics-list-conversation-messages) and [List trace events](/agent-platform/api-reference/analytics-list-traces) to retrieve those details.

Authenticate with the `x-api-key` header. The key must be bound to the project you are querying and have the `session:read` permission.

It provides the following filters:

- `fromDate`: Inclusive start timestamp.
- `toDate`: Exclusive end timestamp.
- `sessionIds`: Filter by specific session IDs; up to 10,000.
- `containmentType`: Filter by how the session was resolved, such as `contained_resolved`, `contained_partial`, `escalated`, or `abandoned`. Values are case-sensitive.
- `environment`: Filter by environment: `dev`, `staging`, `production`, or `working-copy`. Use `dev`, not `development`.
- `channelUId`: Filter by the end-user identity recorded on the channel.
- `callerNumber`: Filter by caller number or caller identity.
- `channel`: Filter by the channel through which the conversation originated. Shorthand works, so `web`, `sdk_web`, and `web_chat` all return the same web chat sessions. A voice channel such as `voice_pipeline` returns all voice sessions.
- `traceDimensions[key]`: Filter by custom session dimensions and their values.
- `status`: Filter by session state, such as `active`, `idle`, `ended`, `completed`, `escalated`, or `abandoned`. Pass a single value. The value `failed` is not accepted as a filter.

You must provide either `fromDate` and `toDate` together, or `sessionIds`. All other filters are optional. Multiple filters are combined with `AND` logic; multiple values within a filter are combined with `OR` logic.

Use `limit` (1 to 10,000, default 100) and `offset` to paginate through the results. A page can hold fewer sessions than `limit` so the response stays within 1 MiB. Check `hasMore` instead of assuming that a short page is the last one.
