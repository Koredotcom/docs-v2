Use this endpoint when you need the same trace data and filtering capabilities as [the corresponding GET endpoint](/agent-platform/api-reference/analytics-list-traces), but want to send the query parameters in the request body instead of the URL. The `POST` endpoint accepts the same parameters and returns the same response as `GET`.

When request encryption is enabled for the Platform Key, send the `TracesQueryBody` as an encrypted JWE. When request encryption is disabled, send the same parameters as a plain JSON object. Response encryption is independent of request encryption; when enabled, responses other than `401` are returned as encrypted JWE payloads. Each encrypted response uses the `EncryptedResponse` schema and carries the `X-ABL-Encrypted: true` header.

The `POST` endpoint supports the same filtering parameters as `GET`. The `POST` body uses the `GET` parameter names as JSON property names. List parameters can be sent as JSON arrays or comma-separated strings. `traceDimensions` is not a parameter in this Traces API; do not use it with this endpoint.

To return the response headers of HTTP tool calls, send `includeResponseHeaders` as a JSON boolean. It works as it does in the `GET` endpoint and needs `"dataMode": "full"`. The default is `false`. A request with `includeResponseHeaders` set to `true` and no `full` data mode returns `400 INVALID_PARAM_COMBINATION`. A non-boolean value returns `400 INVALID_INCLUDE_RESPONSE_HEADERS`. For the response fields, see [Response headers](/agent-platform/api-reference/analytics-list-traces#response-headers).

The response is the same as for `GET`. Workflow tool events include `workflowRun`, and `meta.warnings` appears when part of the page can't be served in full. For details, see [Workflow runs](/agent-platform/api-reference/analytics-list-traces#workflow-runs) and [Warnings](/agent-platform/api-reference/analytics-list-traces#warnings).

Use `POST` method when:

- You must encrypt the request parameters.
- You want to avoid exposing potentially sensitive filter values in the URL.
- You need to send the query as a JSON object rather than URL query parameters.

When request encryption is enabled, the plaintext query object is encrypted as a flattened JWE using the configured Platform Key and sent as an `EncryptedRequest`. A plaintext `POST` body is rejected when request encryption is enabled, while an encrypted body is rejected when request encryption is disabled.

Send an unencrypted body as `application/json`. Prefer `application/jose+json` for an encrypted body. The body must be a JSON object. Do not add query parameters to a `POST` request.
