Use this endpoint to retrieve the same session-level analytics as the [corresponding GET operation](/agent-platform/api-reference/analytics-list-session-summaries), but send the query parameters in a JSON request body instead of the URL query string. It supports the same filters, pagination, validation, permissions, and response format as the GET operation.

Use the `POST` endpoint when the request parameters must be encrypted. With request encryption enabled for the Platform Key, send the query object as a JWE encrypted request. With request encryption disabled, send the parameters as a plain JSON object. Response encryption is independent of request encryption; when enabled, responses other than `401` are returned as encrypted JWE payloads. Each encrypted response uses the `EncryptedResponse` schema and carries the `X-ABL-Encrypted: true` header.

The request body uses the `SessionsQueryBody` schema. Send it as `application/json` when request encryption is disabled. When request encryption is enabled, send it encrypted as an `EncryptedRequest`. Prefer `application/jose+json` for the encrypted body. Don't add a query string to the request. Send `traceDimensions` as an object of dimension names and values, for example `{"traceDimensions": {"accountTier": "gold"}}`.

Send `source` and `channelType` as a string, a JSON array, or a comma-separated string. `source` defaults to `user_initiated`, as in the GET operation. Send `channelUId` as a JSON array or a comma-separated string. Each array entry is one value and isn't split on commas. This POST form is the recommended way to look up an end user, because the identifier stays out of URLs that proxies and access logs can record. Send `dispositionCode` as a string of up to 200 characters. Send `callerNumber` as a JSON array of caller values in any provider format, or as a comma-separated string. You don't need URL encoding, so `+` is safe. Each entry must have at least one letter or digit and at most 512 characters. An empty array returns `400`. For the matching rules, see [Filter by caller number](/agent-platform/api-reference/analytics-list-session-summaries#filter-by-caller-number).

For filter details, see the [GET endpoint help article](/agent-platform/api-reference/analytics-list-session-summaries). The same sections cover [Source](/agent-platform/api-reference/analytics-list-session-summaries#source), [Channel and channel type](/agent-platform/api-reference/analytics-list-session-summaries#channel-and-channel-type), and [Filter by end user](/agent-platform/api-reference/analytics-list-session-summaries#filter-by-end-user).
