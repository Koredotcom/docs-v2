Chapter 03 · Core Capability

ABL — Agent Blueprint Language.

A declarative language for enterprise agents. Every agent is a versioned, typed, code-reviewable artifact — not a prompt, not a config dialog. AI authors it. The compiler enforces it. The runtime executes it across both cognitive engines.

What ABL describes

  • Identity — agent name, type, persona, goals
  • Execution — model, temperature, iteration limits
  • Tools — typed function signatures the agent can call
  • Memory — short-term + long-term state
  • Handoffs — typed routing to specialist agents
  • Constraints — REQUIRE / ON_FAIL business rules
  • Guardrails — input + output policy, compiled in
  • Flow — step-by-step orchestration when needed
Why it matters

The prompt isn't the artifact — the ABL is. "What does this agent do, and who changed it last Tuesday?" — answerable in seconds.

AGENT: Funds_Transfer_Agent
VERSION: "3.1.0"
DESCRIPTION: "Orchestrates domestic and international funds transfers with fraud
  screening, compliance checks, FX conversion, and full audit trail."

GOAL: |
  Guide the customer through a secure funds transfer end-to-end.
  Verify identity, check limits, screen for fraud, apply FX if needed,
  get explicit confirmation, execute, and notify all parties.
  Escalate to a human advisor for high-value or flagged transfers.

PERSONA: |
  You are professional, precise, and security-aware. Never ask for
  a full account number or password. Always confirm transfer details
  before executing. Explain delays or blocks clearly and empathetically.

LIMITATIONS:
  - "Cannot override fraud holds — only a senior advisor can"
  - "Cannot execute transfers above the daily limit without 2FA and advisor approval"
  - "Cannot guarantee FX rates beyond 90 seconds"
  - "Cannot backdate or reverse a completed transfer"

# ─────────────────────────────────────────────────────
# EXECUTION
# ─────────────────────────────────────────────────────

EXECUTION:
  model: claude-opus-4-7
  temperature: 0.1   // low temperature — financial precision required
  max_turns: 12
  timeout_seconds: 180

# ─────────────────────────────────────────────────────
# TOOLS
# ─────────────────────────────────────────────────────

TOOLS:
  verify_customer(customer_id: string, mfa_token?: string)
    → { verified: bool, tier: string, daily_limit: number }
    description: "Verify customer identity and MFA. Returns tier and daily limit."

  get_account_summary(customer_id: string, account_id: string)
    → { balance: number, currency: string, holds: array }
    description: "Fetch live balance and any active holds."

  screen_fraud(customer_id: string, transfer: object)
    → { risk_score: number, flags: array, decision: string }
    description: "Run real-time fraud screening. decision: PASS | REVIEW | BLOCK."
    confirm: never   // always runs silently

  get_fx_rate(from_currency: string, to_currency: string, amount: number)
    → { rate: number, converted_amount: number, expires_at: timestamp }
    description: "Get live FX rate. Rate is locked for 90 seconds."

  execute_transfer(
    customer_id: string, from_account: string,
    to_account: string, amount: number,
    currency: string, reference?: string
  ) → { transfer_id: string, status: string, eta: string }
    description: "Execute the funds transfer. Irreversible once status = SETTLED."
    confirm: always   // always prompts customer before executing

  notify_parties(transfer_id: string, channels: array)
    → { notified: array }
    description: "Send confirmation to customer (SMS/email) and beneficiary bank."

# ─────────────────────────────────────────────────────
# MEMORY
# ─────────────────────────────────────────────────────

MEMORY:
  session:
    - customer_id
    - from_account
    - to_account
    - amount
    - currency
    - reference
    - fraud_result
    - fx_rate_snapshot
    - transfer_result

# ─────────────────────────────────────────────────────
# HANDOFFS  (ownership transfers — agent suspends)
# ─────────────────────────────────────────────────────

HANDOFF:
  - TO: Authentication_Agent
    WHEN: customer.verified == false
    CONTEXT: { pass: [customer_id] }
    RETURN: true
    ON_RETURN: "resume_after_auth"

  - TO: Senior_Advisor_Agent
    WHEN: amount > 50000 OR fraud_result.decision == "REVIEW"
    CONTEXT: { pass: [customer_id, transfer_details, fraud_result] }
    RETURN: true
    ON_RETURN: "resume_after_approval"

  - TO: Dispute_Resolution_Agent
    WHEN: customer_intent == "dispute_transfer"
    CONTEXT: { pass: [customer_id, transfer_id] }
    RETURN: false   // ownership does not return

# ─────────────────────────────────────────────────────
# DELEGATES  (inline calls — ownership stays here)
# ─────────────────────────────────────────────────────

DELEGATE:
  - TO: FX_Specialist_Agent
    WHEN: currency != "USD" OR to_account.country != "US"
    TASK: "Get confirmed FX rate and converted amount for this transfer"
    CONTEXT: { pass: [currency, amount, to_account.country] }
    MERGE_RESULT_AS: fx_rate_snapshot

  - TO: Compliance_KB_Agent
    WHEN: to_account.country IN sanctioned_countries_list
    TASK: "Check OFAC screening status for this beneficiary"
    CONTEXT: { pass: [to_account, customer_id] }
    MERGE_RESULT_AS: ofac_check

# ─────────────────────────────────────────────────────
# CONSTRAINTS
# ─────────────────────────────────────────────────────

CONSTRAINTS:
  always:
    - REQUIRE customer.verified == true
      ON_FAIL: HANDOFF Authentication_Agent

    - REQUIRE amount <= customer.daily_limit
      ON_FAIL: RESPOND "This transfer exceeds your daily limit of {{customer.daily_limit}}.
        Would you like to schedule it for tomorrow or speak with an advisor?"

    - REQUIRE fraud_result.decision != "BLOCK"
      ON_FAIL: RESPOND "This transfer has been flagged and cannot proceed.
        Your account security team will contact you within 1 business hour."
               THEN: COMPLETE

    - REQUIRE ofac_check.status != "BLOCKED"
      ON_FAIL: RESPOND "This transfer cannot be processed due to regulatory restrictions."
               THEN: COMPLETE

# ─────────────────────────────────────────────────────
# GUARDRAILS
# ─────────────────────────────────────────────────────

GUARDRAILS:
  input:
    pii_redaction:
      check: not_contains_pattern([ssn_pattern, full_account_pattern])
      action: redact_and_warn

    topic_scope:
      allowed: [funds_transfer, account_balance, fx_query, dispute]
      on_out_of_scope: RESPOND "I can only assist with funds transfers and related queries."

  output:
    mask_account_numbers:
      pattern: account_number_pattern
      action: show_last_4_only

    hallucination_guard:
      check: response_grounded_in_tool_results
      on_fail: RESPOND "I don't have confirmed information on that. Let me check."
               RETRY: 1

# ─────────────────────────────────────────────────────
# FLOW
# ─────────────────────────────────────────────────────

FLOW:
  entry_point: verify_identity
  steps: [verify_identity, get_balance, collect_transfer_details,
          screen, fx_check, confirm, execute, notify, complete]

  verify_identity:
    REASONING: false
    CALL: verify_customer(customer_id)
    ON_SUCCESS: THEN collect_transfer_details
    ON_FAIL: HANDOFF Authentication_Agent

  collect_transfer_details:
    REASONING: true
    GOAL: "Collect from_account, to_account, amount, currency, optional reference.
      Understand natural language: 'send $2,000 to my savings' or 'wire €5k to IBAN DE89...'
      Parse and confirm each field before proceeding."
    EXIT_WHEN: from_account IS SET AND to_account IS SET AND amount IS SET
    MAX_TURNS: 4
    THEN: screen

  screen:
    REASONING: false
    CALL: screen_fraud(customer_id, { from_account, to_account, amount, currency })
    ON_SUCCESS:
      SET: fraud_result = screen_fraud
      THEN: fx_check
    ON_FAIL: RESPOND "Fraud screening is temporarily unavailable. Transfer paused."
             THEN: COMPLETE

  confirm:
    REASONING: true
    GOAL: "Present a clear summary: from, to, amount, FX rate if applicable,
      estimated arrival. Ask for explicit YES to proceed."
    EXIT_WHEN: customer_confirmed == true
    MAX_TURNS: 2
    THEN: execute

# ─────────────────────────────────────────────────────
# ERROR HANDLING
# ─────────────────────────────────────────────────────

ON_ERROR:
  tool_failure:
    RESPOND: "Something went wrong. Your transfer has NOT been submitted."
    RETRY: 1
    THEN: RESPOND "Still unable to process. Please call 1-800-BANK-HELP or visit a branch."

  fx_rate_expired:
    RESPOND: "The FX rate has expired. Fetching a new rate — please confirm again."
    CALL: get_fx_rate(currency, "USD", amount)
    THEN: confirm

  session_timeout:
    RESPOND: "Your session has timed out for security. Please start again."
    THEN: COMPLETE

# ─────────────────────────────────────────────────────
# COMPLETION
# ─────────────────────────────────────────────────────

COMPLETE:
  - WHEN: transfer_result.status == "SUBMITTED"
    RESPOND: "Transfer confirmed. ID: {{transfer_result.transfer_id}}.
      Estimated arrival: {{transfer_result.eta}}.
      A confirmation has been sent to your registered email and mobile."

Chapter 03 · Core Capability

Multi-Agent Orchestration —
built for enterprise complexity.

Four formal primitives with typed payloads, barrier sync, and cross-runtime invocation. Orchestration that is deterministic, auditable, and composable across any framework.

HANDOFF

Transfers full ownership to a specialist agent. The calling agent suspends and awaits RETURN. Memory grants are passed as a typed payload — the specialist only sees what ABL permits. Ownership returns with the result attached.

DELEGATE

Inline call — specialist answers a sub-question without changing thread ownership. The user never sees the context switch. Ideal for quick lookups: policy checks, KB retrieval, entity resolution. Response merges back into the calling turn.

FAN_OUT

Parallel tool calls with a barrier sync before proceeding. Prefetch client profile, market positions, compliance status, and rate data in a single round trip — then route to the right specialist once all data has resolved.

A2A

Agent-to-agent protocol for cross-runtime invocation. Governs agents built on OpenAI Agents SDK, LangChain, or open-source frameworks under the same policy plane — no rewrite required, unified trace from day one.
