## Correcting an assumption carried from earlier articles in this batch

Earlier articles in this refresh batch noted the ABLP-2996 `expressionToPython` root-guard-variable fix as "not applicable" because their WHEN conditions used multi-segment paths. This article's `is_authenticated != true` is genuinely single-segment, so it was investigated directly rather than assumed safe. Finding: `expressionToPython` is not wired into the runtime `HANDOFF WHEN` evaluation path at all (it is exported from `packages/core` but has no callers in `apps/runtime` or `packages/compiler`) — the actual runtime evaluator (`nullSafeEvaluateCondition`/`evaluateConditionDual`) is a different code path that was never affected by that bug. **This article's example was never broken by the historical `expressionToPython` bug, and needs no fix related to it.** This is a meaningfully more precise conclusion than assuming the fix's relevance from its Jira description alone — recorded here so a future refresh doesn't need to re-derive it.
