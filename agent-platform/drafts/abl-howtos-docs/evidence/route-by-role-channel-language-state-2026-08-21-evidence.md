## Additional findings

1. **Flat CONTEXT shorthand not mentioned**: The parser supports `PASS:`, `SUMMARY:`, `HISTORY:` as flat siblings of the HANDOFF entry (parser lines 5661-5682), without the `CONTEXT:` wrapper. The reference docs at `multi-agent-and-supervisor.mdx:457` confirm this. The article shows only the nested `CONTEXT:` form and does not mention the shorthand.

2. **No-match behavior not explained**: When no HANDOFF WHEN condition matches, the supervisor retains ownership and may respond directly (if `direct_response_allowed` is true) or re-prompt. The article's design advice to "keep the ordinary service route last" is correct but the article does not explain what happens if even that route does not match.

3. **Mixed deterministic+semantic guards**: The runtime supports combining deterministic and semantic conditions in a single WHEN using AND (e.g., `session.channel == "voice" AND "the user is frustrated"`). The article separates them completely but does not mention mixing is possible.

4. **Quoting semantics for WHEN**: The parser `unwrapQuotedRoutingExpression` strips outer double quotes from WHEN values. In the article, the semantic conditions are already quoted in the YAML (e.g., `WHEN: "the user is an administrator..."`). If a semantic condition is unquoted AND looks like it has expression operators, the classifier may mis-classify it. The article does not explain when to quote vs not quote.
