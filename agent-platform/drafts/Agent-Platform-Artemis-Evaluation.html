agents
Enterprise scale Systemic risk

No single view of what's deployed. Regulatory audit is a weeks-long project. Model deprecation is a crisis. Quality regresses silently before anyone notices.

No agent catalog

Teams deploy agents independently with no shared registry. No one knows what's running, who owns it, or what it does. Decommissioning becomes archaeology.

Governance gaps

Each team reinvents guardrails. Policies diverge across frameworks. A single audit question — "what guardrails ran on that session?" — has no consistent answer.

Blind observability

Audit exposure

Compliance reviews that should take hours take weeks. Evidence scattered across platforms, teams, and formats. Every regulator inquiry becomes a fire drill.

Model deprecation

Every model cycle forces a rebuild sprint. Prompts break silently. Behaviors shift without warning. Teams spend weeks on migration instead of value delivery.

Shadow AI

Teams build ungoverned agents outside IT oversight. No policy enforcement, no audit trail, no visibility — until a compliance incident forces a painful reckoning.

The architecture decision you make at 20 agents determines whether you can move fast — and stay compliant — at 200.

ABL — where value is created. Agents as typed contracts.

Agent Blueprint Language turns intent, persona, workflow, memory, tools, constraints, and guardrails into an executable contract. The point is not syntax; the point is that runtime behavior is explicit, reviewable, and enforceable.

enterprise-service-agent.ablIllustrative ABL
AGENT: enterprise_service_agent {
  GOAL:
    Resolve employee service requests end-to-end when safe;
    gather required details and route exceptions to the right owner.

  PERSONA:
    You are a concise, calm, policy-aware service specialist.
    Use approved sources. Do not guess policy or change entitlements.

  RULES:
    - Work hands-off until a consequential action or approval is required.
    - Ask only for missing required fields.
    - Cite policy sources before recommending action.
    - Stop when resolved, approval is required, or required data is missing.

  TOOLS:
    jira_search(issue_key: string): JiraIssue
    servicenow_create_case(payload: ServiceCase): CaseId
    policy_lookup(query: string): PolicyAnswer
    approval_request(case_id: string, approver: string): ApprovalStatus

  GATHER: request_context {
    FIELDS: [employee_id, request_type, urgency, system_name, business_justification]
    STRATEGY: ask_user
    COMPLETE_WHEN: all_fields_present
  }

  MEMORY:
    SESSION: retain request_context, cited_sources, case_id
    USER: remember preferred_contact_channel with consent
    SHARED: pass case_summary to exception_owner only

  FLOW: resolve_request {
    STEP: classify_request
      REASONING: true
      USE: [policy_lookup, jira_search]

    STEP: collect_required_context
      REASONING: false
      GATHER: request_context

    STEP: decide_path
      REASONING: true
      OUTPUT: decision { proceed | needs_approval | exception }

    STEP: create_case
      REASONING: false
      USE: servicenow_create_case

    STEP: request_approval
      WHEN: decision == needs_approval
      USE: approval_request

    HANDOFF: exception_owner
      WHEN: decision == exception
      CONTEXT: case_summary
  }

  CONSTRAINTS:
    max_steps: 12
    latency_target: "4s p95 for non-workflow turns"
    allowed_regions: ["US", "EU"]
    budget_per_session: "0.35 USD"

  GUARDRAILS:
    - kind: pii
      check: mask_sensitive_fields
      action: block_or_redact
    - kind: grounding
      check: require_citations(policy_lookup)
      action: require_safe_answer
    - kind: authorization
      check: tool_scope_matches_user
      action: deny_tool_call

  TESTS:
    grounding_coverage >= 0.95
    required_field_completion >= 0.98
    unauthorized_action_rate == 0
    handoff_precision >= 0.90
}

Multi-agent orchestration — formal primitives, not ad hoc handoffs.

Enterprise work rarely belongs to one agent. Artemis gives teams typed orchestration patterns so specialists can collaborate without leaking memory, losing traceability, or turning handoffs into guesswork.

Handoff

Transfer ownership to a specialist.

The calling agent suspends, passes only approved memory grants, and resumes when the specialist returns a typed result.

Delegate

Ask a specialist without changing ownership.

Ideal for policy lookups, knowledge queries, calculations, and narrow checks that should not interrupt the user's thread.

Fan out

Run parallel work with barrier sync.

Multiple specialists can investigate in parallel, then return into one governed decision path with a complete trace.

Return

Attach a typed result to the parent trace.

Results, confidence, citations, tool outputs, and guardrail outcomes return as structured evidence, not prose pasted into context.

Evals — how you know it works.

Executable assertions over correctness, safety, and policy run continuously, not once at launch. Evals turn "the agent feels better" into a number the business can defend, and they are the prerequisite for trusting, improving, or tuning anything.

Correctness & policy suites

Task accuracy + guardrails, one harness.

Resolution accuracy, false-escalation rate, PII handling, grounded-answer policy, and compliance assertions are evaluated in the same place.

Regression gates

A change can't ship if it drops a metric that matters.

A model swap, prompt change, workflow update, or ABL refinement is blocked unless it beats the baseline on the evals that matter.

Generated from the blueprint

Coverage scales with the agent.

Arch can draft eval cases from the ABL, workflows, knowledge sources, and support documentation so the suite grows with the agent.

The tuning prerequisite

You can't know tuning helped without an eval first.

Evals make every downstream decision measurable instead of anecdotal. Improvement becomes provable.

For enterprise teams

Multiple domains means multiple definitions of "good." Evals let each domain own its bar while the platform enforces the gate uniformly.

Governance

Three governance planes — one continuous policy surface.

Agent governance cannot live in a policy document beside the platform. It has to be structural: compiled into the artifact, enforced at runtime, proven in the trace, and improved through evals.

Plane 01

Policy as code.

Mandatory guardrail sections, schema checks, tool scopes, auth profiles, memory grants, and review workflow live inside the agent specification before deploy.

The compiler refuses missing gates.

Plane 02

Runtime enforcement.

Input, in-flight, and output checks apply on every run: PII masking, topic controls, grounded-answer policy, tool authorization, budget limits, and HITL gates.

Consequential actions stay approval-bound.

Plane 03

Continuous assurance.

Traces, eval results, drift signals, retrieval records, and guardrail outcomes feed the improvement loop and provide audit evidence in seconds.

Every release inherits the same control surface.

Where leverage comes from

  • Reusable contracts — agents become typed artifacts, not invisible prompt state.
  • Shared control plane — the same trace, eval, policy, and audit model spans every agent.
  • Model portability — the harness survives model changes instead of forcing rewrites.
  • Continuous optimization — fixes return as reviewable patches, not ad hoc tuning exercises.

How to measure it

  • Time from brief to first governed blueprint.
  • Review cycles per agent change.
  • Eval pass rate, regression rate, and rollback rate.
  • Operational cost per resolved interaction or completed workflow.

Use current-state baselines where available; avoid presenting improvement rates as guaranteed outcomes before measurement.
