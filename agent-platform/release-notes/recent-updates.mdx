<Update label="August 27, 2026" description="v1.5.2, Patch release">

<p className="rn-title">Agent Builder Experience</p>

<p className="rn-subtitle">Support for Base64-encoded file attachments</p>

Alongside the existing `multipart/form-data` upload path, the platform now accepts Base64-encoded attachments in `application/json` requests, using `filename`, `mimeType`, and `contentBase64`. Successful uploads can return a short-lived signed delivery URL. If the delivery URL expires, you can request a new one without re-uploading the file.

The Agent node's canvas attachments field now accepts attachment IDs directly, in addition to https URLs, so a workflow can hand an already-uploaded attachment to an agent node without re-hosting it as a URL first.

<Update label="August 23, 2026" description="v1.5.0, Major release">

<p className="rn-title">Agent Builder Experience</p>

<p className="rn-subtitle">Artemis CLI</p>

A new customer-facing CLI is now available, letting developers automate the full Agentic lifecycle, including authentication, project sync, eval runs, and deployment, from external systems, without Studio.
<br />[Learn more →](/agent-platform/cli)

<p className="rn-subtitle">Microsoft Foundry Model Catalog support</p>

Microsoft Foundry is now available as a unified provider, replacing the previous Anthropic-only integration. Select models from multiple publishers, including OpenAI, Meta, Mistral, Cohere, and Anthropic, or enter custom deployments. The configuration also supports Azure AD Service Principal authentication with automatic token discovery.

<p className="rn-subtitle">Recurring evaluation run schedules</p>

Eval runs can now be scheduled to recur daily, weekly, or monthly, with time zone selection and flexible start and end conditions.
<br />[Learn more →](/agent-platform/evals#configure-run-settings)

<p className="rn-subtitle">Exact timestamps on eval runs</p>

Eval runs in Studio now display exact start and completion timestamps alongside the existing relative time labels, across Studio.

<p className="rn-subtitle">Unsaved-changes warning in the ABL editor</p>

Studio now warns you before you lose unsaved work when leaving the agent editor, with the option to save, discard, or stay.

<p className="rn-subtitle">In-app Help Center and first-time user welcome experience</p>

Studio now includes a built-in Help Center with guided documentation, a platform primer, feature highlights, and support resources. It also offers a unified welcome screen for first-time users with quick-start actions—creating a project, using a template, connecting Artemis MCP, inviting team members, and accessing docs and support—reopenable anytime from the profile menu.


<p className="rn-title">Knowledge Base</p>

<p className="rn-subtitle">Improved OCR and language handling for SearchAI document extraction</p>

* SearchAI now automatically detects a document's language and selects the corresponding RapidOCR model, rather than relying on a single fixed model regardless of script. This improves results for Arabic, Thai, Urdu, and Latin-script scans.
* Mixed-language documents are kept in their source language rather than translated.
* SearchAI detects pages with unusable or sparse text (scanned images, glyph-name artifacts, collapsed text, or vertical right-to-left output) and runs a full-page OCR fallback to recover readable text.
* Explicit language and OCR-language settings now carry through the SDK, connectors, and every extraction path (sync, async, split-PDF, streaming URL, extraction-only), so configured language hints are honored consistently.
* Automatic OCR now runs only when a PDF's embedded text layer is genuinely unusable, is disabled for pure-text formats by default, and caps fallback retries rather than retrying indefinitely.
* A visual enrichment or OCR failure no longer causes the whole document to fail — extraction continues downstream with any usable text.

<p className="rn-subtitle">Connector enhancements: Custom base URLs and OAuth authentication</p>

Multiple connectors now support custom base URLs and expanded OAuth 2.0 Client Credentials authentication, enabling connections to on-premises deployments and sovereign cloud tenants instead of relying only on public cloud endpoints:

* Jira: Custom base URL and product-version selection for Jira Data Center deployments
* Confluence: Custom base URL, OAuth 2.0 Client Credentials authentication, and product-version selection
* SharePoint: Custom base URL and OAuth 2.0 Client Credentials authentication through custom Azure AD endpoints, including sovereign clouds such as .de
* ServiceNow: Custom base URL, OAuth 2.0 Client Credentials authentication, and product-version selection
* Salesforce: OAuth 2.0 Client Credentials authentication for non-interactive, scriptable authentication
* Microsoft 365 (Excel): OAuth 2.0 Client Credentials authentication for non-interactive Microsoft 365 authentication

<p className="rn-title">Voice Experience</p>

<p className="rn-subtitle">Voice Playground for softphone-based voice testing in Studio</p>

Playground now supports voice testing alongside text testing, allowing developers and QA teams to initiate a softphone interaction, speak with the agent, view the live transcript and call state, and open the session in Observatory for detailed voice debugging. [Learn more →](/agent-platform/testing)

<p className="rn-subtitle">Voice call transfer and escalation to a live agent</p>

The Escalation block in Studio now supports voice call transfers, in addition to the existing chat hand-off to an agent desk. Voice calls can be escalated to a human agent by integrating the call_transfer tool with the ESCALATE block; previously, escalation supported only chat-based handoff. Developers can choose a call transfer type (SIP, PSTN, or relay) and a transfer method (invite, refer, or bye/release-link) directly in the Escalation editor, to prevent failure messages from being announced twice. [Learn more →](/agent-platform/escalate)

Voice agents can also transfer calls to external phone numbers, not just SIP endpoints, by configuring a PSTN phone number as an agent transfer destination in the project voice settings. [Learn more →](/agent-platform/administration/agent-behavior-settings#voice-gateway)

<p className="rn-subtitle">Genesys Cloud Audio Connector for voice bots</p>

Voice calls can now connect to Genesys Cloud through the Audio Connector, using the AudioHook protocol, with support for both Pipeline and Realtime voice modes.
<br />[Learn more →](/agent-platform/channels/set-up-genesys-audio-connector)

<p className="rn-subtitle">Configure language-specific TTS profiles for multilingual voice agents</p>

Voice Pipeline channels can now define an explicit TTS profile for each configured language, including provider, voice, model, output format, pace, and temperature. When the interaction language changes, the agent switches to the configured profile for that language, instead of inferring a voice or provider from the default configuration. [Learn more →](/agent-platform/channels/voice#set-up-pipeline-voice)

<p className="rn-subtitle">Amazon Connect live-agent transfer via SIP BYE with generated conversation summary</p>

Voice calls routed from Amazon Connect to an Artemis agent can now be transferred to a live agent, along with a generated conversation summary. The platform then releases the bot's call leg via SIP BYE, allowing Amazon Connect to resume its contact flow and route the caller with context intact.
<br />[Learn more →](/agent-platform/administration/agent-behavior-settings#voice-gateway)

<p className="rn-subtitle">Validation of STT timeout configuration against provider-specific limits</p>

Voice channel configuration now validates the speech/segmentation-silence timeout against the selected STT provider's actual supported range (for example, Microsoft's 100–5000 ms), instead of accepting any positive value, and rejects invalid values rather than silently clamping or forwarding them.

<p className="rn-subtitle">Forward custom outbound SIP headers on call transfer</p>

Projects can now configure a set of allowed outbound SIP headers to forward during voice call transfers. Administrators select which predefined headers (for example, x-queue, x-skill) a project permits, and agents can attach values for those headers when initiating a SIP REFER or INVITE transfer. Enforcement, sanitization, and drop telemetry are applied at runtime. [Learn more →](/agent-platform/sending-custom-sip-headers)

<p className="rn-subtitle">Multi-gateway BYOC SIP support</p>

BYOC (Bring Your Own Carrier) voice channels now support configuring multiple SIP gateway IP addresses and CIDR ranges, replacing the previous single-IP field. Each entry is provisioned as its own Jambonz SIP gateway, with full lifecycle management for create, update, rollback, and cleanup.

<p className="rn-title">Digital Experience</p>

<p className="rn-subtitle">Genesys Cloud Open Messaging integration for digital channel agent handoff</p>

Conversations on Web Chat, WhatsApp, and other messaging channels can now be handed off to a live agent through Genesys Cloud.
<br />[Learn more →](/agent-platform/channels/set-up-genesys-open-messaging)

<p className="rn-subtitle">Add Support for Microsoft Teams and Copilot channel</p>

Microsoft Teams and Copilot are now supported as a new deployment channel. Users can create a Teams channel instance from the Studio deployments screen, configure credentials and identity policies, and have the runtime enforce a verified Teams identity on inbound messages.
<br />[Learn more →](/agent-platform/channels/set-up-ms-teams-copilot#set-up-microsoft-teams-and-copilot)

<p className="rn-subtitle">File attachment support in the API channel and web SDK chat widget</p>

The file attachment option in the chat widget can now be shown or hidden per project, and the API channel now passes along caller-supplied context to the agent.
<br />[Learn more →](/agent-platform/channels/set-up-web-sdk-channel)

<p className="rn-subtitle">Auto-disconnect idle chat widget sessions</p>

The embedded chat widget can now be configured to automatically disconnect or end a session after a period of user inactivity.
<br />[Learn more →](/agent-platform/channels/set-up-web-sdk-channel)


<p className="rn-title">Insights</p>

<p className="rn-subtitle">One place to see every LLM call</p>

A new Generations view shows every model call, from Studio, search, and live traffic, in one place, with cost, latency, and token usage. <br />[Learn more →](/agent-platform/analytics-insights/analytics-explorer#generations)

<p className="rn-subtitle">Filter analytics by environment and channel</p>

Analytics dashboards is now filetered by environment (development, staging, production) and channel, so testing data doesn't get mixed in with production numbers. <br />[Learn more →](/agent-platform/analytics-insights/analytics-explorer#narrow-the-list)

<p className="rn-subtitle">See who gave feedback</p>

The feedback table and exported reports now show which user submitted each piece of feedback, plus any custom tags. <br />[Learn more →](/agent-platform/analytics-insights/customer-voice#feedback-table)

<p className="rn-subtitle">Public analytics APIs for sessions, traces, and LLM usage</p>

External systems can now pull conversation history, session and session-summary reporting data, messages, execution traces, and LLM cost and usage ledger data directly through public APIs.


<p className="rn-title">Governance</p>

<p className="rn-subtitle">Simpler guardrail threshold configuration and scanner configuration</p>

Guardrail policies now provide a simpler way to configure detection thresholds at the project level. [Learn more →](/agent-platform/safety-and-guardrails#guardrail-policies)
<br />Workspace administrators can configure guardrail providers and their available scanners, while project authors can select which configured providers the project can use. Guardrail providers also support a wider range of classifier response formats. [Learn more →](/agent-platform/administration/ai-configuration#guardrail-providers)

<p className="rn-subtitle">Entity-based PII detection and anonymization</p>

PII detection and anonymization now support entity-based detection. Authors can create PII patterns using entity recognition (built-in or model-backed) instead of regex. An ignore-values list lets authors exclude known values from detection and reduce false positives.
<br />[Learn more →](/agent-platform/pii-protection#custom-patterns)

<p className="rn-subtitle">Auth Profile fields to reference deployment environment variables</p>

Project Auth Profile fields — Token URL, Refresh Token URL, Scopes, Client ID, and Client Secret — can now be populated from environment variables defined under Deployments, instead of requiring these values to be entered directly into the Auth Profile.

<p className="rn-subtitle">OAuth and PKCE support for remote MCP servers</p>

Remote MCP server authentication profiles now support OAuth configuration, including authorization, token, and refresh URLs, scopes, and PKCE. PKCE can be enabled with the S256 challenge method.

<p className="rn-subtitle">Simpler Azure encryption setup</p>

Customers using their own Azure encryption keys no longer need to register an app in their Azure tenant — the platform now manages that identity, and key rotation is simpler. This also adds support for additional compliance certifications (GDPR, SOC2, NIST, FIPS-140-3). 
<br />[Learn more →](/agent-platform/administration/workspace-and-team#policies)

<p id="breaking-changes" className="rn-title">Breaking changes and what to check before moving to 1.4.0</p>

<p id="agent-developers" className="rn-subtitle">For agent developers</p>

**Supervisor role is now explicit**

`canRespondDirectly` is deprecated as the primary way to set supervisor behavior. New agents should declare `BEHAVIOR: role: router` (route only) or `role: orchestrator` (combine results and respond). Existing agents keep working through compatibility mapping, but a role that conflicts with the old boolean setting now fails to compile.

```yaml expandable=true
Before (1.3.3):
    SUPERVISOR: Benefits_Router
    canRespondDirectly: false
    HANDOFF:
      - TO: Claims_Agent
    	WHEN: intent.category == "claims"
After (1.4.0):
    SUPERVISOR: Benefits_Router
    BEHAVIOR:
      role: router
    HANDOFF:
      - TO: Claims_Agent
    	WHEN: intent.category == "claims"
```

**Routers can no longer own returned work**

A router can only select the next agent. If the parent needs to use a child agent's returned result, declare it an orchestrator instead. Agents that use `DELEGATE` inside a router will no longer compile.


```yaml expandable=true
Before (1.3.3) — DELEGATE inside a router, now a compile error:
    SUPERVISOR: Benefits_Router
    canRespondDirectly: false
    DELEGATE:
      - TO: Plan_Lookup_Agent
    	WHEN: intent.category == "benefits"
    	RETURNS:
      	plan_summary: object
After (1.4.0) — declared as an orchestrator instead:
    SUPERVISOR: Benefits_Coordinator
    BEHAVIOR:
      role: orchestrator
    DELEGATE:
      - TO: Plan_Lookup_Agent
    	WHEN: intent.category == "benefits"
    	RETURNS:
      	plan_summary: object
    INSTRUCTIONS: |
      Use plan_summary to answer the member. Do not expose unrelated session memory.
```


**Compiler warnings can now block publishing**

Diagnostics that used to be silently accepted — conflicting role and flag settings, routers containing DELEGATE, unmapped handoff inputs, unsupported tool array schemas — now stop a project from compiling or publishing. Review and resolve any outstanding warnings before promoting existing projects on 1.4.0.


**Handoff and delegate inputs must resolve, or the call fails**

A handoff or delegate no longer runs with a missing or stale input value. Add an explicit `MEMORY` read for any value the child needs, and use `ON_RETURN` to map back the results the parent depends on.

For deterministic FLOW parents, `HANDOFF` with `RETURN: true` now suspends at the transition boundary and resumes from the saved next step once the child returns — review verifier, auth, eligibility, and multi-agent flows where a parent depends on a child's returned values.


```yaml expandable=true
Before (1.3.3):
    HANDOFF:
      - TO: Authentication_Agent
    	WHEN: intent.category == "auth"
    	RETURN: true
    	INPUT:
      	memberId: '{{member_id}}'
After (1.4.0):
    MEMORY:
      member_id:
    	type: string
    	access: read
    HANDOFF:
      - TO: Authentication_Agent
    	WHEN: intent.category == "auth"
    	RETURN: true
    	INPUT:
      	memberId: '{{member_id}}'
    	ON_RETURN:
      	action: resume_intent
      	map:
            authentication_status: result.authentication_status
        	member_id: result.member_id
```

**Tools must declare the memory they read and write**

A tool that needs conversation memory must declare `context_access.read` and/or `context_access.write`. If the declared memory isn't available, the tool doesn't run — check tools that previously assumed memory was always present.


```yaml expandable=true
Before (1.3.3):
    TOOLS:
      get_plan_information(memberId: string) -> { success: boolean, plans: array }
    	type: http
    	endpoint: "/eligibilitymembersinfo/query"
    	method: POST
After (1.4.0):
    MEMORY:
      authentication_status:
    	type: string
    	access: read
      member_plan_summary:
    	type: object
    	access: write
    TOOLS:
      get_plan_information(memberId: string) -> { success: boolean, plans: array }
    	type: http
    	endpoint: "/eligibilitymembersinfo/query"
    	method: POST
    	context_access:
      	read: [authentication_status]
      	write: [member_plan_summary]
```


**Declare the item type for array inputs**

Workflow array inputs still work without an item type, but declaring one — for example `itemType: "string"` — is now recommended. Workflow and connector array parameters are also projected into the model-facing tool schema with an items definition in 1.4.0, so some model providers (for example Gemini/Vertex) can reject the whole tool declaration if a typed array doesn’t declare its item type.


```yaml expandable=true
Before (permissive array):
    { "name": "available_days", "type": "array", "required": true }
After (typed array):
    {
      "name": "available_days",
      "type": "array",
      "itemType": "string",
      "required": true
    }
```

**Review PII detection settings**

New projects start with no built-in PII detection enabled by default (`enabled_builtins: []`). If your agent relied on default PII protection, explicitly enable the detection types you need before publishing.

**Re-check SearchAI metadata and title filters**

Filters that were previously dropped or ignored — unknown standard filters, metadata filters, and title-only filters — are now honored correctly. Review saved knowledge base and tool filters, since results may return different, more accurate documents after upgrading.

**Gather validation outputs are now canonical**

FLOW `gather` validation and retry-exhaustion fields are now lowered into the canonical execution model instead of relying on display-only alias names or implicit retry fallbacks. Make gather validation outputs explicit and don't rely on a label as if it were a runtime variable name.

**Terminal output is held until the final response is confirmed**

Runtime now defers final output until response checkpoints pass, which cuts down on duplicate terminal responses and output arriving after cancellation — but it also surfaces incorrect output-ownership wiring earlier. Re-test multi-agent flows with async fan-out, remote handoff returns, delayed voice responses, or structured `COMPLETE` payloads without text.

**Review agents that branch on channel or transfer state**

Message metadata, channel identity, and transfer state now persist more consistently across reconnects, cancellation, escalation, and remote handoff returns. If an agent branches on channel identity or resumes after a remote or human-agent transfer, re-test it on 1.4.0.

<p id="administrators" className="rn-subtitle">For admins</p>

**Recompile and re-import migrated projects**

Projects moved between tenants or environments now go through stricter namespace validation before they can be published. Re-import or recompile any migrated projects on 1.4.0 and confirm there are no outstanding namespace warnings.

**Validate workflows triggered outside of Studio**

Start-input defaults and required-input validation for workflows are now applied server-side across every trigger path — cron, webhook, connector-polling, and agent-triggered — not just Studio's Run dialog. Validate promoted workflow versions on each of these trigger paths, not only by running them manually in Studio.
