## Set up Realtime LLM Voice channel
 
Realtime LLM Voice is a voice channel that handles live voice conversations through a single provider-native speech session. It supports Realtime LLM models (such as OpenAI Realtime and Gemini Live) through the Kore.ai Voice Gateway (KoreVG) or a Bring Your Own SIP connection.
 
Unlike the STT → LLM → TTS pipeline that Pipeline Voice uses, a provider-native realtime model owns the live audio conversation. KoreVG handles telephony, connection routing, bounded session state, traces, and the call lifecycle.
 
<Tip>Studio also provides in-product guidance. On the **Realtime LLM Voice** channel page, click **Setup instructions** to open a step-by-step panel that covers connection creation, provider and phone routing, call quality validation, and security, latency, and reliability boundaries.</Tip>
 
### Create a Realtime LLM Voice channel
 
To create a Realtime LLM Voice channel, go to **Deployments** > **Channels** > **Voice** > **Realtime LLM Voice** > **New connection** and complete the following steps in order.
 
<Steps>
  <Step title="Set up the connection">
    On the **New Realtime LLM Voice Connection** page, provide the following fields.
    | Field | Description |
    | --- | --- |
    | **Display Name** | A label for the connection. |
    | **Connection Name** | A stable system name for the connection, up to 255 characters. Use an environment-specific identifier such as `realtime-voice-production`. It's an external identifier, not a phone number or a shared gateway account. |
    | **Environment** | The deployment the connection binds to. Select an environment whose active deployment contains the realtime-compatible agent, tools, model policy, and welcome behavior. Select an environment to follow its active deployment automatically, or leave the default to use the working copy. When no environment has an active deployment yet, create a deployment first to bind the connection to a published environment. |
    | **Provider Verification Strength** | Controls how strictly the platform trusts the provider's identity assertions for session continuity and linking. **Weak** is the default. Choose **Strong** only for channels or providers whose identity assertions you trust. |
    | **Initial Status** | **Active** connections are usable immediately. **Inactive** connections stay saved but disabled until you activate them. Use **Inactive** while the provider and phone routing are incomplete. An **Active** phone-routed connection without a provisioned number can't receive production PSTN calls. |
  </Step>
  <Step title="Create the connection">
    Click **Create**.
    <Note>Create the connection before you configure voice details. The connection record must exist before Studio can provision a phone number and save provider-specific realtime settings.</Note>
  </Step>
</Steps>
### Configure the Realtime LLM Voice channel
 
Once the channel is created, open it from the **Realtime LLM Voice** connections list. The connection has three tabs: **Settings**, **Speech**, and **Testing**. The **Settings** tab holds the voice provider and call routing. The **Speech** tab holds realtime orchestration, the S2S provider, and advanced voice behavior. The **Testing** tab holds the shareable softphone link.
 
<Steps>
  <Step title="Choose a call routing option (Kore.ai Voice Gateway)">
    On the **Settings** tab, under **Realtime LLM Voice Settings**, set **Voice Provider** to **Kore.ai Voice Gateway** or **Bring Your Own SIP**. If you choose **Kore.ai Voice Gateway**, set the following under **Call routing**. Choose how calls reach this agent. Enable **Soft Phone** for browser testing, and add a phone number (DID) when the channel needs a real phone number.
    | Route | Description |
    | --- | --- |
    | **Soft Phone** (FREE) | Dial the agent from your browser with no DID purchase or telephony charges. Use it for evals, QA, and demos. **Launch dialer** opens the browser dialer. |
    | **Phone Number (DID)** | Purchase a real phone number through Twilio. Disable this route to stop DID listing and call routing while keeping the number saved. |
 
    Keep KoreVG as the managed telephony gateway unless your platform owner has approved another provider. Confirm that the realtime provider you plan to use is available for your tenant and environment.
 
    <Note>If you select **Phone Number (DID)**, complete the next step. If you selected **Voice Provider: Bring Your Own SIP** instead, skip to step 3.</Note>
  </Step>
  <Step title="Configure the phone number (DID only)">
  - Set **Provider** to **Twilio**.  
  - Toggle **Inbound calls** (routes calls from this number into the voice agent).  
  - Toggle **Outbound calls** (allows this number for campaign dial‑out).  
  - Select a **Country**, **Number Type**, and optional **Area Code**.  
  - Choose **Search Available Numbers** to list matching numbers.  

  Buy or assign a Twilio‑backed number from the saved connection’s settings.  
  - Confirm the number is bound to this connection before activation.  
  - After assignment, the number appears in the **Phone Number** field.  
  - Select **Remove** to unbind the number from the connection.
  </Step>
  <Step title="Configure SIP settings (Bring Your Own SIP only)">
    If you chose **Bring Your Own SIP**, the **Call routing** options are replaced by a **SIP Configuration** section on the **Settings** tab. Set the following fields.
    | Field | Description |
    | --- | --- |
    | **Our SIP Server Address** | A read-only address. Configure your SIP provider to send `INVITE` to this address, for example `korevg-np.kore.ai:5060`. Select **Copy** to copy the address. |
    | **SIP Gateway IPs / CIDRs** | Provider SIP source addresses. Separate multiple IPv4 addresses or CIDR ranges with commas, for example `203.0.113.50:5080, 3.80.16.0/23`. |
    | **SIP Termination URI** | The termination address your SIP provider expects outbound calls to reach, as either an **IP Address** or **Domain Name**. Select the type, then type the SIP termination IP address or domain name in the **SIP termination URI** field below it. |
    | **DID / Phone Number** | The phone number (DID) your SIP provider routes to this SIP gateway. |
    | **Enable E.164 (leading +)** | Prepend a leading `+` to outbound numbers sent to the carrier. On by default, which international (full-E.164) numbers require. Turn off only for local or national-format numbers, otherwise the leading `+` misroutes them. |
  </Step>
  <Step title="Set SIP header trust and save the connection settings">
    At the bottom of the **Settings** tab, for either voice provider, set the following.
    | Field | Description |
    | --- | --- |
    | **Trust inbound SIP headers** | Off by default. Turn it on only if your SBC sets or overwrites these headers. If the headers can arrive from the caller, the value isn't trustworthy. When on, transfer headers configured to pass through from the inbound call (for example, `User-to-User`) are sent on the transfer. When off, they are dropped. |
    | **Connection Name** | The system name of the connection. Select the copy icon to copy it. |
 
    Click **Save Changes** to apply the settings.
  </Step>

    * **Realtime orchestration**: Select how runtime coordinates the conversation flow and business tool execution for realtime voice interactions. Realtime orchestration determines whether the realtime model or runtime controls conversation progression and business actions, such as bookings, orders, and payments.
 
      | Mode | Description | Recommended for |
      | --- | --- | --- |
      | **Legacy - model-selected tools** | Preserves the existing behavior where the realtime model manages both the conversation and business tool selection. | Existing agents and backward compatibility. |
      | **Runtime Guarded - hybrid freeform (recommended)** | Allows the realtime model to conduct the conversation naturally while runtime validates tool execution and context updates against the current FLOW step. Business tools execute only when they belong to the active FLOW step, preventing out-of-order actions while maintaining the authored FLOW. | New realtime voice agents that require natural conversations while maintaining FLOW integrity. |
      | **Runtime Owned - canonical turn** | Runtime controls every conversation turn and executes the FLOW exactly as authored. ### Test the Realtime LLM Voice Channel

Open the **Testing** tab to verify the channel before going live.

- **Shareable softphone link:** Generate a time‑limited link that lets anyone call the channel from a phone browser through the real gateway and view a read‑only transcript.  
  - Links expire after 7 days and can be revoked at any time.  
  - **Active links** shows links currently in use, or **No active links for this channel**.  
  - Viewing active links requires read access; generating or revoking links requires edit permission.  

- **Soft Phone dialer:** From the **Settings** tab, select **Soft Phone > Launch dialer** to call the agent directly from your browser.  
  - No DID purchase or telephony charges are required.

### Verify and secure the Realtime LLM Voice channel
 
Before you go live, validate the quality of realtime calls. Realtime quality depends on the slowest leg of the call, so test each of the following.
 
<Steps>
  <Step title="Preview with HTTPS voice">
    Generate a time‑limited preview, allow microphone access, start and stop a call, mute/unmute, and confirm chat remains usable if microphone or provider setup fails.
  </Step>
  <Step title="Run an isolated PSTN test call">
    Dial the provisioned number and validate greeting, bidirectional audio, tool execution, transfer/termination, caller hang‑up, and one stable Runtime session.
  </Step>
  <Step title="Measure latency budget">
    Record gateway connect time, provider session setup, input audio commit, first model audio, end‑to‑end turn p50/p95, jitter, and packet loss.
  </Step>
  <Step title="Test barge‑in and rapid turns">
    Interrupt a long agent response, speak immediately, and verify stale audio is cancelled, tool calls aren’t duplicated, and the next user turn is preserved.
  </Step>
  <Step title="Exercise failure scenarios">
    Deny microphone access, force provider disconnect, gateway reconnect, model timeout, tool failure, phone hang‑up, and capacity rejection. Confirm caller hears or receives the designed fallback.
  </Step>
</Steps>

### Security, Latency, and Reliability Practices

- **Protect credentials:** Treat realtime provider and carrier credentials as administrator‑managed secrets. Do not copy API keys into connection identifiers, browsers, screenshots, or agent prompts.  
- **Minimize overhead:** Avoid unnecessary transcoding, buffering, proxy hops, and oversized tool responses. Set explicit connection and turn timeouts, and verify heartbeat behavior through every proxy.  
- **Validate capacity:** Check provider concurrency, KoreVG session limits, phone capacity, and backpressure before load tests. Capacity rejection must fail predictably, not degrade active calls.  
- **Define fallback behavior:** Specify caller‑visible handling for provider unavailability, timeout, safety rejection, tool failure, and transfer failure. Include rules for retry, reprompt, mode switch, or call termination.  
- **Trace sessions:** Capture call/session IDs, provider events, tool calls, turn latency, interruptions, errors, and termination reasons. Scrub audio, transcripts, and credential data from logs.

### Troubleshoot Realtime LLM Voice
 
* **Calls to the number fail:** an **Active** phone-routed connection without a provisioned number can't receive production PSTN calls. Assign or buy a number, and confirm it's bound to this connection.
* **The channel can't start a session:** resolve missing provider credentials and model configuration, then save the connection and test again.
* **Duplicate tool calls or stale audio after an interruption:** repeat the barge-in test from [Verify and secure the Realtime LLM Voice channel](#verify-and-secure-the-realtime-llm-voice-channel) and check the traces for the affected call and session IDs.
  For the full validation checklist, click **Setup instructions** on the Realtime LLM Voice channel page.

## Set up Pipeline Voice channel

It's a voice channel that handles calls through separate speech-to-text, LLM, and text-to-speech stages, connected through Kore.ai Voice Gateway. Unlike Realtime LLM Voice, which uses a single speech-to-speech model, this pipeline lets you choose and configure the ASR (speech-to-text) and TTS (text-to-speech) providers independently.

<Note>Choose your voice provider before you begin - it determines which additional fields apply later in this setup.</Note>

To configure a Pipeline Voice channel, go to **Deployments** > **Channels** > **Voice** > **Pipeline Voice** > **+ New** and complete the following steps in order.

<Steps>
  <Step title="Set Up the Connection">
    On the **New Pipeline Voice Connection** page, provide the following fields.

    | Field | Description |
    | --- | --- |
    | **Display Name** | A label for the connection. |
    | **Connection Name** | A system name for the connection, such as `pipeline-voice-prod`. Up to 255 characters. |
    | **Environment** | The deployment the connection binds to. Select an environment to follow its active deployment automatically, or leave the default to use the working copy. When no environment has an active deployment yet, create a deployment first to bind the connection to a published environment. |
    | **Provider Verification Strength** | Controls how strictly the platform trusts the provider's identity assertions for session continuity and linking. **Weak** is set by default. Choose **Strong** only for channels/providers whose identity assertions you trust for stronger continuity and linking decisions. |
    | **Initial Status** | **Active** connections are usable immediately. **Inactive** connections stay saved but disabled until you activate them. |

    Click **Create**.
  </Step>

  <Step title="Choose a Voice Provider">
    After creating the channel, go to the **Configuration** tab. Under **Pipeline Voice Settings**, set **Voice Provider** to either **Kore.ai Voice Gateway** or **Bring Your Own SIP** — this determines which call routing fields appear next.
  </Step>

  <Step title="Configure Call Routing (Kore.ai Voice Gateway)">
    If you chose **Kore.ai Voice Gateway**, set the following fields under **Call routing**. Choose how calls reach this agent — enable Soft Phone for browser testing, or add a DID when this channel needs a real phone number.

    | Route                  | Description                                                                                                                                                     |
    |------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|
    | **Soft Phone** (FREE)  | Dial the agent from your browser. No DID purchase or telephony charges. Use this for evals, QA, and demos. Select **Launch dialer** to open the browser dialer. |
    | **Phone Number (DID)** | Purchase a real phone number through Twilio. Disable this route to stop DID listing and call routing while keeping the number saved.                            |

    <Note>If you enable **Phone Number (DID)**, complete the next step. If you chose **Voice Provider: Bring Your Own SIP** instead, skip to Configure SIP Settings.</Note>
  </Step>

  <Step title="Configure the Phone Number (DID Only)">
    Set the **Provider** to **Twilio**, toggle **Inbound calls** (route calls from this number into the voice agent) and **Outbound calls** (allow this number to be used for campaign dialout), and select a **Country** and **Number Type**. Optionally enter an **Area Code** to filter available local numbers. Select **Search Available Numbers** to list matching numbers.
  </Step>

  <Step title="Configure SIP Settings (Bring Your Own SIP)">
    If you chose **Voice Provider: Bring Your Own SIP**, set the following fields under **SIP Configuration**.

    | Field                       | Description                                                                                                                                |
    | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
    | **Our SIP Server Address**  | Configure your SIP provider to send `INVITE` to this address, for example `korevg-np.kore.ai:5060`. Select **Copy** to copy the address.   |
    | **SIP Gateway IPs / CIDRs** | Provider SIP source addresses. Separate multiple IPv4 addresses or CIDR ranges with commas, for example `203.0.113.50:5080, 3.80.16.0/23`. |
    | **SIP Termination URI**     | The termination address your SIP provider expects outbound calls to reach, as either an **IP Address** or **Domain Name**. Enter the URI in the field below the selected type. |
    | **DID / Phone Number**      | The phone number (DID) your SIP provider routes to this SIP gateway, for example `+14155551234` or `98492`.                                |

    Toggle **Enable E.164 (leading +)** to prepend a leading `+` to outbound numbers sent to the carrier - on by default, which international (full-E.164) numbers require. Turn it off only for local/national-format numbers, since the leading `+` otherwise misroutes them.
  </Step>

  <Step title="Configure Speech Recognition">
    Under **Speech Recognition**, set the following fields.

    | Field                       | Description                                                                                                                                                               |
    | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
    | **Provider**                | The speech-to-text credential set to use, for example `Deepgram Speech Credentials`.                                                                                      |
    | **Language**                | The recognition language, for example `Multilingual`.                                                                                                                     |
    | **STT Model**                | The recognition model, for example `Nova 3 (latest, most accurate)`.                                                                                                      |
    | **Minimum STT confidence**  | Reject transcripts below this confidence (0-1) and treat them as no-input. `0` disables the gate. Provider-relative - calibrate per channel.                              |
    | **Custom vocabulary**       | Add domain-specific terms to improve speech recognition. You can set the **Phrase** (for example `ACME, policy number`) and optional **Boost**. For **Emotech**, add **hotwords** (domain-specific words or phrases you want the speech recognition system to recognize more reliably) and set the **Hotword Weight**. A value from 5 to 10 is recommended. Clear the custom vocabulary list to disable hotwords.|
    | **Multilingual speech recognition** | Choose the recognizer for each configured language. Enable **A different recognizer per language** to select the speech recognizer for each language. Add a language profile before configuring language-specific recognition. |

  </Step>

  <Step title="Configure Speech Synthesis">
    Under **Speech Synthesis**, set the following fields.

    | Field                                | Description                                                                                                                                                                              |
    |--------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
    | **Voices by language**               | Enable this option to configure separate text-to-speech settings for each language supported by the agent. When disabled, the channel uses a single TTS configuration for all languages. |
    | **Language**                         | Select the language for which you want to create a TTS profile, then click **Add language**.                                                                                             |
    | **Provider**                         | The text-to-speech credential set to use for the selected language, for example `ElevenLabs (TTS) Credentials` or `Deepgram Speech Credentials`.                                         |
    | **Voice**                            | The voice used for synthesized speech for the selected language, for example `Sarah - Mature, Reassuring, Confident - (american, young, female)`.                                        |
    | **Switch TTS for detected language** | When enabled, calls can change the TTS language, voice, and model after speech recognition detects a different language.                                                                 |

    <Note>
    - After you click **Add language**, the platform creates a dedicated TTS configuration section for that language. Configure the provider, voice, model, and any provider-specific settings independently for each language.
    - Available fields vary by provider. Some providers expose additional settings such as TTS model, output format, speed, temperature, and voice tuning controls. Each language profile maintains its own provider configuration, allowing multilingual agents to use different voices and models for different languages.
    </Note>
  </Step>

  <Step title="Tune ElevenLabs Voice Settings (ElevenLabs Only)">
    If you selected an ElevenLabs voice, override playback and prosody for this channel connection under **ElevenLabs Voice Settings**.

    | Field                  | Description                                                                                                                         |
    |------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
    | **TTS Model**          | The synthesis model, for example `Eleven Multilingual v2`.                                                                          |
    | **Speed**              | Adjusts speaking pace. `1.0` is normal; lower slows the voice down, higher makes it faster. Range: `0.7`–`1.2`.                     |
    | **Stability**          | Controls consistency across generations. Higher is more stable and less expressive; lower allows more variation. Range: `0`–`1`.    |
    | **Similarity boost**   | Keeps the output closer to the selected voice. Higher values preserve more of the original voice character. Range: `0`–`1`.         |
    | **Style exaggeration** | Amplifies voice style and emotion. Higher values can sound more expressive but may increase latency or instability. Range: `0`–`1`. |
    | **Speaker boost**      | Enhances speaker similarity and clarity. Turning it off may reduce latency for some voices.                                         |

    Under **Preview Voice**, enter sample text (up to 500 characters) and select **Generate** to hear the configured voice before saving.
  </Step>

  <Step title="Configure Conversation Controls">
    Set the following fields.

    | Field                              | Description                                                                                                |
    | ----------------------------------- | ---------------------------------------------------------------------------------------------------------- |
    | **Barge-in**                        | Allow the caller to interrupt the agent while it is speaking.                                              |
    | **Speech Timeout (ms)**             | Controls how long the speech provider waits through silence before finalizing the current speech segment. This does not combine separate final results. For example, `3000`. |
    | **Transcript Grouping Timeout (ms)** | After the speech provider returns a final result, waits this long for another final result and combines the parts into one user input. Leave blank to process each final result immediately. For example, `1500`. |
    | **Welcome Message**                 | The opening prompt the agent speaks, such as `Hello! How can I help you today?`.                           |
    | **Allow caller to interrupt the welcome**   | Allows callers to interrupt the welcome message when barge-in is active.                           |
    | **Noise isolation**                 | Apply server-side noise reduction to inbound call audio to filter out background voices and ambient noise. |

    Under **Connect greeting** (audio), optionally play a clip as soon as the call connects, before the agent's first turn. If the project's greeting-audio library has no clips yet, the panel shows a note and an **Open Greeting Audio** link to add one.
  </Step>

  <Step title="Save the Channel">
    Click **Save Changes** to apply the configuration.
  </Step>
</Steps>

### Manage an existing Pipeline Voice channel

Open a channel from **Deployments** > **Channels** > **Voice** > **Pipeline Voice**. It displays the following three tabs.

<Tabs>
  <Tab title="Overview">
    The **Connection Summary** displays these fields.

    | Field           | Description                             |
    |-----------------|-----------------------------------------|
    | **Status**      | for example: *Active*                   |
    | **Created**     | Timestamp the channel was created       |
    | **Updated**     | Timestamp of the last change            |
    | **Environment** | for example: `dev`                      |
    | **Source Type** | `Channel Connection`                    |
    | **Source ID**   | Unique identifier (UUID) of the channel |
    
  </Tab>

  <Tab title="Configuration">

    | Field                 | Description                                                                                                         |

  </Tab>
