## Supported actions

Actions are GitHub operations that an agent runs as Action Tools during a conversation. You can also run them from an [Integration node](/agent-platform/workflows#integration-node) in a workflow.

## Workflow triggers

Triggers are GitHub events that start a workflow automatically. Select them as [app triggers](/agent-platform/workflows#app-triggers) when you configure a workflow.

| Trigger | Fires when |
| --- | --- |
| New Pull Request | A pull request has activity. |
| New Issue | An issue has activity. |
| New Comment Posted | A comment is posted on a discussion. |
| New Discussion | A discussion has activity. |
| New Review Request | You're asked to review a pull request. |
| New Mention | You're mentioned in a comment. |
| Push | A branch receives a push, including commits, tags, branch or tag deletions, and repositories created from a template. |
| New Commit | A commit is pushed. |
| New Branch | A branch is created. |
| New Release | A release is added. |
| New Label | A label is created. |
| New Milestone | A milestone is created. |
| New Collaborator | A collaborator is added. |
| New Star | A repository's stars change. |

## Set up the integration

<Steps>
  <Step title="Get GitHub credentials">
    For **OAuth 2.0**, create a [GitHub OAuth app](https://github.com/settings/developers), set its callback URL to the Artemis **Callback URL**, and copy the **Client ID** and **Client Secret**. For **API Key**, create a [personal access token](https://github.com/settings/tokens) with access to the repositories the agent uses.
  </Step>
  <Step title="Create the auth profile">
    In **Integrations**, select **GitHub** > **Connect**. On **Project Auth Profiles**, select **New Profile** > **Integration Profile** > **GitHub** > **Continue**. Select an **Auth Type**, enter the credentials, and select **Create Profile**. For OAuth 2.0, select **Authorize**.

    | Auth Type | Fields |
    | --- | --- |
    | **OAuth 2.0** | **Client ID** and **Client Secret**. Artemis pre-fills the GitHub endpoints and the scopes `repo`, `admin:org`, and `admin:repo_hook`. |
    | **API Key** | Paste the token into **API Key**. Keep the `authorization` header, `Bearer ` prefix, and `x-github-api-version` header (`2022-11-28`). |

    **Usage Mode**: **Preconfigured** shares one authorization across users; **JIT** and **Preflight** ask each user to authorize, during or before the session. See [Auth profiles](/agent-platform/administration/integrations-settings#auth-profiles).
  </Step>
  <Step title="Create the action tool">
    In **Tools**, select **New Tool** > **Action** > **GitHub** > **Continue**. Select the **Action** and **Auth Profile**, set parameter defaults (leave a value empty for the agent to supply at runtime), and select **Create Tool**. Then [assign the tool to an agent](/agent-platform/tools/actions#assign-an-action-to-an-agent).
  </Step>
</Steps>

## Troubleshoot common issues

| Issue | Resolution |
| --- | --- |
| `Bad credentials` | Regenerate the token, or authorize the OAuth profile again. |
| `Resource not accessible` | Grant the token or app access to the repository and organization. |
| Repository list is empty | For organization repositories, approve the OAuth app in the organization's settings. |
| Triggers don't fire | Confirm the account can manage webhooks on the repository (`admin:repo_hook`). |
