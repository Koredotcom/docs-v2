Use the Azure Blob Storage integration to create and manage containers and blobs, read blob content, and manage blob tags through Action Tools.

| Authentication | Actions |
| --- | --- |
| Azure AD (Service Principal) | ([9](/agent-platform/integrations/enterprise-systems/azure-blob-storage#supported-actions)) |

## Supported actions

| Action | Use it to |
| --- | --- |
| [List Containers](#list-containers) | List containers in the storage account. |
| [Create Container](#create-container) | Create a container. |
| [Delete Container](#delete-container) | Delete a container. |
| [List Blobs](#list-blobs) | List blobs in a container. |
| [Create Blob](#create-blob) | Upload a file as a blob. |
| [Read Blob](#read-blob) | Read a blob. |
| [Delete Blob](#delete-blob) | Delete a blob. |
| [Add Tags to Blob](#add-tags-to-blob) | Add tags to a blob. |
| [Find Blobs](#find-blobs) | Find blobs by tags. |

## Prerequisites

- An Azure Storage account and a container, or permission to create one.
- A Microsoft Entra ID app registration with a service principal, tenant ID, client ID, and client secret.
- The service principal must have data access for the containers and blob operations the tools will use. See [Authorize access to blobs using Microsoft Entra ID](https://learn.microsoft.com/en-us/azure/storage/blobs/authorize-access-azure-active-directory).

## Set up the integration

<Steps>
  <Step title="Prepare the Azure service principal">
    Create or identify a Microsoft Entra ID app registration and service principal. Grant it the required Azure Blob Storage data access, and have the storage account name, tenant ID, client ID, and client secret ready.
  </Step>
  <Step title="Create the auth profile">
    In **Integrations**, select **Azure Blob Storage** > **Connect**. On **Project Auth Profiles**, select **New Profile** > **Integration Profile** > **Azure Blob Storage** > **Continue**. Use **Azure AD (Service Principal)** and enter the account name, tenant ID, resource, scopes, client ID, and client secret. The resource defaults to `https://storage.azure.com`. Scopes are space-separated. Set the profile name and choose whether it is visible to project members, then select **Create Profile**. The profile is preconfigured; users do not need to authorize it separately.
  </Step>
  <Step title="Create the action tool">
    In **Tools**, select **New Tool** > **Action** > **Azure Blob Storage** > **Continue**. Select the action and auth profile, configure its inputs, and select **Create Tool**. Then [assign the tool to an agent](/agent-platform/tools/actions#assign-an-action-to-an-agent).
  </Step>
</Steps>

## Troubleshoot common issues

| Issue | Resolution |
| --- | --- |
| An action returns an authorization error | Verify the service principal has the required Azure Blob Storage data access. |
| An action can't find a container or blob | Check the selected `container` and the `blobName`. |
| **Find Blobs** returns no matches | Verify the container and the tags supplied to the action. |
