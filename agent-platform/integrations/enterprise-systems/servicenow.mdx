Use the ServiceNow integration to create, retrieve, update, and search records in ServiceNow tables, and to attach or find files. It also provides triggers for new or updated records.

| Authentication | Actions | Triggers |
| --- | --- | --- |
| OAuth 2.0, Client Creds, OAuth Password, Basic | ([6](#supported-actions)) | ([2](#triggers)) |

## Supported actions

| Action | Use it to |
| --- | --- |
| [Create Record](#create-record) | Create a new record in a specified table |
| [Update Record](#update-record) | Update an existing record in a specified table |
| [Get Record](#get-record) | Retrieve a specific record by its ID |
| [Find Records](#find-records) | Search for records in a table using a query |
| [Attach File to Record](#attach-file-to-record) | Upload and attach a file to a record |
| [Find File](#find-file) | List or download file attachments from a record |

## Triggers

| Trigger | Fires when |
| --- | --- |
| [New Record](#new-record) | Triggers when a new record is created in a table |
| [Updated Record](#updated-record) | Triggers when a record is updated in a table |

## Prerequisites

- A ServiceNow instance and an account with access to the tables and records your tools will use.
- A ServiceNow domain and credentials for one of the authentication methods offered in Studio.

## Set up the integration

<Steps>
  <Step title="Create a ServiceNow auth profile">
    In **Tools**, select **New Tool** > **Action** > **ServiceNow** > **Continue** > **Manage profiles**. On **Project Auth Profiles**, select **New Profile** > **Integration Profile** > **ServiceNow** > **Continue**. Choose an authentication type and enter the required credentials. For OAuth 2.0, Studio supplies the authorization and token endpoints, the useraccount scope, and a callback URL to register in ServiceNow.
  </Step>
  <Step title="Configure the action tool">
    Return to the action builder, select the ServiceNow action and auth profile, configure its inputs, and create the tool. Then [assign the tool to an agent](/agent-platform/tools/actions#assign-an-action-to-an-agent).
  </Step>
</Steps>

The table selector includes common tables such as Incident (`incident`), Change Request (`change_request`), Problem (`problem`), Service Request (`sc_request`), Requested Item (`sc_req_item`), Catalog Task (`sc_task`), Task (`task`), User (`sys_user`), Group (`sys_user_group`), Configuration Item (`cmdb_ci`), and Knowledge (`kb_knowledge`). ## Trigger reference

The optional filter uses a ServiceNow encoded query, for example: priority=1^state=1.

**Find Records** uses a default limit of 1,000 records. Large results may be trimmed to fit connector response limits.

## File attachments

For **Attach File to Record**, provide either a file input or the fileBase64 parameter. The file input accepts a file from an earlier step, a link, or file content. Server file paths are not supported. If the file name or content type is omitted, the connector uses the file name and infers the content type when possible.

For **Find File**, action_type selects whether to list attachments or download a file. You can optionally filter by file name or provide an attachment sys_id; the default accepted type is any file, and the default return format is a Base64 encoded string.

## Troubleshoot common issues

| Issue | Resolution |
| --- | --- |
| Authorization or table lookup fails | Check the ServiceNow instance URL or domain and confirm the selected profile's credentials can access the instance and table. |
| A record is not available in the dropdown | Select the correct table or enter the record sys_id in manual_sys_id. |
| A trigger does not fire | Confirm the selected table and review the optional encoded filter query. |
| File attachment fails | Provide file content through File or fileBase64; server file paths are not supported. Confirm the record ID and attachment permissions. |
| A record search returns fewer rows than expected | Check the limit and query. Large responses may be limited by the connector. |
