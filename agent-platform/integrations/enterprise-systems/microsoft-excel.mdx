## Workflow triggers

Triggers are Microsoft Excel events that start a workflow automatically. Select them as [app triggers](/agent-platform/workflows#app-triggers) when you configure a workflow.

| Trigger | Fires when |
| --- | --- |
| New Row | A row is added. Can include existing rows. |
| New Row in Table | A row is added to a table. |
| New Worksheet | A worksheet is created in a workbook. |
| Updated Row | A row is added or updated. |

## Prerequisites

- Workbooks in **.xlsx** format, stored in OneDrive or a SharePoint document library.

## Set up the integration

<Steps>
  <Step title="Register an Entra ID app">
    Register an app in [Microsoft Entra ID](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app), create a client secret, and copy the **Application (client) ID** and **Directory (tenant) ID**. Add Microsoft Graph permissions such as `Files.ReadWrite.All` and `Sites.ReadWrite.All` as **Delegated** or **Application** permissions, grant admin consent, and for delegated access add the Artemis **Callback URL** as a **Web** redirect URI.
  </Step>
  <Step title="Create the auth profile">
    In **Integrations**, select **Microsoft Excel** > **Connect**. On **Project Auth Profiles**, select **New Profile** > **Integration Profile** > **Microsoft Excel** > **Continue**. Select an **Auth Type**, configure the fields, and select **Create Profile**. For delegated access, select **Authorize**.

    <Tabs>
      <Tab title="OAuth 2.0 App (User Delegated)">
        Artemis doesn't pre-fill the endpoints or scopes for this type. Enter **Authorization URL** `https://login.microsoftonline.com/<tenant>/oauth2/v2.0/authorize`, **Token URL** `.../oauth2/v2.0/token`, **Scopes** (for example `offline_access Files.ReadWrite.All Sites.ReadWrite.All`), **Client ID**, and **Client Secret**.

        **Usage Mode**: **Preconfigured** shares one authorization across users; **JIT** and **Preflight** ask each user to authorize, during or before the session. See [Auth profiles](/agent-platform/administration/integrations-settings#auth-profiles).
      </Tab>
      <Tab title="OAuth 2.0 Client Credentials">
        Keep **Authorize Using** as **Client Secret** and the pre-filled **Token URL** and **Scopes** (`https://graph.microsoft.com/.default`). Enter **Client ID** and **Client Secret**.
      </Tab>
    </Tabs>
  </Step>
  <Step title="Create the action tool">
    In **Tools**, select **New Tool** > **Action** > **Microsoft Excel** > **Continue**. Select the **Action** and **Auth Profile**, set parameter defaults (leave a value empty for the agent to supply at runtime), and select **Create Tool**. Then [assign the tool to an agent](/agent-platform/tools/actions#assign-an-action-to-an-agent).
  </Step>
</Steps>

## Troubleshoot common issues

| Issue | Resolution |
| --- | --- |
| `AADSTS50011` redirect URI mismatch | Add the exact **Callback URL** as a **Web** redirect URI in the app registration. |
| `AADSTS65001` consent required | Grant admin consent for the API permissions, and then authorize again. |
| `403 Forbidden` | Add the missing Microsoft Graph permission for the action, and grant consent. |
| Workbook or worksheet lists are empty | Check **storageSource**, and for SharePoint select **siteId** and **documentId** first. |
| Rows land in the wrong columns | Set **isFirstRowHeaders** and match `values` keys to the header names. |
