## Triggers

| Trigger | Fires when |
| --- | --- |
| New Case Attachment | A new Attachment or File is added to a Case. |
| New Contact | A Contact is created. |
| New Field History Event | A tracked field changes on a selected object. |
| New Lead | A Lead is created. |
| New or Updated Record | A record is created or updated on a selected object, optionally filtered by a SOQL condition. |
| New Outbound Message | Salesforce sends an outbound message to the trigger. |
| New Record | A record is created on a selected object, optionally filtered by a SOQL condition. |
| New or Updated File | A Salesforce File (`ContentDocument`) is created or updated. This trigger does not fire for classic Attachments or Notes. |
| New Case in Queue | A new Case is assigned to a selected queue. |

## Prerequisites

- A Salesforce org and a user or integration identity with access to the records and operations your tools need.
- An OAuth app configured in Salesforce for OAuth 2.0 authorization, or a Salesforce My Domain URL and connected-app credentials for OAuth 2.0 Client Credentials.
- For OAuth 2.0, the app must allow the callback URL shown in the Studio auth profile and the requested scopes: `refresh_token`, `full`, and `api`.
- For Client Credentials, Salesforce My Domain is required. Studio supports **Client Secret** and **JWT assertion** authorization methods.

## Set up the integration

<Steps>
  <Step title="Create a Salesforce auth profile">
    In **Tools**, select **New Tool** > **Action** > **Salesforce** > **Continue**, then select **Manage profiles**. In **Project Auth Profiles**, select **New Profile** > **Integration Profile** > **Salesforce** > **Continue**. Choose **OAuth 2.0** or **OAuth 2.0 Client Credentials**. For OAuth 2.0, configure the Salesforce hostname if needed, add the profile callback URL to the Salesforce app, and enter the client ID and secret. For Client Credentials, enter the Salesforce My Domain URL, choose **Client Secret** or **JWT assertion**, and provide the matching credentials and settings. Save the profile and authorize it when using OAuth 2.0.
  </Step>
  <Step title="Create the action tool">
    In **Tools**, select **New Tool** > **Action** > **Salesforce** > **Continue**. Select the **Action** and **Auth Profile**, configure the inputs, and select **Create Tool**. Then [assign the tool to an agent](/agent-platform/tools/actions#assign-an-action-to-an-agent).
  </Step>
</Steps>

## Troubleshoot common issues

| Issue | Resolution |
| --- | --- |
| OAuth authorization fails | Check the Salesforce hostname, client credentials, callback URL, and requested scopes. For a sandbox or custom domain, use the appropriate Salesforce hostname. |
| Client Credentials authorization fails | Confirm the My Domain URL, client ID, and the selected Client Secret or JWT assertion configuration. |
| An action can't find or update a record | Verify the object and record IDs and confirm that the authorized Salesforce identity has the required object and field permissions. |
| A query or report fails | Check the SOQL syntax and confirm the authorized identity can access the referenced objects, fields, and report. |
| A trigger doesn't return expected events | Check the selected object, queue, and SOQL condition. For **New Outbound Message**, confirm Salesforce is configured to send the outbound message to the trigger endpoint. |
| A file trigger misses an attachment | **New or Updated File** covers `ContentDocument` files, not classic Attachments or Notes. Use **New Case Attachment** for files attached to Cases. |
