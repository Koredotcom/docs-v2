Use the Microsoft Outlook integration to let agents send, reply to, forward, draft, label, move, and find email in Microsoft 365 mailboxes through Microsoft Graph.

| Authentication | Actions | Workflow triggers |
| --- | --- | --- |
| OAuth 2.0 App (User Delegated), Azure AD (Service Principal), OAuth 2.0 Client Credentials | [12](#supported-actions) | [3](#workflow-triggers) |

## Supported actions

Actions are Outlook operations that an agent runs as Action Tools during a conversation. You can also run them from an [Integration node](/agent-platform/workflows#integration-node) in a workflow.

| Action | Use it to |
| --- | --- |
| [Send Email](#send-email) | Send an email. |
| [Reply to Email](#reply-to-email) | Reply to a message, or save the reply as a draft. |
| [Forward Email](#forward-email) | Forward a message with an optional comment. |
| [Create Draft Email](#create-draft-email) | Create a draft without sending it. |
| [Send Draft Email](#send-draft-email) | Send an existing draft. |
| [Request Approval in Email](#request-approval-in-email) | Send an approval request and wait for the recipient to approve or reject it. |
| [Find Email](#find-email) | Search messages with full-text search. |
| [Download Attachment](#download-attachment) | Download the attachments of a message. |
| [Add Label to Email](#add-label-to-email) | Add categories to a message. |
| [Remove Label from Email](#remove-label-from-email) | Remove categories from a message. |
| [Move Email to Folder](#move-email-to-folder) | Move a message to another folder. |
| [Custom API Call](#custom-api-call) | Call any Microsoft Graph endpoint the other actions don't cover. |

## Workflow triggers

Triggers are Outlook events that start a workflow automatically. Select them as [app triggers](/agent-platform/workflows#app-triggers) when you configure a workflow.

| Trigger | Fires when |
| --- | --- |
| New Email | A new email arrives in the inbox. |
| New Email in Folder | A new email is delivered to a folder you specify. |
| New Attachment | An email with one or more attachments arrives. |

## Set up the integration

<Steps>
  <Step title="Register an Entra ID app">
    Register an app in [Microsoft Entra ID](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app), create a client secret, and copy the **Application (client) ID**, **Directory (tenant) ID**, and secret value. Add Microsoft Graph permissions: **Delegated** (for example `Mail.ReadWrite`, `Mail.Send`, `offline_access`) for user sign-in, or **Application** (`Mail.ReadWrite`, `Mail.Send`, with admin consent) for app-only access. For delegated access, add the Artemis **Callback URL** as a **Web** redirect URI.

    <Warning>Application permissions cover every mailbox in the tenant. Scope them with an Exchange Online application access policy or RBAC for Applications.</Warning>
  </Step>
  <Step title="Create the auth profile">
    In **Integrations**, select **Microsoft Outlook** > **Connect**. On **Project Auth Profiles**, select **New Profile** > **Integration Profile** > **Microsoft Outlook** > **Continue**. Select an **Auth Type**, configure the fields, and select **Create Profile**. For delegated access, select **Authorize**.

    <Tabs>
      <Tab title="OAuth 2.0 App (User Delegated)">
        Artemis doesn't pre-fill the endpoints. Enter **Authorization URL** `https://login.microsoftonline.com/<tenant>/oauth2/v2.0/authorize`, **Token URL** `.../oauth2/v2.0/token`, the delegated **Scopes**, **Client ID**, and **Client Secret**.

        **Usage Mode**: **Preconfigured** shares one authorization across users; **JIT** and **Preflight** ask each user to authorize, during or before the session. See [Auth profiles](/agent-platform/administration/integrations-settings#auth-profiles).
      </Tab>
      <Tab title="Azure AD (Service Principal)">
        Enter **Mailbox / User (app-only)** (UPN or object ID of the target mailbox), **Azure Tenant ID**, **Scopes** (`https://graph.microsoft.com/.default`), **Client ID**, and **Client Secret**. Keep **Resource** as `https://graph.microsoft.com`.
      </Tab>
      <Tab title="OAuth 2.0 Client Credentials">
        Keep **Authorize Using** as **Client Secret** and the pre-filled **Token URL** and **Scopes**. Enter **Client ID** and **Client Secret**.
      </Tab>
    </Tabs>
  </Step>
  <Step title="Create the action tool">
    In **Tools**, select **New Tool** > **Action** > **Microsoft Outlook** > **Continue**. Select the **Action** and **Auth Profile**, set parameter defaults (leave a value empty for the agent to supply at runtime), and select **Create Tool**. Then [assign the tool to an agent](/agent-platform/tools/actions#assign-an-action-to-an-agent).
  </Step>
</Steps>

## Troubleshoot common issues

| Issue | Resolution |
| --- | --- |
| `AADSTS50011` redirect URI mismatch | Add the exact **Callback URL** as a **Web** redirect URI in the app registration. |
| `AADSTS65001` consent required | Grant admin consent for the API permissions, and then authorize again. |
| `403 Forbidden` or `ErrorAccessDenied` | Add the missing Graph permission for the action, and grant consent. |
| App-only calls fail with `/me request is only valid with delegated authentication` | Enter the target mailbox in **Mailbox / User (app-only)**. |
| Delegated profile stops refreshing | Include `offline_access` in **Scopes**, and then authorize again. |
| Message dropdowns are empty | Confirm the profile has read access (`Mail.Read` or `Mail.ReadWrite`) to the mailbox. |
