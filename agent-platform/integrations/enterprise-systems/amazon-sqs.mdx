Use the Amazon SQS integration to let agents and workflows send messages to SQS queues, so downstream systems can process them. Artemis signs each request with AWS SigV4.

| Authentication | Actions | Workflow triggers |
| --- | --- | --- |
| AWS IAM (SigV4) | [1](#supported-actions) | None |

## Supported actions

Actions are Amazon SQS operations that an agent runs as Action Tools during a conversation. You can also run them from an [Integration node](/agent-platform/workflows#integration-node) in a workflow.

| Action | Use it to |
| --- | --- |
| [Send Message](#send-message) | Send a message to a queue. |

## Prerequisites

- An SQS queue and its URL.

## Set up the integration

<Steps>
  <Step title="Prepare AWS credentials">
    Create an IAM role (recommended) or an IAM user with access keys, and allow `sqs:SendMessage` on the queue ARN. For a role, add a trust policy that requires the **External ID** shown in the Artemis profile form.
  </Step>
  <Step title="Create the auth profile">
    In **Integrations**, select **Amazon SQS** > **Connect**. On **Project Auth Profiles**, select **New Profile** > **Integration Profile** > **Amazon SQS** > **Continue**. Set **Usage Mode** to **Preconfigured**, choose **Credentials**, and select **Create Profile**.

    <Tabs>
      <Tab title="Assume role (recommended)">
        | Field | Value |
        | --- | --- |
        | **Endpoint type** | **Custom AWS service** (the default, Bedrock AgentCore, doesn't apply) |
        | **Signing service** | `sqs` |
        | **Region** | The Region of your queue, for example `us-east-1` |
        | **Role ARN** | ARN of the role you created |
        | **Session duration** | Optional. 900 to 3600 seconds (default 3600) |
        | **External ID** | Read only. Add it to the role's trust policy. |

        <Warning>If the form shows **Platform AWS identity not configured**, ask your platform administrator to configure it, or use access keys.</Warning>
      </Tab>
      <Tab title="Access keys">
        | Field | Value |
        | --- | --- |
        | **Region** | The Region of your queue |
        | **Signing service** | `sqs` (pre-filled) |
        | **Access Key ID**, **Secret Access Key** | From the IAM user. Leave **Bucket**, **Endpoint**, and **Session Token** empty. |
      </Tab>
    </Tabs>
  </Step>
  <Step title="Create the action tool">
    In **Tools**, select **New Tool** > **Action** > **Amazon SQS** > **Continue**. Select the **Action** and **Auth Profile**, set parameter defaults (leave a value empty for the agent to supply at runtime), and select **Create Tool**. Then [assign the tool to an agent](/agent-platform/tools/actions#assign-an-action-to-an-agent).
  </Step>
</Steps>

## Troubleshoot common issues

| Issue | Resolution |
| --- | --- |
| `AccessDenied` | Allow `sqs:SendMessage` on the queue ARN. |
| `NonExistentQueue` | Check `queueUrl` and that **Region** matches the queue. |
| Requests fail with a signature error | Confirm **Signing service** is `sqs`. For Assume role, confirm **Endpoint type** is **Custom AWS service**. |
