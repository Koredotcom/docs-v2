Use the Gmail integration to let agents send, reply to, draft, find, and read email, and request approvals by email, through Action Tools.

| Authentication | Actions | Triggers |
| --- | --- | --- |
| OAuth 2.0 | ([7](/agent-platform/integrations/enterprise-systems/gmail-integrations#supported-actions)) | ([4](/agent-platform/integrations/enterprise-systems/gmail-integrations#triggers)) |

## Supported actions

| Action | Use it to |
| --- | --- |
| [Send Email](#send-email) | Send an email, or save it as a draft. |
| [Request Approval in Email](#request-approval-in-email) | Send an approval request and wait for the recipient to approve or reject it. |
| [Reply to Email](#reply-to-email) | Reply to the sender or to all recipients of a message. |
| [Create Draft Reply](#create-draft-reply) | Save a reply as a draft without sending it. |
| [Get Email](#get-email) | Read a message by its ID. |
| [Find Email](#find-email) | Search messages by sender, recipient, subject, content, label, category, date, or attachment. |
| [Custom API Call](#custom-api-call) | Call any Gmail API endpoint the other actions don't cover. |

## Triggers

| Trigger | Fires when |
| --- | --- |
| New Email | New mail arrives in the inbox. |
| New Labeled Email | A label is added to an email. |
| New Attachment | An email with an attachment arrives. |
| New Label | A new label is created. |

## Prerequisites

- A Google Cloud project with the **Gmail API** enabled and an OAuth consent screen. In **Testing** status, only test users can authorize and refresh tokens expire after seven days.

## Set up the integration

<Steps>
  <Step title="Create a Google OAuth client">
    Create an OAuth client ID of type **Web application**, add the Artemis **Callback URL** to **Authorized redirect URIs**, and copy the **Client ID** and **Client Secret**. See [Using OAuth 2.0 to access Google APIs](https://developers.google.com/identity/protocols/oauth2).
  </Step>
  <Step title="Create the auth profile">
    In **Integrations**, select **Gmail** > **Connect**. On **Project Auth Profiles**, select **New Profile** > **Integration Profile** > **Gmail** > **Continue**. Enter the **Client ID** and **Client Secret**, select **Create Profile**, and then select **Authorize**.

    Artemis pre-fills the Google endpoints, the `access_type=offline` and `prompt=consent` parameters, and these scopes: `gmail.send`, `gmail.readonly`, `gmail.compose`, and `email`. Add the same scopes to the consent screen.

    **Usage Mode**: **Preconfigured** shares one authorization across users; **JIT** and **Preflight** ask each user to authorize, during or before the session. See [Auth profiles](/agent-platform/administration/integrations-settings#auth-profiles).
  </Step>
  <Step title="Create the action tool">
    In **Tools**, select **New Tool** > **Action** > **Gmail** > **Continue**. Select the **Action** and **Auth Profile**, set parameter defaults (leave a value empty for the agent to supply at runtime), and select **Create Tool**. Then [assign the tool to an agent](/agent-platform/tools/actions#assign-an-action-to-an-agent).
  </Step>
</Steps>

## Troubleshoot common issues

| Issue | Resolution |
| --- | --- |
| `redirect_uri_mismatch` during authorization | Add the exact **Callback URL** to the OAuth client's **Authorized redirect URIs**. |
| `access_denied` or the app isn't verified | Add the user as a test user, or publish the consent screen. |
| The profile stops working after seven days | The consent screen is in **Testing** status. Publish the app, and then authorize again. |
| `403 Insufficient Permission` | Confirm the profile's scopes cover the action, and then authorize again. |
| Email sends from the wrong address | Set `from` to an address listed in the account's **Send mail as** settings. |
| **Find Email** returns an error | Provide at least one search filter. |
