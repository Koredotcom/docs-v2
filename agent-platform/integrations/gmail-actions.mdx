Use the Gmail integration to let Artemis agents send and reply to email, create drafts, search and read messages, and request approvals by email through Action Tools. Gmail triggers can also start workflows when new mail, labels, or attachments arrive. Before you create a Gmail Action Tool, create an OAuth 2.0 auth profile that lets Artemis access Gmail through a Google Cloud OAuth client.

| Item | Value |
| --- | --- |
| Category | Communication |

| Actions | 7 |

## Supported actions

| Action | Use it to |
| --- | --- |
| [Send Email](#send-email) | Send an email, or save it as a draft. |
| [Request Approval in Email](#request-approval-in-email) | Send an approval request and wait for the recipient to approve or reject it. |
| [Reply to Email](#reply-to-email) | Reply to the sender or to all recipients of a message. |
| [Create Draft Reply](#create-draft-reply) | Save a reply as a draft without sending it. |
| [Get Email](#get-email) | Read a message by its ID. |
| [Find Email](#find-email) | Search messages by sender, recipient, subject, content, label, category, date, or attachment. |
| [Custom API Call](#custom-api-call) | Call any Gmail API endpoint the other actions don't cover. |

## Supported triggers

| Trigger | Fires when |
| --- | --- |
| New Email | New mail arrives in the inbox. |
| New Labeled Email | A label is added to an email. |
| New Attachment | An email with an attachment arrives. |
| New Label | A new label is created. |

To start a workflow from a trigger, see [Integration node](/agent-platform/workflows#integration-node).

## Prerequisites

- A Google Workspace or Gmail account.
- A Google Cloud project with the **Gmail API** enabled.
- Permission to configure the OAuth consent screen and create OAuth client IDs in Google Cloud.
- An Artemis project with permission to create auth profiles and Action Tools.

## Step 1: Create a Google OAuth client

1. In the [Google Cloud console](https://console.cloud.google.com/), open your project, and then enable the **Gmail API**.
2. Configure the **OAuth consent screen**. Add the Gmail scopes listed in [Step 2](#step-2-create-a-gmail-auth-profile).
3. Create an **OAuth client ID** of type **Web application**.
4. Under **Authorized redirect URIs**, add the **Callback URL** from the Artemis auth profile form.
5. Copy the **Client ID** and **Client Secret**.

For detailed instructions, see [Using OAuth 2.0 to access Google APIs](https://developers.google.com/identity/protocols/oauth2).

<Note>If the consent screen's publishing status is **Testing**, only the test users you add can authorize, and Google expires their refresh tokens after seven days. Publish the app for production use.</Note>

## Step 2: Create a Gmail auth profile

<Steps>
  <Step title="Open the auth profile form">
    1. In Artemis, go to **Integrations**, and then select **Gmail**. The details panel lists the supported actions, triggers, and configured auth profiles.
    2. Select **Connect**. The **Project Auth Profiles** page opens.
    3. Select **New Profile** > **Integration Profile**.
    4. Under **Communication**, select **Gmail**, and then select **Continue**.
  </Step>
  <Step title="Enter the profile details">
    | Field | Description |
    | --- | --- |
    | **Auth Type** | Keep **OAuth 2.0**. |
    | **Profile Name** | Enter a name that identifies the profile, for example `Gmail - Support inbox`. |
    | **Description** | Optional. Describe the purpose of the profile. |
    | **Usage Mode** | Select how users get credentials. See [Usage modes](#usage-modes). |
    | **Visible to project members** | Turn on to let project members use the profile. |
  </Step>
  <Step title="Review the OAuth settings">
    Artemis pre-fills the Google endpoints, scopes, and parameters.

    | Field | Value |
    | --- | --- |
    | **Authorization URL** | `https://accounts.google.com/o/oauth2/v2/auth` |
    | **Token URL** | `https://oauth2.googleapis.com/token` |
    | **Refresh URL** | `https://oauth2.googleapis.com/token` |
    | **Scopes** | `https://www.googleapis.com/auth/gmail.send`, `email`, `https://www.googleapis.com/auth/gmail.readonly`, `https://www.googleapis.com/auth/gmail.compose` |
    | **Require PKCE** | Off. |
    | **Additional Authorization Parameters** | `response_type` = `code`, `access_type` = `offline`, `prompt` = `consent`. These parameters return a refresh token. |
    | **Callback URL** | Read only. Copy it into the OAuth client's **Authorized redirect URIs**. |
    | **Client ID** | Paste the client ID from Step 1. |
    | **Client Secret** | Paste the client secret from Step 1. |

    <Note>Artemis encrypts secrets at rest and never displays them after you save the profile.</Note>
  </Step>
  <Step title="Save and authorize the profile">
    1. Select **Create Profile**.
    2. In **Preconfigured** mode, select **Authorize**, sign in with the Google account the agent uses, and approve the requested permissions.
    3. Verify that the profile status is **Active**.
  </Step>
</Steps>

### Usage modes

| Mode | Behavior | Scope |
| --- | --- | --- |
| **Preconfigured** | An admin authorizes one account at setup time, for example a shared support inbox. Users don't need to authorize. | Shared |
| **JIT (Just-in-Time)** | Artemis prompts the user to authorize mid-conversation when a tool needs credentials. The agent acts on the user's own mailbox. | Per-user |
| **Preflight** | The user authorizes before the session starts. | Per-user |

For more about profile settings, see [Auth profiles](/agent-platform/administration/integrations-settings#auth-profiles).

## Step 3: Create a Gmail action tool

<Steps>
  <Step title="Start a new action tool">
    1. Go to **Tools**.
    2. Select **New Tool** > **Action**.
    3. In **Choose an Integration**, select **Gmail**, and then select **Continue**.
  </Step>
  <Step title="Configure the tool">
    | Field | Description |
    | --- | --- |
    | **Tool Name** | Artemis suggests a name based on the action. Use lowercase letters, numbers, and underscores. |
    | **Description** | Describe what the tool does and when the agent should use it. |
    | **Action** | Select one of the [supported actions](#supported-actions). |
    | **Auth Profile** | Select the profile you created in Step 2. |
  </Step>
  <Step title="Configure input and output parameters">
    For each input parameter, enter a **Default value**, or leave it empty so the agent provides the value at runtime. To exclude a parameter, select its delete icon. Then select an output mode: **Use complete tool output** or **Define custom parameters**.
  </Step>
  <Step title="Save the tool">
    Select **Create Tool**.
  </Step>
</Steps>

For more details, see [Action Tools](/agent-platform/tools/actions).

## Step 4: Use the action tool

Add the tool to an agent so the agent can invoke it during conversations. See [Assign an action to an agent](/agent-platform/tools/actions#assign-an-action-to-an-agent).

**Example:** An HR agent uses **Find Email** with `subject` set to `Offer letter` and `has_attachment` set to `True` to locate a candidate's signed offer, and then uses **Reply to Email** to confirm receipt.

## Troubleshoot common issues

| Issue | Resolution |
| --- | --- |
| `redirect_uri_mismatch` during authorization | Add the exact **Callback URL** to the OAuth client's **Authorized redirect URIs**. |
| `access_denied` or the app isn't verified | Add the user as a test user, or publish the consent screen. |
| The profile stops working after seven days | The consent screen is in **Testing** status. Publish the app, and then authorize again. |
| `403 Insufficient Permission` | Confirm the profile's scopes cover the action, and then authorize again. |
| Email sends from the wrong address | Set `from` to an address listed in the account's **Send mail as** settings. |
| **Find Email** returns an error | Provide at least one search filter. |
