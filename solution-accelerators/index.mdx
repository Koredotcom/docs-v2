Solution Accelerators give you a working, multi-agent application for a business function from day one. Instead of designing agents, routing, and integrations on an empty canvas, you start from a complete design that Kore.ai has already built and tested.

You connect your systems of record, set a handful of configuration values, and publish one conversational assistant that your employees reach in AI for Work. This section explains what an accelerator contains, how it handles a request, and how you take one live.

## What is a Solution Accelerator

A Solution Accelerator packages the agents, tools, and integrations for one business function into a single agentic app. It turns a set of scattered self-service portals into one conversation.

AI for HR shows the idea clearly. Today your employees move between a leave portal, a benefits site, a payslip archive, a profile record, a case queue, and a timesheet tool. AI for HR replaces those six stops with one assistant that understands the request and completes it in the right system.

Every accelerator ships with five building blocks:

| Building Block | What It Does |
|----------------|--------------|
| **Supervisor agent** | Reads each request, detects the intent, and routes it to the right specialist. |
| **Specialist agents** | Own one domain each, such as time off or HR cases, and complete the task end to end. |
| **HTTP and workflow tools** | Connect the agents to your systems of record and run multi-step logic. |
| **Knowledge retrieval** | Answers policy questions from your indexed content through Search AI, with source links. |
| **Deployment path** | Publishes the whole app to AI for Work as one Autonomous Agent. |

## How an accelerator handles a request

Every request travels the same path, from the employee's message to your system of record and back. Follow the steps below to see how AI for HR completes a request.

1. The employee asks a question or makes a request in AI for Work.
2. The supervisor detects the intent, stores it in shared session memory, and hands the request to exactly one specialist.
3. The specialist reads the stored context, so the employee never repeats the request.
4. The specialist calls its tools to read data or, after the employee confirms, to make a change.
5. The specialist returns the result in the same conversation.

<Note>If the employee changes topic midway, the current specialist hands the conversation to the right peer and takes it back once the peer finishes. The employee sees one continuous conversation throughout.</Note>

## Rules every accelerator follows

Accelerators apply the same safety rules in every domain. These rules protect your data and keep employees in control of every change.

| Rule | What It Means for You |
|------|------------------------|
| **One owner per request** | The supervisor hands each request to exactly one specialist and never does the work itself. |
| **Confirm before any change** | Agents read data freely, but they submit a request or update a record only after the employee confirms in chat. |
| **Source values only** | Agents show values exactly as your system of record returns them, with no estimates or rewording. |
| **Grounded answers** | Agents answer policy questions from your indexed content and cite the source. When nothing matches, they offer to raise a case instead of guessing. |

## What you configure

An accelerator runs across four layers, and you configure each layer in a specific place. The layers also tell you which team owns which part of the setup.

| Layer | What Runs There | What You Configure |
|-------|-----------------|--------------------|
| **AI for Work** | The Autonomous Agent that employees use, plus channels and admin controls | Workspace, agent connection, metadata, and guardrails |
| **Agentic app on Agent Platform** | The supervisor, the specialists, session memory, and HANDOFF routing | LLM credentials and the default model |
| **Tools** | HTTP tools and workflow tools | Endpoints, headers, config variables, and workflow registration |
| **Systems and knowledge** | Your systems of record and policy repositories | API access and the Search AI connector |

## Your path to a live accelerator

You take an accelerator live in six steps across Agent Platform and AI for Work. Follow them in order, because each step builds on the one before it.

| Step | What You Do | Where |
|------|-------------|-------|
| **1. Plan** | Lock your scope, name your team, and secure access to your systems. | Your organization |
| **2. Configure tools** | Create the HTTP tools, build and register the workflows, and add config variables. | Agent Platform |
| **3. Connect knowledge** | Connect your policy repository to Search AI and give the agents access through the Search AI API. | Search AI |
| **4. Set the LLM** | Add provider credentials, add a model from the catalog, and make it the default. | Agent Platform |
| **5. Deploy** | Create an Autonomous Agent, connect it to your agentic app, and publish it. | AI for Work |
| **6. Validate** | Test every tool, agent rule, and scenario, then roll out to a pilot group. | Agent Platform and AI for Work |

For AI for HR, the Implementation Guide walks you through every step with screenshots and request bodies.

## Key concepts

These terms appear on every accelerator page. Learn them once, and the rest of the documentation reads faster.

| Term | Definition |
|------|------------|
| **Agentic app** | The multi-agent application you build and run on Agent Platform. |
| **Supervisor agent** | The entry agent. It classifies intent, stores it in session memory, and routes the request. |
| **Specialist agent** | An agent that owns one domain and its tools. |
| **HANDOFF** | The block that passes the conversation from one agent to another. In AI for HR, control returns to the sending agent after the receiver finishes its turn. |
| **Session memory** | Shared values that every agent in the session reads, such as `current_intent` and `target_agent`. |
| **HTTP tool** | A tool that calls one API endpoint in a system of record. |
| **Workflow tool** | A tool that chains HTTP tools and logic, such as creating a time off request. |
| **Config variable** | A project value that tools read at run time as `{{config.KEY}}`. |
| **Autonomous Agent** | The AI for Work entry that connects employees to your agentic app. |
| **Metadata** | Custom values, such as the employee's email, that AI for Work passes to the agentic app. |

## Where accelerators fit in Kore.ai

Kore.ai offers three paths to an agentic application, and each path trades speed for control. Pick the path that matches how much you want to build yourself.

| Path | What You Start With | Choose It When |
|------|---------------------|----------------|
| **Solution Accelerator** | A complete application for a business function | You want the fastest route to a working assistant. |
| **AI Marketplace** | More than 60 tool templates, 20 agent templates, and 200 prompt and RAG templates | You want to assemble your own solution from ready parts. |
| **Agent Platform** | The platform itself | No accelerator or template fits, and you want full control. |

You can also combine paths. Deploy an accelerator first, then extend it with your own agents on Agent Platform.
