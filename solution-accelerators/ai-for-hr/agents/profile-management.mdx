The Profile Management agent lets employees view their employee record and update selected fields. It displays the record in a structured table and applies a change only after the employee confirms it.

The agent normalizes every value before it submits, and it never exposes raw field names to the employee. Friendly labels keep the conversation readable.

## Flows

The agent supports three flows. Two read from Workday, and one writes to it.

| Flow | What the agent does |
|------|---------------------|
| **View the employee record** | Retrieves the profile and displays the details in a structured table. |
| **Update a field** | Identifies the field and new value, confirms the change with fixed phrasing, normalizes the value, and applies it. |
| **Find an employee** | Searches for an employee by name and returns their details. |

## Sensitive fields

Some fields need evidence before the agent changes them. The agent asks for the supporting documentation as part of the confirmation step.

Plan which fields your HR policy treats as sensitive, and align the agent instructions with that list before you go live.

## Tools

Three tools support the flows. `get_user` is shared with Benefit Management, so configure it once.

| Tool | Type | Description |
|------|------|-------------|
| `search_user` | HTTP | Searches for an employee and returns their details. |
| `get_user` | HTTP | Fetches the logged-in employee's information. |
| `update_user` | Workflow | Updates a single profile field. |

### Request bodies

`search_user`:

```json
{
  "person_names": "{{input.name}}"
}
```

`get_user`:

```json
{
  "id": "{{config.USERID}}"
}
```

`update_user` passes the constructed update body straight through:

```text
{{input.body}}
```

## Guardrails

Four rules govern profile changes. They keep the employee record clean and auditable.

- The agent confirms every change before it applies it.
- The agent normalizes submitted values.
- The agent requires supporting documentation for sensitive fields.
- The agent shows friendly labels instead of raw field names.
