Good planning turns an AI for HR rollout into a configuration exercise instead of a project full of surprises. Use this page to lock your scope, team, systems, configuration values, and governance before anyone opens Agent Platform.

Work through the sections in order and finish with the readiness checklist. Every item you close here saves a round trip during configuration.

## Implementation at a glance

You take AI for HR live in six steps. Planning covers step 1, and every later step depends on the decisions you make here.

| Step | What You Do |
|------|-------------|
| **1. Plan** | Set scope, team, systems, values, and governance (this page). |
| **2. Configure tools** | Create HTTP tools, build and register workflows, and add config variables. |
| **3. Connect knowledge** | Connect your policy repository to Search AI. |
| **4. Set the LLM** | Add provider credentials and set the default model. |
| **5. Deploy** | Connect an Autonomous Agent in AI for Work to your agentic app. |
| **6. Validate** | Test tools, agents, and scenarios, then roll out. |

## Lock your scope

Decide which domains go live first. Start with the domains that generate the most HR tickets today, and add the rest in later phases.

HR_Supervisor always ships, because it routes every request. Choose the specialists for your first phase:

| Specialist | Domain |
|------------|--------|
| **Time Off Assistant** | Leave balances, requests, and leave planning |
| **Benefit Management** | Plans, enrollment, eligibility, and dependents |
| **Compensation** | Payslip questions for the logged-in employee |
| **Profile Management** | Viewing and updating the employee record |
| **Case Management** | HR policy answers and HR cases |
| **Offboarding Management** | Voluntary resignation |
| **Timesheet Management** | Viewing timesheets for yourself or a direct report |

<Tip>Case Management makes a strong first domain. It answers policy questions from content you already own and turns every unanswered question into a structured case.</Tip>

## Assemble your team

Five roles cover everything an AI for HR implementation needs. Name an owner for each role before configuration starts.

| Role | What They Own |
|------|---------------|
| **AI for Work admin** | The workspace, the Autonomous Agent, user enrollment, guardrails, data retention, and orchestration settings |
| **Agent Platform builder** | The agentic app, HTTP tools, workflows, config variables, the Search AI connection, and the LLM setup |
| **HR system owners** | API access to Workday and ServiceNow |
| **HR knowledge owners** | The policy and handbook content that Search AI indexes |
| **HR team and pilot users** | Confirmation that answers and transactions match HR policy before rollout |

## Prepare systems and access

AI for HR reaches three systems and runs inside one AI for Work workspace. Secure access to all of them before your builder starts.

### Workday

Workday holds most of the data that AI for HR reads and writes. Six of the seven specialists depend on it.

- AI for HR reads and writes leave, benefits, payroll, employee records, timesheets, and terminations.
- Collect the API endpoints and credentials for each HTTP tool.

### ServiceNow

ServiceNow runs the HR case flow. Case Management reads the HR service catalog there and creates, comments on, and resolves cases.

- Collect the API endpoints and credentials for the catalog and case tools.

### Search AI

Search AI answers every HR policy question. Set it up early, because your knowledge owners need time to index and review content.

1. In XO11, open **Search AI** and go to **Connectors** > **All connectors**.
2. Configure the connector for your policy repository, such as Confluence Cloud.
3. Copy the client ID and client secret from the Search AI app.
4. Generate a JWT signed with the client secret, using this header:

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

5. Go to **Browse** > **Filter**, select your source under **Source Title**, and click **Apply**.
6. Open the JSON of any chunk and copy the `sourceType` value. The advanced search API uses it as a filter.

### AI for Work and the LLM

AI for Work hosts the Autonomous Agent that employees use, and the LLM powers every agent. Line up both before deployment week.

- Confirm an AI for Work workspace and admin access.
- Get an API key for your LLM provider and choose the model you plan to use.

## Collect configuration values

The tools read identity and connection values from config variables at run time. Collect these values now, so your builder enters them once in project settings.

| Config Variable | Tools That Use It |
|-----------------|-------------------|
| `EMPLOYEE_ID` | Leave balance, holidays, and requests; adding dependents; enrolled benefits; payslips; resignation |
| `DEPENDENTS_EMPLOYEE_ID` | Fetching existing dependents |
| `USERID` | Fetching the employee's information |
| `USER_ID` | Fetching resignation reasons |

Tools read a config variable with this syntax:

```text
{{config.KEY}}
```

AI for Work also passes the employee's email to the agentic app as metadata. Each context reads it with its own path:

```text
Agent:         {{_metadata.email}}
Workflow tool: {{vars._session._metadata.email}}
HTTP tool:     {{session._metadata.email}}
```

<Warning>The `benefits_for_employees` tool ships with a fixed `employee_id` in its request body. Replace it with your own value or a config variable before you test, or every user sees the same available benefits.</Warning>

## Decide governance settings

AI for Work gives you controls for access, privacy, and orchestration. Agree on each setting with your security team before go-live.

| Setting | What You Decide |
|---------|-----------------|
| **User enrollment** | Open to your domain, invitation only, or synced from your directory |
| **PII guardrails** | Which personal data to redact or replace, such as Social Security numbers, email addresses, phone numbers, credit card numbers, and PAN numbers |
| **Banned topics** | Subjects the assistant must refuse |
| **Access** | Workspace roles, SSO, IP restrictions, and role-based access to knowledge |
| **Data retention** | Full queries or metadata only, set by account or by agent |
| **Orchestration steps** | Guardrail enforcement, small talk handling, intelligent agent routing, enterprise knowledge lookup, and fallback to AI knowledge |

## Plan your rollout

Choose where employees meet AI for HR and who uses it first. A small pilot group surfaces policy gaps before the whole workforce sees them.

- **Channels:** the AI for Work assistant, Microsoft Teams, Copilot, web, and voice, plus SDKs for your own apps.
- **Regions:** policy answers cover India and the US. Index content for every region your pilot group works in.
- **Pilot group:** pick employees and managers who raise HR requests often and give candid feedback.

Complete every item before configuration starts. Each open item blocks a later step.

| Item | Blocks Step |

| Phase 1 domains agreed | 2 |
| An owner named for each role | 2 |
| Workday and ServiceNow API access granted | 2 |

| LLM API key and model chosen | 4 |
| AI for Work workspace ready and governance settings agreed | 5 |
