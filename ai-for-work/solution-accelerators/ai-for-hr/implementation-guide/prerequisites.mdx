Gather every access, credential, and value on this page before you configure AI for HR. Each item unblocks a specific configuration step, and a missing item stops the build partway.

Work through the four sections in order: platform access, system access, knowledge, and configuration values.

## Platform access

AI for HR spans two Kore.ai products, and you need admin rights in both. Confirm these before your builder starts.

| Requirement | Why you need it |
|-------------|-----------------|
| **Agent Platform workspace** | Holds the agentic app, its agents, tools, and config variables. |
| **AI for Work workspace with admin access** | Hosts the Autonomous Agent that employees use, plus enrollment, guardrails, and retention settings. |
| **Search AI access in XO11** | Connects your policy repository and serves knowledge answers. |
| **LLM provider credentials** | Power every agent. Add the API key and select a model in the workspace catalog. |

## System access

The agents read from and write to your HR systems through HTTP tools. Ask your system owners for endpoints and credentials early, because approvals often take longest.

| System | What AI for HR does there |
|--------|---------------------------|
| **Workday** | Reads and writes leave, benefits, payroll, the employee master record, timesheets, and termination. |
| **ServiceNow** | Reads the HR service catalog and creates, comments on, views, and resolves HR cases. |

Use a test tenant for your first build. Offboarding submits a real resignation, and time off creates a real request.

## Knowledge content

Case Management answers policy questions only from content that Search AI indexes. Prepare the content and its owners before configuration.

- Identify the policy and handbook content employees ask about most.
- Confirm that the content lives in a repository Search AI connects to, such as Confluence Cloud.
- Index content for India and the US, the two regions the agent passes downstream.
- Name an owner who keeps the content current after go-live.

## Configuration values

The tools resolve identity and connection values at run time. Collect these values so your builder enters them once.

| Value | Used by |
|-------|---------|
| `EMPLOYEE_ID` | Leave balance, holidays, and requests; adding dependents; enrolled benefits; payslips; resignation |
| `DEPENDENTS_EMPLOYEE_ID` | Fetching existing dependents |
| `USERID` | Fetching the employee's information |
| `USER_ID` | Fetching resignation reasons |
| **Search AI client ID and client secret** | Generating the auth token for the advanced search API |
| **Search AI `sourceType` value** | Filtering the search to your indexed source |

<Note>AI for Work passes the employee's email to the agentic app as metadata. Plan how your agents use that value alongside the config variables above.</Note>

## Readiness check

Confirm each item below before you open Agent Platform. An open item blocks the step shown.

| Item | Blocks |
|------|--------|
| Agent Platform workspace available | Tool configuration |
| Workday and ServiceNow endpoints and credentials granted | Tool configuration |
| Config variable values collected | Tool configuration |
| Policy content indexed, with client ID, secret, and `sourceType` ready | Search AI connection |
| LLM credentials added and a default model set | Agent responses |
| AI for Work workspace and admin access confirmed | Deployment |
