Configure AI for HR in Agent Platform in three passes: create the HTTP tools, build and register the workflow tools, then add the config variables the tools read at run time. Finish with the LLM setup, so every agent answers with the model you chose.

Follow the order below. Workflows depend on HTTP tools, and agents depend on registered workflows.

## Configure an HTTP tool

Each HTTP tool calls one endpoint in Workday, ServiceNow, or Search AI. Create one tool for each call the agents make.

1. In your project, go to **Tools** and click **+ New Tool**, then select **HTTP**.
2. Enter the tool name and description, then click **Next**.
3. Enter the endpoint URL, method, headers, and parameters.
4. Click **Next**, then click **Create tool**.
5. Open the tool, go to **Testing**, click **Run test**, and enter the required input parameters to confirm the call works.

<Tip>Test every HTTP tool before you add it to a workflow or an agent. A tool that passes here rules out endpoint, header, and input problems later.</Tip>

## Configure a workflow tool

A workflow chains HTTP tools and logic, such as creating a time off request or aggregating payslips. Building one takes two steps, and registering it takes a third.

1. Create the HTTP tools the workflow calls.
2. Build the workflow and select each configured HTTP tool inside it.
3. Go to **Tools** > **Workflows** and click **+ Register Workflow**.
4. Enter the tool name and description, select the workflow, and set the execution mode to **Synchronous**.
5. Click **Register Workflow**.

<Note>An agent sees a workflow only after you register it. An unregistered workflow never appears in the agent's tool list.</Note>

## Configure config variables

Config variables hold identity and connection values, so the same tool definitions work across environments. Add them once at project level.

1. Go to project **Settings** and select **Config Variables** under **General**.
2. Click **+ Add Variable**.
3. Enter the key, type, value, and description, then save.
4. Reference the variable in a tool with this path:

```text
{{config.KEY}}
```

AI for HR uses four identity variables:

| Variable | Used by |
|----------|---------|
| `EMPLOYEE_ID` | Leave, dependents, enrolled benefits, payslips, and resignation |
| `DEPENDENTS_EMPLOYEE_ID` | Fetching existing dependents |
| `USERID` | Fetching the employee's information |
| `USER_ID` | Fetching resignation reasons |

## Configure the LLM

Every agent needs a model, and the project default must match the workspace default. Add the credentials first, then the model.

1. Go to **Workspace Settings** > **AI Configuration** > **LLM Providers** > **Credentials**.
2. Click **+ Add Credentials**, enter the name and API key, select the provider type, and click **Add Credential**.
3. Open **Model Catalog** and click **+ Add Model**.
4. Select the provider from **Browse Catalog**, search for the model, and click **Add to Workspace**.
5. Click the star icon next to the model to set it as the default.
6. Go to **Project Settings** > **General** > **Models** and confirm that the default matches the workspace default.

## What comes next

Two steps remain after the platform configuration. Connect your knowledge source, then publish the app to employees.

- Connect your policy repository in **Connect Search AI**.
- Publish the agentic app in **Deploy in AI for Work**.
