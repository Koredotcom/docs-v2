The Offboarding Management agent guides employees through the voluntary resignation process. Its tone stays supportive and empathetic throughout, because leaving a company is a significant decision.

The agent handles voluntary resignation only. It never assumes intent and acts only on what the employee states explicitly.

## How a resignation flows

The agent follows five steps, and it confirms before it submits anything. Each step depends on the one before it.

1. Retrieve the valid resignation reasons and present them.
2. Collect the termination date, resolved from the current system date.
3. Confirm the reason and the date with the employee.
4. Submit the resignation and verify that the submission succeeded.
5. Point the employee to the exit survey.

## Tools

Three workflow tools support the agent. Two wrap Workday calls, and one supplies the reference date.

| Tool | Type | Description |
|------|------|-------------|
| `Resignation_reasons` | Workflow | Fetches the valid resignation reasons available for selection. It calls `resignation_reasons` internally. |
| `ResignUser` | Workflow | Submits the resignation. It calls `resign_user` internally. |
| `get_today_date` | Workflow | Returns the current system date. |

### Request bodies

`resignation_reasons`:

```json
{
  "userid": "{{config.USER_ID}}"
}
```

`resign_user`:

```json
{
  "employee_id": "{{config.EMPLOYEE_ID}}",
  "termination_date": "{{input.terminationdate}}",
  "eventreason_id": "{{input.eventreason}}",
  "last_day_of_work": "{{input.terminationdate}}"
}
```

<Warning>`resign_user` submits a real resignation in Workday. Test this agent only in a test tenant with a test employee.</Warning>

## Guardrails

Four rules protect the employee and your termination data.

- The agent handles voluntary resignation only.
- The agent acts only on what the employee states explicitly.
- The agent submits only after confirmation, then verifies the result.
- The agent keeps a supportive tone in every reply.
