HR_Supervisor is the single entry point into the AI for HR runtime. It reads every employee message, identifies the HR intent, and hands the request to exactly one specialist agent.

The supervisor is a router and nothing more. It never performs specialist HR work such as leave, benefits, compensation, or profile updates, and it never runs an HR transaction tool.

## What it does

The supervisor completes four actions on every turn. Each action takes place before any specialist sees the request.

1. Identifies the employee's HR intent from the message.
2. Stores the intent and the request context in shared session memory.
3. Returns a brief, professional acknowledgment.
4. Hands off to exactly one specialist.

## Intent categories

The supervisor routes across seven intent categories, one for each specialist. Each category carries its own lexical cues in the agent instructions.

| Intent | Specialist |
|--------|------------|
| `time_off` | Time Off Assistant |
| `benefits` | Benefit Management |
| `compensation` | Compensation |
| `profile_management` | Profile Management |
| `case_management` | Case Management |
| `offboarding` | Offboarding Management |
| `timesheet_management` | Timesheet Management |

## When the intent is unclear

The supervisor never guesses. When it can't determine an intent, it recovers in a fixed sequence.

1. Presents the seven service areas to the employee.
2. Retries the classification once.
3. Re-extracts the intent from the employee's reply and routes.

## Session memory

The supervisor writes the routing decision to memory scoped to the session. Every agent declares the same memory block, so the receiving specialist reads the context instead of asking again.

| Memory key | Type | What it holds |
|------------|------|---------------|
| `current_intent` | string | The HR intent category detected from the request |
| `target_agent` | string | The specialist selected for this turn |

## Handoff behavior

The supervisor carries one HANDOFF block per specialist, and each block is gated on an intent category. Exactly one block fires per turn, and the supervisor passes a short context summary with it.

Every block uses `RETURN: true`, `ON_RETURN: continue`, and `ON_FAILURE: continue`. Control returns to the supervisor once the specialist finishes its turn.

## Guardrails

Three rules keep the supervisor inside its role. They also make routing problems easy to spot in the trace.

- It routes to exactly one specialist per turn.
- It never performs specialist HR work itself.
- It never runs an HR transaction tool.

## Tools

HR_Supervisor attaches no tools. Every data call belongs to the specialist that owns the domain.
