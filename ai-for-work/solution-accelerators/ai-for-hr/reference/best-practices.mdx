These practices come from how AI for HR is built: how the supervisor routes, how the tools resolve identity, and how the agents ground their answers. Apply them during configuration and after go-live.

Each section covers one stage: scope, configuration, knowledge, testing, rollout, and operations.

## Scope the first release tightly

A narrow first release reaches employees faster and produces cleaner feedback. Add domains once the first set runs smoothly.

- Start with the domains that generate the most HR tickets today.
- Deploy Case Management early. It answers from content you already own and turns every unanswered question into a structured case.
- Add write-heavy domains, such as offboarding, after your team trusts the read paths.

## Keep configuration portable

Config variables exist so the same tool definitions work across environments. Use them consistently, and promotion between environments stops breaking.

- Put every identity and connection value in a config variable, never in a request body.
- Reference values as `{{config.KEY}}` and keep key names identical across environments.
- Review shipped tools for hard-coded identifiers before your first test.
- Register every workflow with the execution mode set to Synchronous.

## Treat knowledge content as a product

Case Management answers only from what Search AI indexes, so your content quality sets your answer quality. Give the content an owner and a review cycle.

- Index policy content for India and the US, the two regions the agent passes downstream.
- Review indexed content whenever a policy changes.
- Track the questions that end in a case. They show you the gaps in your content.
- Keep one source of truth per policy, so the search returns one consistent answer.

## Test from the bottom up

Test tools first, then agent rules, then full scenarios. A failing tool breaks every agent that calls it, so start there.

- Run each HTTP tool from **Testing** > **Run test** before any agent uses it.
- Use a test tenant for offboarding and time off, because both write real records.
- Read the multi-agent trace whenever a scenario fails. It names the agent and the step.
- Rerun the whole scenario suite after any change to instructions, tools, or content.

## Roll out in stages

A pilot group surfaces policy gaps before the whole workforce sees them. Keep the group small and the feedback loop short.

- Pick employees and managers who raise HR requests often and give candid feedback.
- Launch in one channel first, then add Microsoft Teams, Copilot, web, and voice.
- Tell employees what the assistant does and does not do, so expectations match the scope.
- Record a KPI baseline before launch, so you can show the change afterward.

## Operate with intent

Adoption grows when someone owns the assistant after go-live. Assign that owner during planning, not after launch.

- Watch workspace analytics weekly: queries, active users, queries per agent, and top agents.
- Review audit logs for unexpected agent activity.
- Evaluate agents for accuracy, relevance, and bias after every change.
- Feed recurring case topics back into your knowledge content.

## Write agent instructions that stay predictable

If you extend the accelerator with your own agents, follow the conventions the shipped agents use. Consistency keeps routing reliable.

- Give each agent one domain and no overlapping tools.
- Carry a HANDOFF block for every peer, so a topic change reaches the right agent.
- Require confirmation before any write action.
- Surface missing information instead of assuming it.
