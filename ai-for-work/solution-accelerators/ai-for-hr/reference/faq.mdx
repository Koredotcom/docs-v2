These questions come up most often when teams evaluate, configure, and run AI for HR. Each answer points to the page that covers the topic in full.

Use this page as a quick reference during evaluation calls and rollout briefings.

## About the accelerator

### What is AI for HR?

AI for HR is a Solution Accelerator: a multi-agent application that Kore.ai has already built and tested for HR self-service. It runs on Agent Platform and reaches employees through AI for Work as one Autonomous Agent.

### Which service areas does it cover?

It covers seven areas: time off, benefits, pay, profile, HR policies and cases, resignation, and timesheets. Each area belongs to one specialist agent.

### How much of it do we build ourselves?

You configure rather than build. The agents, routing, handoffs, tools, and safety rules ship with the accelerator, and you supply system access, config values, knowledge content, LLM credentials, and governance settings.

### Can we extend it?

Yes. You add your own agents, tools, and workflows on Agent Platform, and you point the shipped HTTP tools at your own endpoints.

## Systems and data

### Which systems does it connect to?

The shipped tools call Workday for leave, benefits, payroll, the employee master record, timesheets, and termination, and ServiceNow for the HR service catalog and cases. Search AI serves policy knowledge.

### Does it store our HR data?

No. The agents read from and write to your systems of record through HTTP tools, and they surface values verbatim from those systems.

### How does the assistant know who is asking?

AI for Work passes the employee's email to the agentic app as metadata, and the HTTP tools resolve identity from config variables. See **Prerequisites** for the full list of values.

### Which languages and regions does it support?

Case Management infers the region from the message and passes either India or the US downstream. Index policy content for both regions, so employees in either location get an answer.

## Behavior

### Can the assistant change data without asking?

No. Read paths run freely, and every write path requires explicit in-chat confirmation from the employee.

### What happens when the assistant can't answer a policy question?

It offers to raise an HR case rather than answering from general knowledge. It then collects the title, description, and priority and creates the case in ServiceNow.

### What happens if an employee changes topic midway?

The current specialist hands the conversation to the peer that owns the new topic and takes it back once that peer finishes. The employee sees one continuous conversation.

### Can an employee see a colleague's payslip?

No. Compensation serves the logged-in employee only, and it cannot modify payroll, issue refunds, or resolve disputes.

### Can managers see their team's data?

Managers view timesheets for their direct reports, and they find colleagues through the directory search. Other team data stays in your HR systems.

## Implementation

### How long does implementation take?

The work divides into six steps: plan, configure tools, connect knowledge, set the LLM, deploy, and validate. Your timeline depends mostly on how fast you get API access and indexed content.

### Who needs to be involved?

Five roles: an AI for Work admin, an Agent Platform builder, HR system owners, HR knowledge owners, and a pilot group from the HR team. See **Plan your AI for HR implementation**.

### Do we need a test environment?

Yes. Offboarding submits a real resignation and time off creates a real request, so run your first build against a test tenant.

### How do we test the deployment?

Test in three layers: each tool on its own, then the agent rules, then full scenarios in AI for Work. See **Validate and test AI for HR**.

## Operations

### How do we monitor usage?

Use AI for Work workspace analytics for queries, active users, tokens, queries per agent, and top agents. Use audit logs to trace user actions and agent activity.

### How do we debug a failed conversation?

Open the multi-agent trace for the session. It names the agent that handled each turn, every model call, and every tool run with its status.

### How do we keep answers current?

Review your indexed policy content whenever a policy changes, and evaluate the agents after any change to instructions, tools, or content.
