Use the AI for Work public APIs to send notifications, retrieve audit logs, and retrieve trace logs from your own applications and reporting tools.

| API | Description |
|-----|-------------|
| [Notify API](#notify-api) | Send interactive notifications with action buttons to users through an agent. |
| [Audit Log API](#audit-log-api) | Retrieve administrative and user activity records for reporting, SIEM integration, or compliance workflows. |
| [Trace Log API](#trace-log-api) | Retrieve query-level trace log records, including response time, token consumption, models, intent, and feedback. |

---

## Authentication

All AI for Work public API requests go to `https://{{host}}/api/public/`, where `{{host}}` is the AI for Work environment URL for your account.

Each API uses one of two credentials:

| API | Credential | Header |
|-----|-----------|--------|
| Notify API | The agent access token from the agent settings page | `authorization` |
| Audit Log API | A Personal API Key generated by an Admin user | `auth` |
| Trace Log API | A Personal API Key generated by an Admin user | `auth` |

### Generate a Personal API Key

The Audit Log API and the Trace Log API accept only a Personal API Key that a user with the Admin role generates. Keys generated by users without the Admin role do not work with these APIs.

To generate a Personal API Key:

1. Sign in to AI for Work.
2. Open the profile menu and select **Personal API Key**.
3. Copy the generated key and store it securely.

## Notify API

The Notify API sends interactive notifications to users. Notifications can include customizable response options and action buttons. For how agents pause and resume conversations around alerts, see [Handling Alert Tasks](/ai-for-work/custom-agents/agent-management#handling-alert-tasks).

<Note> Applicable only for Bot, Autonomous, and Workflow Agents. </Note>

### Endpoint Reference

| Property | Value |
|---|---|
| **Method** | POST |
| **Endpoint** | `https://{{host}}/api/public/agents/{agentId}/notify` |
| **Content-Type** | `application/json` |
| **Authorization** | `authorization: (authToken)` — The access token obtained from the agent settings page. |
| **API Scope** | Notification |

### Path Parameters

| Parameter | Required/Optional | Description |
|---|---|---|
| host | Required | Environment URL, for example `https://work.example.ai` |
| agentId | Required | The unique identifier of the agent. Replace `{agentId}` in the URL with the actual agent ID, obtained from the Post URL field while creating an agent. |

### Request Body Parameters

| Parameter | Type | Required/Optional | Description |
| --- | --- | --- | --- |
| to | string | Required | Email address of the application user (single recipient). |
| message | object | Required | Contains notification title and body text. |
| message.title | string | Required | Notification title. |
| message.body | string | Required | Notification message body. |
| category | string | Required | Category of the notification (e.g., `"agent"`). |
| actions | array | Required | Array of interactive response buttons. |
| actions[].title | string | Required | Button label text. |
| actions[].type | string | Required | Action type (e.g., `"postback"`). |
| actions[].utterance | string | Required | Text sent when the user selects the button. |
| actions[].payload | object | Required | Custom data passed with the action. |

### Sample Request

```bash
curl --location --request POST 'https://work.example.ai/api/1.1/public/agents/ag-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx/notify' \
--header 'authorization: (YOUR_AUTH_TOKEN)' \
--header 'Content-Type: application/json' \
--data-raw '{
    "to": "john.doe@example.com",
    "message": {
        "title": "Agent Update",
        "body": "Notification description"
    },
    "category": "agent",
    "actions": [
        {
            "title": "LaptopRequest",
            "type": "postback",
            "utterance": "submit action 1",
            "payload": {
                "transactionId": "tx-qwe2cd11",
                "sessionId": "s-hr3wx21rt",
                "event": "laptopRequest"
            }
        }
    ]
}'
```

### Sample Response

```json
{
    "notify": "success"
}
```

### Key Points

* The `to` email address must belong to a valid application user.
* The `to` key accepts a single email address in the initial implementation.
* Use custom payload data for tracking and response handling.
* Include `actions` in the request payload to present users with interactive buttons.

## Audit Log API

The Audit Log API retrieves log data programmatically for custom reporting, SIEM integration, or compliance workflows. For what the audit log records and where to view it in the product, see [Audit Log](/ai-for-work/administration/audit-log).

### Endpoint Reference

| Property | Value |
|----------|-------|
| **Method** | `GET` |
| **Endpoint** | `https://{{host}}/api/public/auditlogs` |
| **Content-Type** | `application/json` |
| **Authorization** | `auth: {{PersonalToken}}` — A Personal API Key generated by an Admin user. See [Generate a Personal API Key](#generate-a-personal-api-key). |

### Query Parameters

All parameters are optional. Combine them to narrow results.

| Parameter | Description | Example |
|-----------|-------------|---------|
| `entity` | Type of resource to filter by | `entity=usergroups` |
| `entityId` | Unique ID of a specific resource instance | `entityId=12345` |
| `userId` | Filter by the user who performed the action | `userId=john_doe` |
| `emailId` | Filter by the email address of the acting user | `emailId=john.doe@example.com` |
| `startTime` / `endTime` | Time window for the query (ISO 8601 format) | `startTime=2024-12-01T00:00:00Z&endTime=2024-12-05T23:59:59Z` |
| `action` | Type of action: `create`, `update`, or `delete` | `action=create` |

### Supported Entities and Actions

| Entity | `entity` Key | Supported Actions |
|--------|-------------|-------------------|
| User Group | `usergroup` | create, update, delete |
| Agent | `Agent` | create, update, delete |
| Role | `role` | create, update, delete |
| SSO Status | `ssostatus` | update |
| Service Account | `serviceaccount` | create, update, delete |
| LLM Integrations | `llmintegrations` | create, update, delete |
| Domains | `domains` | create, update, delete |
| Rate Limits | `ratelimits` | update |
| Email Notification Preferences | `emailnotificationpreferences` | update |
| Business Rules | `nlprules` | create, update, delete |
| User Enrollment | `userenrollment` | update |

### Sample Request

```bash
curl --location 'https://{{host}}/api/public/auditlogs?startTime=2024-12-01T23%3A59%3A59Z&endTime=2024-12-12T23%3A59%3A59Z&entity=nlprules&action=update&emailId=test.user%40example.com' \
--header 'auth: {{PersonalToken}}'
```

## Trace Log API

The Trace Log API retrieves trace log records for a specified date range. Each record captures a single user request and includes response time, token consumption, the models involved, the identified intent, and any feedback the user submitted. Use this API to pull usage, latency, token, and feedback data into your own reporting tools, data warehouses, or internal dashboards. For what a trace log shows in the product, see [Trace Logs](/ai-for-work/analytics#trace-logs).

### Endpoint Reference

| Property | Value |
|----------|-------|
| **Method** | `GET` |
| **Endpoint** | `https://{{host}}/api/public/analytics` |
| **Content-Type** | `application/json` |
| **Authorization** | `auth: {{PersonalToken}}` — A Personal API Key generated by an Admin user. See [Generate a Personal API Key](#generate-a-personal-api-key). |
| **Required Role** | Admin |

### Headers

| Header | Value | Description |
|--------|-------|-------------|
| `auth` | `{{PersonalToken}}` | The Personal API Key generated from the profile menu. |
| `accept` | `application/json, text/plain, */*` | Accepted response content types. |
| `content-type` | `application/json` | Request content type. |

### Query Parameters

| Parameter | Required/Optional | Type | Description |
|-----------|-------------------|------|-------------|
| `startDate` | Required | Number | Start of the date range, as a Unix timestamp in milliseconds. |
| `endDate` | Required | Number | End of the date range, as a Unix timestamp in milliseconds. |

### Sample Request

```bash
curl --location \
  'https://{{host}}/api/public/analytics?startDate=1744108557559&endDate=1744194957559' \
  --header 'accept: application/json, text/plain, */*' \
  --header 'content-type: application/json' \
  --header 'auth: {{PersonalToken}}'
```

### Response Reference

**Top-level response**

| Parameter | Type | Description |
|-----------|------|-------------|
| `analytics` | Array of objects | The trace log records that match the requested date range. |
| `hasMore` | Boolean | Returns `true` if more records are available beyond those returned. |
| `filters` | Object | The date range applied to the request. |
| `filters.startDate` | Number | Start of the applied date range, as a Unix timestamp in milliseconds. |
| `filters.endDate` | Number | End of the applied date range, as a Unix timestamp in milliseconds. |

**Trace log record**

Each object in the `analytics` array contains the following fields.

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | String | Unique identifier for the record. |
| `lMod` | Number | Timestamp of the last modification to the record. |
| `timestamp` | Number | Timestamp indicating when the platform processed the request. |
| `responseTimeMs` | Number | Total response time for the request, in milliseconds. |
| `llmStats` | Array of objects | Events describing each stage of LLM processing, including small talk handling, intent detection, and final answer generation. See **LLM event object**. |
| `agentInfo` | Object | Information about the agent that performed the task. |
| `totalReqTokens` | Number | Total number of tokens used in the request. |
| `totalRespTokens` | Number | Total number of tokens generated in the response. |
| `queryPoints` | Number | Scoring or ranking metric applied to the query. |
| `status` | Boolean | Indicates whether the platform processed the request successfully. |
| `userId` | String | Unique identifier for the user who made the request. |
| `accountId` | String | Unique identifier for the account or tenant. |
| `feedback` | Object | Feedback the user submitted for the response. See **Feedback object**. |
| `channel` | String | The platform or medium through which the user made the request, for example, `web`. |
| `intentModel` | String | The LLM model used to determine the intent. |
| `reqStatus` | String | The current status of the request. |
| `question` | String | The query or request the user submitted. |
| `intent` | String | The intent identified for the user question. |
| `msgId` | String | Unique identifier for the message. |
| `boardId` | String | Unique board identifier related to the request. |
| `traceId` | String | Unique request identifier. |
| `wsId` | String | Unique workspace identifier. |
| `totalRespTime` | Number | Total time taken to process and return the response, in milliseconds. |

**LLM event object**

Each object in the `llmStats` array contains the following fields.

| Parameter | Type | Description |
|-----------|------|-------------|
| `e` | String | The specific LLM event, for example, `Guardrail Validation` or `getAnswer`. |
| `eType` | String | The event type, for example, `llm`. |
| `m` | String | The LLM model used for the event. |
| `ts` | Number | Timestamp marking when the platform logged the event. |
| `rt` | Number | Response time for the event, in milliseconds. |
| `responseTimeMs` | Number | Response time for the event, in milliseconds. |
| `ipT` | Number | Number of input tokens sent to the model for the event. |
| `opT` | Number | Number of output tokens the model generated for the event. |
| `llmEvent` | String | The specific LLM event. |

**Feedback object**

| Parameter | Type | Description |
|-----------|------|-------------|
| `value` | String | The feedback rating, for example, `like` or `dislike`. |
| `comment` | String | Free-text comment the user submitted. |
| `category` | Array of strings | Feedback categories the user selected, for example, `Not factually correct`. |
