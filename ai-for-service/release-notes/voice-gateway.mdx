## v11.28.0 August 29, 2026

<Badge> Minor Release </Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">ASR and TTS</p>

<p className="rn-subtitle">Speech Speed and Pronunciation Controls for Deepgram Aura-2 TTS</p>

Deepgram Aura-2 TTS now supports configurable speech speed (0.7-1.5, default 1.0) using call control parameters and IPA-based pronunciation overrides for domain-specific terms. [Learn more→](/ai-for-service/channels/voice-gateway/speech-customization#deepgram)

<p className="rn-subtitle">Centralized Default and Multi-region Fallback for ASR or TTS Providers</p>

Voice Gateway now automatically applies default primary and fallback ASR or TTS providers when none are configured at the node, flow, or app level. User-configured settings always take precedence, and fallback resolution prefers the same provider in the target region for speech consistency. 

<p className="rn-title">Call Control Parameters</p>

<p className="rn-subtitle">Turn Detection Model Using Call Control Parameters</p>

The Turn Detection Model is now configurable through call control parameters, letting administrators tune end-of-utterance detection for voice interactions. Available controls include enabling intelligent turn detection, selecting the detection model, adjusting the response speed threshold, supporting open-ended responses, and defining the expected answer shape — such as digits, date, choice, or regex — with optional length, range, and valid option constraints. [Learn more→](/ai-for-service/channels/voice-gateway/speech-customization#turn-detection-parameters)

<p className="rn-title">Integration</p>

<p className="rn-subtitle">Auto-generated Genesys Audio Connector WSS URL for Artemis</p>

Voice Gateway now exposes a provisioning API that generates a unique, project-bound audiosocket WSS URL for Genesys Audio Connector channels created in Artemis. The generated URL terminates inbound Genesys audio at Voice Gateway, forwarding ASR transcripts and TTS playback to Artemis over the existing text WebSocket, without requiring manual URL entry. [Learn more→](https://docs.kore.ai/agent-platform/channels/set-up-genesys-audio-connector)

<p className="rn-title">WebSDK</p>

<p className="rn-subtitle">Configurable Full-window Expansion for Video Call Widget</p>

A new `enableFullScreenVideoCall` parameter in the Web SDK controls whether the video call expands to a full-window or stays within the widget area. The default is false (widget-bound), preserving existing behavior for integrations that do not set the parameter. [Learn more→](https://github.com/Koredotcom/web-kore-sdk/tree/v3/dev/docs/plugins/agent-desktop#video-call-expansion)

<p className="rn-title">Configuration</p>

<p className="rn-subtitle">Configurable Recording Initiation and Consent Handling for Video Calls</p>

Video Call Recording Settings now include a Recording Start option - Manual (default) or Automatic - and a Recording Consent option - Display Consent Prompt (default) or Consent Managed Externally. These settings can be combined independently to match different customer compliance models. Existing customers retain the current behavior of manual recording with an in-product consent prompt. [Learn more→](/ai-for-service/app-settings/advanced-settings/system-settings#video-call-recording-control)

## v11.27.1 August 08, 2026

<Badge> Patch Release </Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">Call Control Parameters</p>

<p className="rn-subtitle">Backchannel Phrases Accepted as a Call Control Parameter</p>

Voice Gateway now accepts a backchannel words array from the Agent node as a call control parameter, applying the same keep-playing behavior as the existing Artemis path — detected backchannel words during playback suppress barge-in without interrupting audio. Behavior is consistent whether the phrase list comes from AI for Service or Artemis. [Learn more→](/ai-for-service/channels/voice-gateway/speech-customization#barge-in-related-parameters)

<p className="rn-subtitle">Ignore Voice Backchannel Inputs During User Input Processing</p>

Voice Gateway now supports configurable backchannel word filtering, letting administrators prevent common acknowledgments like **yeah**, **uh-huh**, and **okay** from triggering Natural Language Understanding (NLU) processing or dialog execution. [Learn more→](/ai-for-service/channels/voice-gateway/speech-customization#backchannel-words)

## v11.27.0 July 25, 2026

<Badge> Minor Release </Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">ASR and TTS</p>

<p className="rn-subtitle">Sarvam ASR and TTS Support Using Call Control Parameters </p>

Sarvam ASR and TTS are now available as native providers in the Voice Gateway, configurable through call control parameters. Sarvam TTS supports pace and temperature controls for fine-tuning speech output. [Learn more→](/ai-for-service/channels/voice-gateway/speech-customization#sarvam-asr)

<p className="rn-title">Voice Calls</p>

<p className="rn-subtitle">Agent Network Interruption Re-routing for Outbound and Campaign Calls</p>

The agent network interruption re-routing behavior - including queue re-injection, AI context summary, transfer notification tag, transcript timeline events, and Diagnostics page updates - now applies to manual outbound and campaign outbound calls, in addition to inbound calls. [Learn more→](/ai-for-service/contact-center/agent-console#re-routing-voice-calls-due-to-network-interruption)

<p className="rn-title">API</p>

<p className="rn-subtitle">Register Custom ASR/TTS Speech Vendors</p>

The speech-services API lets administrators register custom ASR and TTS vendors in the Voice Gateway, with separate endpoint configurations for speech-to-text, text-to-speech, and TTS streaming. This enables integrations with third-party or proprietary speech providers not available in the built-in vendor list. [Learn more→](/ai-for-service/apis/contact-center/create-custom-speech-service)

## v11.25.0 May 30, 2026

<Badge> Minor Release </Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">Call Recording</p>

<p className="rn-subtitle">Enhanced Call Recording Status Handling and Messages</p>

Call recording statuses have been updated for clearer visibility into failures. Calls under two seconds now surface a dedicated unavailability status. Both the Fetch Call Recording and Fetch Call Recording V2 APIs reflect these updated statuses and messages. [Learn more→](/ai-for-service/analytics/overview/conversations#call-recording)

<p className="rn-title">Configuration</p>

<p className="rn-subtitle">Configuration Actions Restricted in Published Mode</p>

When an app is in Published mode, configuration-modifying actions in the Voice Gateway module are now restricted. Phone number and SIP trunk management actions — including purchase, assign, update, and delete — are disabled, and Voice Preferences, Voice Call Properties, and System Error Settings show only a View option. [Learn more→](/ai-for-service/channels/voice-gateway/configure-voice-gateway#published-mode-restrictions)

<p className="rn-subtitle">Voice Authentication removed from the UI</p>

The Voice Authentication option has been removed from Language & Speech settings as no provider support is currently available. Other Language & Speech configurations are unaffected. 

<p className="rn-title">API</p>

<p className="rn-subtitle">Per-turn Latency Breakdown in Conversation History API</p>

The `getMessages`, `getMessagesV2`, and `messages-lite` APIs now support an `includeLatency=true` parameter that returns a per-turn latency breakdown for bot response messages on the Voice Gateway, covering ASR, bot processing, and TTS segments. [Learn more→](/ai-for-service/apis/automation/conversation-history)

## v11.24.0 April 25, 2026

<Badge> Minor Release </Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">ASR and TTS</p>

<p className="rn-subtitle">Playback Status for Background TTS Streaming</p>

Playback status is now captured during background TTS streaming to determine completion and prevent interruptions in call flows. This ensures accurate execution of subsequent call actions across Deepgram, ElevenLabs, and custom TTS vendors.

<p className="rn-subtitle">Word-Level Timestamps for ASR Transcriptions</p>

Word-level timestamps for ASR-generated transcriptions are now stored and made available for downstream modules and use cases, supporting features such as quality analysis and detailed conversation insights. Timestamps are captured and persisted in their native format for flexible consumption.

<p className="rn-subtitle">ASR Dropdown Support for Deepgram Flux</p>

The Deepgram Flux option now appears in the ASR dropdown alongside Deepgram in the Start Flow configuration. Selecting it applies default values for `deepgramEotThreshold` and `deepgramEotTimeoutMs` in the session configuration. User-defined values override defaults when explicitly configured. [Learn more→](/ai-for-service/channels/voice-gateway/configure-voice-gateway#voice-preferences)

<p className="rn-title">Call Transcription</p>

<p className="rn-subtitle">Transcript Enhancement for IVR Prompts and DTMF Capture</p>

IVR prompts played during waiting and callback flows-including Initial, Transfer, Periodic, Callback, Voicemail, and Chat Deflection messages-are now recorded in the interaction transcript along with all user DTMF inputs. DTMF entries appear in the same format as Automation interactions and follow the correct chronological sequence. Callback scenarios include both the user's DTMF input and confirmation messages without data loss.

<p className="rn-subtitle">Transcription Language Selection for Manual Outbound Calls</p>

Agents can select a transcription language during manual outbound calls via a dropdown that includes enabled languages from user attributes, plus an Autodetect option. If no selection is made, the bot language is applied by default. Any language selected will be saved for future calls, with the option to modify it before each call. [Learn more→](/ai-for-service/contact-center/agent-console#manual-call-dialer)

<p className="rn-title">Call Recording</p>

<p className="rn-subtitle">Video Call Recording for Chat-Escalated Interactions</p>

Agents can manually start, pause, resume, and stop video call recording with customer consent. The recording captures video, audio, and screen share, with clear indicators shown to both the agent and the customer. Recordings stop when the call ends, process asynchronously, and are available as download-only files with defined retention (of voice call recordings) and error handling. [Learn more→](/ai-for-service/contact-center/agent-console#video-call-recording)

## v11.23.1 April 11, 2026

<Badge> Patch Release </Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">Text to Speech</p>

<p className="rn-subtitle">Background TTS Streaming Enhancements</p>

* **TTSOptions Support**: `ttsOptions` is now supported during background TTS streaming, allowing dynamic voice and language changes. This applies across Message, Entity, and Agent nodes without impacting streaming behavior, and excludes TTS text streaming to avoid latency from connection re-establishment.

* **Playback Status Support**: Playback status is now captured during background TTS streaming to accurately detect completion, ensuring correct handling of prompts, hang-up flows, and no-input scenarios. Currently, Microsoft ASR and Sarvam (Custom) are supported, with extensibility for other providers.

## v11.22.0 February 28, 2026

<Badge> Minor Release </Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">ASR and TTS</p>

<p className="rn-subtitle">Google Cloud TTS Streaming Support</p>

Google Cloud Text-to-Speech now supports both audio and text streaming. Audio streaming is enabled by default, while text streaming requires the TTS Streaming and Model Response Streaming flags. Streaming works across standard flows, Agent Node, and Agentic App use cases, with seamless playback, defined latency thresholds, fallback handling, and full backward compatibility. Support applies only to HD (Chirp) voices.

<p className="rn-subtitle">Azure TTS Text Streaming Support in Voice Gateway</p>

Voice Gateway now supports Azure TTS text streaming, enabling progressive speech synthesis for real-time LLM responses. Streaming operates over WebSocket with seamless audio continuity, validation controls, and graceful fallback to non-streaming mode when needed.

<p className="rn-subtitle">Deepgram ASR: Flux Model Integration</p>

Voice Gateway now supports the Deepgram Flux ASR model, delivering improved turn detection, lower latency, and better transcription quality. The ASR selection dropdown includes Deepgram ASR-Flux, supporting English across all accents.

<p className="rn-title">Agentic Apps</p>

<p className="rn-subtitle">Remove Tool-Call Audio in Agentic App</p>

The system no longer plays default music when the Agentic App makes a tool call using real-time voice APIs. The platform remains silent during tool execution until the bot responds, preventing audio overlap—even if the response is delayed.

<p className="rn-title">Configuration</p>

<p className="rn-subtitle">SIP Trunk Configuration: Same DID Handling</p>

If a SIP trunk uses the same DID with a different IP/FQDN, the system allows it across different accounts or apps, but prompts for confirmation within the same account and app. If both the DID and IP/FQDN match an existing entry, the system blocks creation and displays an error message.

## v11.21.0 January 17, 2026

<Badge> Minor Release </Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">ASR and TTS</p>

<p className="rn-subtitle">TTS Streaming at Start Flow Level</p>

TTS Streaming can be configured at the start flow level to reduce voice response latency. The platform maintains a persistent streaming connection throughout the call and adapts playback based on the model's response streaming behavior.

<p className="rn-subtitle">Continuous Gather at Start Flow Level</p>

Provided a Continuous Gather option at the start flow when TTS streaming is enabled. Caller input is captured continuously to reduce latency and support agentic voice interactions, without altering default behavior unless configured.

<p className="rn-subtitle">Model Selection for ASR and TTS Providers</p>

The platform now permits model selection for ASR and TTS providers directly from the app-level and Start Flow-level UIs. The selected model is consistently applied across design-time and runtime voice scenarios, including interactions, transcriptions, and monitoring, without requiring call-control parameters.

<p className="rn-subtitle">TTS Providers: Required Language Support</p>

The platform ensures that all natively supported TTS providers offer support for required languages wherever the vendor supports them. This applies to AWS Amazon Polly, Google, Microsoft Azure, ElevenLabs, OpenAI TTS, Deepgram, and similar integrations. The required languages include English, Japanese, Spanish, German, Arabic, French, Hindi, and Filipino.
