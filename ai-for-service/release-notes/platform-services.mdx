## v11.28.0 August 29, 2026

<Badge>Minor Release</Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

## LLM and Generative AI

### Multiple Configurations for OpenAI and Azure OpenAI

Developers can now configure multiple integrations for OpenAI and Azure OpenAI, enabling separate connections for different environments or regions. Each integration supports a unique name, endpoint, API key, and model set. Existing configurations automatically migrate to the default integration, whose name is set to the configured model name. [Learn more→](/ai-for-service/generative-ai-tools/llm-integration#multiple-integrations-for-openai-and-azure-openai)

### Build Resilient GenAI with Model Fallbacks

Introducing a fallback model to improve GenAI availability during outages and transient failures. Administrators can configure a primary model, fallback model, and resume interval. When the primary model fails, the platform automatically routes requests to the fallback model and resumes sending requests to the primary model after the configured duration. Fallback activity is available through logs and analytics. [Learn more→](/ai-for-service/generative-ai-tools/llm-integration#fallback-model)

### Reduce Guardrail Latency with Configurable Execution

Guardrails and feature calls can now be configured to run in parallel, reducing processing latency:

- **System and Custom Guardrails:** Enable parallel execution to evaluate system and custom guardrails concurrently. When disabled, system guardrails run before custom guardrails. Default: enabled.
- **Guardrails and Feature Calls:** Enable parallel execution to run feature calls concurrently with guardrails. When disabled, feature calls run after guardrails pass. Default: disabled. [Learn more→](/ai-for-service/generative-ai-tools/guardrails#guardrails-execution-settings)

### Control the Scope of Data Anonymization

Developers can now scope Data Anonymization to just the user input and conversation history rather than the entire outbound LLM request payload. This prevents non-PII content that matches a configured regex from being unintentionally anonymized, while still protecting sensitive user data. Disabled by default to preserve existing behavior. [Learn more→](/ai-for-service/generative-ai-tools/data-anonymization#limit-anonymization-scope)

### Closure Summary as a Standalone GenAI Feature

Closure Summary is now a standalone GenAI feature with its own model configuration, prompt, and enablement setting, independent of the Conversation Summary feature used for Arrival Summary. On upgrade, the existing Conversation Summary prompt is automatically copied as the default Closure Summary prompt, preserving current behavior until administrators choose to customize it. [Learn more→](/ai-for-service/contact-center/configurations/settings/configuration-settings#enable-llm-based-summarization)



## Channels

### Debug Logs Extended to Voice Conversations

Debug Logs now support voice conversations on the platform, making it easier for developers to troubleshoot voice conversations by tracing automation execution in real time, similar to how they can with chat conversations. Debug Logs open automatically during testing by default, but can be disabled.

### Support AutoSuggestions in Google Chat

The platform now supports autosuggestions in Google Chat. As users enter a search term in an entity configured as a Google Card, the platform sends the request to the configured endpoint and displays the returned suggestions, letting AI Agents provide relevant, real-time suggestions from external systems. [Learn more→](/ai-for-service/channels/add-google-chat#step-4-configure-the-google-chat-channel)


---

## Analytics

### Millisecond Precision for Debug Log Timestamps

Debug Logs under Task Execution Log now display timestamps down to the millisecond, with chronological sorting based on the full timestamp, and the same precision is retained in exported copies. This makes it easier to trace the exact execution order, for faster, more accurate root cause analysis during troubleshooting and app development. [Learn more→](/ai-for-service/analytics/automation/task-execution-logs#debug-log)

---

## App Settings

### German NLP Processing Migration for Machine Learning Engine

German language processing now uses the machine learning (ML) engine for intent detection, entity extraction, and interruption handling, replacing the legacy pattern-based CS approach. This update improves adaptability, accuracy, and maintainability for German conversations while preserving existing CS-based processing for all other supported languages.

---

## API

### Debug Logs API Support for Additional Channels

The Debug Logs API now supports MS Teams, Slack, Mattermost, Facebook, Google Chat, and Telegram, enabling programmatic retrieval of debug logs across additional communication channels with the same diagnostic detail available for existing channels. [Learn more→](/ai-for-service/apis/automation/fetch-debug-logs)

### Rate Limits for Analytics and Builder APIs

Rate limits for Analytics APIs have been updated to improve dashboard reliability by preventing repeated client-side requests after failed jobs. [Learn more→](/ai-for-service/apis/automation/api-list#analytics-apis)

### Pagination Support for LLM Usage Logs API

The LLM Usage Logs API now returns `moreAvailable` and `total` fields to indicate whether additional records exist and the total result count, simplifying pagination and reducing unnecessary API calls. [Learn more→](/ai-for-service/apis/automation/llm-usage-logs-api)

### Support Batch Session Retrieval in Get Sessions

The Get Sessions API now supports batch retrieval, allowing multiple session or call IDs in a single request payload. This reduces the need for parallel API calls when retrieving session details, helping customers stay within rate limits and improving retrieval efficiency for large-scale automation workflows. [Learn more→](/ai-for-service/apis/automation/get-sessions-history)

## v11.27.0 July 25, 2026

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">LLM and Generative AI</p>

<p className="rn-subtitle">Custom Guardrails Support</p>

Custom guardrails can now be created to enforce organization-specific safety and compliance requirements. Define validation logic in a custom prompt from the Prompts Library and use models from the Models Library to evaluate LLM inputs and outputs before they reach users. Custom guardrails run in parallel with system guardrails to minimize latency. [Learn more→](/ai-for-service/generative-ai-tools/guardrails#custom-guardrails)

<p className="rn-title">Configuration</p>

<p className="rn-subtitle">Granular User Management Permissions</p>

User Management permissions are expanded from three options (Full Access, View, None) to six: Full Access, Edit & Delete, Edit, View, View & Invite, and None. This lets administrators assign responsibilities more precisely — for example, granting edit rights without delete authority, or invite access without edit rights. [Learn more→](/ai-for-service/user-management/users-and-role#user-management)

<p className="rn-title">Analytics</p>

<p className="rn-subtitle">Conversations Dashboard: New Filter for No Response from Agent</p>

A new **No Response from Agent** filter in the Conversations tab lets supervisors filter conversations, including in-progress conversations, where an agent hasn't yet replied across all channels, except voice. [Learn more→](/ai-for-service/analytics/overview/conversations#create-filter)

<p className="rn-subtitle">Switch Conversations Without Closing the Details Tab</p>


Selecting a different conversation in the Conversations dashboard now updates the Details tab directly without requiring the current tab to be closed first. The conversation list remains fully interactive while the tab is open.

<p className="rn-subtitle">Custom Time Range and Timezone Support</p>


Analytics now supports custom date and time range filtering with second-level precision and timezone selection across all dashboards, providing a consistent filtering experience throughout the platform. [Learn more→](/ai-for-service/analytics/dashboard-filters#filter-criteria-descriptions)




<p className="rn-subtitle">Standard Response Statements</p>


Administrators can now disable individual statements from the Standard Responses edit page. When disabled, the AI Agent doesn't send the response during runtime conversations, providing greater control over system-generated messages. [Learn more→](/ai-for-service/automation/intelligence/conversation-management#statements)

<p className="rn-title">App Settings</p>

<p className="rn-subtitle">Selective Export of App Variable Categories</p>


Developers can now choose whether to include or exclude Environment Variables and Content Variables when exporting an app. Only the exported variable categories are imported into the destination environment, simplifying multi-environment deployments. By default, both variable categories are included. [Learn more→](/ai-for-service/deployment/app-management#exported-components-reference)

<p className="rn-title">Web SDK</p>

<p className="rn-subtitle">Web SDK File Sharing and Download Enhancements</p>


The Web SDK now supports customizable attachment download button styling and clearer file and image sharing actions, improving branding flexibility and the user experience.

## v11.26.0 June 27, 2026

<Badge>Minor Release</Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">LLM and Generative AI</p>

<p className="rn-subtitle">Connect AI Agents to External Tools via MCP</p>


AI Agents can now be integrated with enterprise applications using the Model Context Protocol (MCP), enabling a single connection to discover and enable tools that are automatically registered in GenAI Tools for reuse. Detailed execution logs provide visibility into tool activity for monitoring and troubleshooting. [Learn more→](/ai-for-service/generative-ai-tools/model-context-protocol)


<p className="rn-subtitle">JavaScript Prompts for Claude Models</p>

JavaScript prompts are now supported for Anthropic Claude models. The prompt template supports Messages API-compatible payloads, conversation history, and tool calling — automatically mapping inputs and outputs to Anthropic's tool_use and tool_result formats. Tool definitions are optional. [Learn more→](/ai-for-service/generative-ai-tools/llm-integration#anthropic)




<p className="rn-subtitle">Enhanced Recognition and Normalization of Polish Date Expressions</p>

The NLP date entity recognition module now accurately detects, validates, and normalizes complex Polish date expressions, including fully spelled-out dates, word-number combinations, and multiple date format permutations. Valid Polish date inputs are converted into a standardized format, and invalid or ambiguous entries are identified accordingly.

<p className="rn-title">Channels</p>

<p className="rn-subtitle">Email Session Creation Based on Subject</p>

The email channel now supports session creation based on the email subject. Admins can choose from the following options to manage how incoming emails are grouped into conversations: None, Thread-based sessions, or Subject-based sessions.

A normalized email subject is used to identify ongoing sessions, allowing replies with the same subject to remain in a single session even when email threading headers are unavailable or unreliable. [Learn more→](/ai-for-service/channels/add-email-channel#session-identity-and-grouping)

<p className="rn-title">App Settings</p>

<p className="rn-subtitle">Pre-processor Script for Custom Translation Engines</p>

A pre-processor script can now be configured for custom translation engines, dynamically transforming translation requests before they're sent to external providers. The script executes after the translation context is generated and before the API request is resolved, enabling language code mapping, payload customization, header updates, and variable creation for API calls. [Learn more→](/ai-for-service/app-settings/language-management/managing-translation-services#enable-custom-translation-engine)

<p className="rn-subtitle">Support Cross-Dialog Reuse of Redacted PII Entities</p>

Redacted Personally Identifiable Information (PII) entities can now be reused across dialogs within the same user session via the new `botUserSession.piiEntities` object. Developers can store tokenized values — such as email addresses, phone numbers, and account details — and reference them in downstream dialogs without prompting the user for the same information again. Using `piiEntities` maintains the platform's existing security posture. [Learn more→](/ai-for-service/app-settings/advanced-settings/pii-data-masking#reuse-sensitive-entities-across-dialogs)


<p className="rn-title">API</p>

<p className="rn-subtitle">Response Payload Encryption Support for Public APIs</p>

Enhanced response payload encryption by adding an optional `includeMeta` parameter that exposes pagination metadata, such as `moreAvailable` and `total`, outside the encrypted payload. [Learn more→](/ai-for-service/apis/automation/api-introduction#how-request-and-response-payload-encryption-works)

<p className="rn-subtitle">Debug Logs API Support for Webhook Channel</p>


The Debug Logs API now supports webhook (IVR) channel executions, enabling the retrieval of koreDebugger logs generated during webhook-based bot interactions. [Learn more→](/ai-for-service/apis/automation/fetch-debug-logs)

The retention period for attachments in user-bot conversations can now be configured independently in Advanced Settings, allowing organizations to manage file data separately from conversations. <p className="rn-title">Security & Control</p>


<p className="rn-subtitle">SSO Enhancements: Onboarding and Login Controls</p>


AI for Service supports both Identity Provider (IdP)-Initiated and Service Provider (SP)-Initiated SSO. In the IdP-initiated flow, authentication begins at the IdP, which sends a SAML response to the Platform for validation. In the SP-initiated flow, authentication begins at the Platform, which redirects the user for authentication before creating a session.

This enhancement adds the following capabilities:


* Restrict Auto-Onboarding: By default, new users are automatically onboarded during IdP-initiated login. When this toggle is enabled, automatic onboarding is disabled, keeping user provisioning fully controlled by your external system.
* Skip 2FA During First-Time Login: Administrators can now skip OTP-based authentication for first-time logins, providing flexibility to align the login experience with your organization's security policies especially where authentication is already enforced at the IdP level.

<p className="rn-title">Channels</p>


<p className="rn-subtitle">Email Channel Enhancements</p>



**DKIM Configuration**

DomainKeys Identified Mail (DKIM) is now available as a standalone module, allowing users to verify a domain independently before setting up an email channel and reuse it across multiple channels — eliminating repeated verification.


* Advanced Email Channels: DKIM verification is mandatory for the channel setup. The Platform checks for a verified DKIM record and requires completed verification before proceeding.

* Microsoft Exchange: DKIM signing is optional and off by default. Without it, the Platform sends emails through the Microsoft Graph API using Microsoft's native delivery. To enable DKIM signing, you must verify a DKIM record before completing the channel setup.

**Improved HTML Email Processing**

The Email channel now efficiently handles large HTML emails. Raw text is extracted for processing while the full HTML structure — including lists, hyperlinks, and text alignment — is preserved for accurate display in Agent Desktop.
