## v11.27.1 August 8, 2026

<Badge>Patch Release</Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">Agent Flow</p>

<p className="rn-subtitle">Configure LLM Timeout for DialogGPT</p>

Developers can now set the LLM response timeout for conversation orchestration models used by DialogGPT. The Timeout (seconds) setting accepts values from 1 to 60 seconds (default: 60 seconds). If the model doesn't respond within the configured timeout, the request fails and the task failure event is triggered. [Learn more→](/ai-for-service/automation/dialoggpt#model-configurations)
 

<p className="rn-subtitle">Allow Zero No-Input Retries in Voice Call Properties</p>

Voice flows can now skip no-input retries by setting No. of Retries to 0. The platform runs the configured timeout action immediately after the first no-input timeout, skipping the retry prompt and the second timeout wait. This reduces call delays and improves the caller experience. [Learn more→](/ai-for-service/automation/agent-flows#app-level-channel-settings)

Prompt nodes now support configurable timeout error handling. Choose whether a timed-out LLM request ends the task by triggering a Task Execution Failure Event or continues by transitioning to a fallback node. This enables graceful timeout recovery and improves timeout visibility in execution logs. By default, existing Prompt nodes close the task and trigger a Task Execution Failure Event on timeout, ensuring backward compatibility. <p className="rn-title">App Testing</p>

Docker Status now displays the Conversation Testing creation. When the Conversation Test suite creation process continues in the background, the Docker Status shows the test suite name, status icon, and timestamp. Each entry includes a View option that opens the corresponding test suite details for quick access to run results. [Learn more→](/ai-for-service/automation/testing/regression-testing/conversation-testing/test-case-execution-summary)

## v11.26.1 July 11, 2026

<Badge>Patch Release</Badge>

This update includes enhancements and bug fixes. The key enhancement included in this release is summarized below.

<p className="rn-title">Agent Flow</p>

<p className="rn-subtitle">Skip DialogGPT Intent Detection</p>


The Entity and Confirmation nodes now support the Skip Intent Detection option. When enabled, the runtime prioritises processing of entity/confirmation inputs and skips DialogGPT intent detection when the node uses Intent-over-Entity precedence. This reduces response latency and LLM token usage without affecting the conversation flow. The option is available per node and is disabled by default. [Learn more→](/ai-for-service/automation/dialogs/node-types/entity-node#component-properties)

<p className="rn-subtitle">Retry Configuration for Confirmation Node</p>


The Confirmation Node now supports built-in retry configuration. Developers can configure the number of retry attempts (default: 5) and define the action to take when the retry limit is reached, providing consistent retry handling across channels. For existing apps, current behavior is preserved by automatically assigning 5 allowed retries and End of Dialog as the default action when the retry limit is exceeded. [Learn more→](/ai-for-service/automation/dialogs/node-types/confirmation-nodes#instance-properties)

## v11.26.0 June 27, 2026

<Badge>Minor Release</Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">Agent Flow</p>

<p className="rn-subtitle">Prompt Node Supports Conversation History</p>


The Prompt Node now supports a configurable Conversation History Length at the node level. Up to 50 recent conversation messages (default: 5) can be included in prompts sent to the LLM, providing greater control over conversation context and prompt size. [Learn more→](/ai-for-service/automation/dialogs/node-types/genai-prompt#component-properties)


<p className="rn-subtitle">Content Variables: User Variant-Based Resolution</p>


Developers can now define variant-specific values within a single content variable, enabling multi-region and multi-segment deployments without duplicating variables or adding conditional flow logic.

For each language, developers can define labeled variants (en-us, en-gb, en-au, etc., or in any other format) and a mandatory default value. At runtime, the platform resolves the correct value by checking the new reserved session variable `context.session.BotUserSession.UserVariant`: if a case-sensitive match is found, the variant-specific value is returned; otherwise, the Default value for the active language is used.

Content variables without variants continue to resolve by language as before.

For example, content variable: support_number

- Default: +1-800-000-xxxx
- US: +1-800-111-xxxx
- UK: +44-800-222-xxxx
- AU: +61-800-333-xxxx

[Learn more→](/ai-for-service/app-settings/variables/using-bot-variables#user-variant-based-content-variables)

<p className="rn-subtitle">Enhanced Automation Node Timeout and Retry Settings</p>


A new link in the Automation node now takes users directly to the Timer tab to set timeouts. Updated description clarifies that these settings apply only while the system is identifying which dialog to trigger — once a dialog starts, its own timeout settings take over. [Learn more→](/ai-for-service/flows/node-types/automation#timer)

<p className="rn-title">Agent Transfer</p>

<p className="rn-subtitle">Manage Chat Transcript Links for Agent Transfers</p>

Developers can now control whether a chat transcript link is included in agent transfers, providing an additional layer of security for regulated industries. The Chat Transcript Link setting in the Agent Transfer node of the Welcome Flow is enabled by default and applies to all agent transfers from the app, including those initiated from Dialog Tasks. [Learn more→](/ai-for-service/flows/node-types/agent-transfer#general-settings)

## v11.24.0 April 25, 2026

<Badge>Minor Release</Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">Agent Flow</p>

<p className="rn-subtitle">Agent Node: Reduced Latency via Conditional DialogGPT Fallback</p>

The Agent Node now intelligently manages user input, bypassing DialogGPT by default during active execution. This shift from a dual-processing model to a single-call model optimizes the conversation flow for speed and efficiency.

* Significant Latency Reduction: By skipping the DialogGPT call for every user input, the Agent Node delivers much faster responses to the end user.
* Lower LLM Consumption Costs: Reducing a model's calls directly lowers your token usage and operational overhead.
* Intelligent Topic Switching: The Agent Node handles the conversation independently until it detects an "interruption" (a change in user intent). DialogGPT is then triggered as a fallback to determine the next best action.

<Note>This feature applies to custom V2 streaming and non-streaming prompts.</Note>

[Learn more→](/ai-for-service/automation/agent-node#agent-interruption-detection)


<p className="rn-subtitle">Context-Aware Custom Prompts for GenAI Features</p>

The context object is now supported in pre-processor and post-processor scripts for DialogGPT, Answer Generation, Zero Shot Model, and Rephrase User Query features using custom prompts, independent of the underlying model.


<p className="rn-subtitle">Entity and Confirmation Nodes – Follow-up Intent Control</p>

Previously, when 'Entity over Intent' was enabled, the system automatically added the detected intent to the 'Follow-up Intents' array, with no option to prevent this. To give developers more control, a new 'Add intent to Follow-up Intents' option has been introduced, allowing them to choose whether the detected intent is queued or discarded. [Learn more→](/ai-for-service/automation/dialogs/node-types/entity-node#advanced-controls)


<p className="rn-subtitle">Agent Transfer Node – Extended Post-agent Conversation Behavior</p>

Post-agent conversation behavior has been extended to include Salesforce MIAW and ServiceNow integrations, in addition to the existing Genesys Agent Desktop. This feature allows developers to automatically initiate a predefined dialog flow after an agent conversation ends. This enables customers to capture valuable user feedback post-agent conversations. [Learn more→](/ai-for-service/flows/node-types/agent-transfer#general-settings)

<p className="rn-subtitle">Automation Node-Retry Action Handling</p>

When retries are exhausted on Automation nodes using user-input-based execution, the system now executes the configured Action After Exceeding Retries instead of defaulting to call termination. Existing timeout, wait time, and retry behavior are preserved. If no action is configured, the system plays a default message and disconnects the call.

<p className="rn-title">Agent Transfer</p>

<p className="rn-subtitle">Genesys Session Closure on User Exit in Genesys</p>

During an active Genesys agent conversation, closing the Web SDK session now automatically ends the corresponding agent session and notifies the agent. [Learn more→](/ai-for-service/integrations/agents/agent-transfer-integrations#conversation-end-message)

## v11.21.0 January 17, 2026

<Badge>Minor Release</Badge>

This update includes enhancements and bug fixes. The key enhancements included in this release are summarized below.

<p className="rn-title">DialogGPT</p> 

<p className="rn-subtitle">Multiple Intent Descriptions</p>

DialogGPT now allows users to add multiple descriptions for each intent, giving the flexibility to define various phrasings, perspectives, and explanations. This enhancement helps users achieve broader semantic coverage and significantly improves the accuracy of intent shortlisting and detection—especially valuable when working with broad, overlapping, or domain-specific intents. 


<p className="rn-title">Agent Node</p> 

<p className="rn-subtitle">Ability to Render Rich UI Components from LLM Responses</p>

The Agent Node can now pass structured JSON responses from the LLM to client channels for rich UI presentation. When users enable the "Parse Rich Templates" option in custom prompt settings (available for V1 and V2 prompts), the node passes the JSON payloads as structured responses to the Platform, which then sends them as templates to client channels. This can be achieved by either prompting the model to generate responses in structured JSON format or by generating the templates in the prompt post-processor. The Node passes these JSON payloads as structured responses to the Platform, which then sends them as templates to client channels. The client channels render these templates as supported UI components such as cards, lists, tables, and suggestion chips, enabling visually engaging information display beyond plain text. 


<p className="rn-title">Security (API Scopes)</p> 

<p className="rn-subtitle">End-to-End Request and Response Payload Encryption for APIs</p>

Payload encryption support has been extended to request payloads for selected APIs, in addition to the existing response payload encryption. The "Enforce Request and Response Payload Encryption" option (renamed from "Enforce Response Payload Encryption") now encrypts both request and response payloads. When enabled, the system generates a key to encrypt payloads in both directions, ensuring full end-to-end data protection for APIs within the JWT application's assigned scope. 


<p className="rn-title">Flows & Channels</p>

<p className="rn-subtitle">Enhanced Response Structure for the Get Linked Apps API</p>


The Get Linked Apps API has been enhanced with a revised response structure to retrieve all linked applications associated with a universal or parent app.




<p className="rn-title">Agent Transfer</p>

<p className="rn-subtitle">Read Receipts for WhatsApp Cloud API Integration</p>

The Platform now supports WhatsApp Cloud API read receipts, allowing end users to see message status indicators (delivered and read) across both bot and agent conversations. This feature is automatically available for all existing and new WhatsApp Cloud API integrations. 

<p className="rn-subtitle">Availability of Salesforce MIAW Conversation ID</p>

The Platform now exposes the Salesforce MIAW Conversation ID in the bot user context during agent transfer. This enables Message, Script, and Call Flow nodes, as well as external integrations, to access the active MIAW conversation identifier at runtime for tracking, correlation, and conditional logic. 



<p className="rn-title">NLU Config</p>

<p className="rn-subtitle">BGE M3 Embeddings Support</p>

The Platform now supports BGE M3 Embeddings as an additional option for Knowledge Graph, Machine Learning, and Few-Shot NLP use cases across all languages.

Users can select BGE M3 alongside existing options (MPNet and LaBSE) to enhance multilingual performance and improve retrieval accuracy.
