Set up the Azure Blob Storage connector to import conversation recordings, transcripts, and metadata from Azure Blob Storage into Quality AI Express. The Connector imports conversation recordings, transcripts, and metadata from Microsoft Azure Blob Storage into Quality AI Express on a configurable schedule. This also supports voice and chat interactions from third-party CCaaS platforms and processes data on a configurable schedule.

## Prerequisites

### Azure Storage Requirements

| Requirement | Description |
|---|---|
| **Storage Account** | Azure Storage account with Blob access subscription. |
| **Authentication** | Service Principal (Recommended) or Connection String. |
| **Container** | Azure Blob container with conversation files. |
| **Supported File Types** | WAV, MP3, JSON, CSV. |
| **Maximum File Size** | 50 MB per file. |
| **Timestamp Format** | ISO 8601 UTC (`YYYY-MM-DDTHH:MM:SSZ`). |
| **File Accessibility** | Audio files must be reachable over HTTPS. |
| **Test File** | A `test.csv` file in each configured ingestion folder. |

### Platform Requirements

| Requirement | Description |
|---|---|
| **Quality AI Express** | Connector feature enabled in platform settings. |
| **Agent Setup** | Agents configured with valid email addresses matching platform accounts. |
| **Queue Setup** | Quality AI queues configured and available for mapping. |
| **Permissions** | Access to Connectors configuration or Integrations and Extensions. |

### Service Principal Permissions

Service Principal authentication requires the following Azure role assignment.

| Role | Scope | Purpose |
|---|---|---|
| **Storage Blob Data Reader** | Storage Account | Read and list blobs. |

Assign this role at the storage account level, not just at the container level.

Navigate to: **Storage Account** > **Access Control (IAM)** > **Add role assignment**.

Avoid assigning broader permissions such as Contributor or Owner.

## Authentication Methods

The connector supports two authentication methods.

### Service Principal (Recommended)

Service Principal provides identity-based authentication using an Azure App Registration.

The following credentials are required:

- Tenant ID
- Client ID
- Client Secret
- Storage Account Name

The App Registration must have the `Storage Blob Data Reader` role assigned to the storage account.

### Connection String

The connector authenticates with Azure Blob Storage using a connection string.

To obtain the connection string:

1. Open the Azure portal.
1. Navigate to **Storage Account**.
1. Select the required storage account.
1. Go to **Security + Networking** > **Access Keys**.
1. Copy the **Connection String** for **Key1** or **Key2**.
1. Use the connection string while configuring the connector.

Example format:

`DefaultEndpointsProtocol=https;AccountName=...;AccountKey=...;EndpointSuffix=core.windows.net`

<Note>The fields displayed in the connector vary depending on the selected **Auth Type**.</Note>

## Supported Data Types

The connector supports stereo voice, mono voice, voice transcripts, and chat transcripts.

| Data Type            | Format   | Files per Conversation | Analytics                               | Channel Assignment                                                                |
| -------------------- | -------- | ---------------------- | --------------------------------------- | -------------------------------------------------------------------- |
| **Stereo Voice**     | WAV, MP3 | 1                      | Complete Analytics, Enhanced Analytics  | Single dual-channel recording (Left = Agent, Right = Customer).                    |
| **Mono Voice**       | WAV, MP3 | 2                      | Complete Analytics, Enhanced Analytics  | Separate agent and customer recordings. Mixed audio isn't supported. |
| **Voice Transcript** | JSON     | 1                      | Text Analytics, Complete Text Analytics | Pre-transcribed voice conversation.                                  |
| **Chat Transcript**  | JSON     | 1                      | Text Analytics, Complete Text Analytics | Message-level chat transcript.                                       |

### Stereo Voice

A stereo recording contains both agent and customer audio in a single dual-channel recording.

- **Left channel**: Agent.
- **Right channel**: Customer.
- One audio file per conversation.

Channel assignments must be represented correctly in the CSV metadata using `agentChannel` and `customerChannel`.

### Mono Voice
Mono conversations require two separate audio files:

- **Agent recording**
- **Customer recording**

Example:

- `conv-123456-agent.wav`
- `conv-123456-customer.wav`

A single mixed mono recording isn't supported.

Each mono conversation must have two CSV rows sharing the same `conversationId`.

### Voice Transcripts

Voice transcripts allow importing previously transcribed voice conversations without reprocessing the original audio.

- Format: JSON.
- One transcript file per conversation.
- `recordingType = transcription`.
- `channelType = voice`.

### Chat Transcripts

Chat transcripts support conversations from platforms such as:

- Web Chat, WhatsApp, Facebook Messenger, and other supported messaging platforms.
- Format: JSON.
- One transcript file per conversation.
- `recordingType = transcription`.
- `channelType = chat`.

## CSV Metadata Formats

This section defines the required CSV metadata fields for each supported conversation type.

Core fields are shared across conversation types, while recording-specific fields differ.

### Stereo Voice

- `recordingType = stereo`
- `channelType = voice`

| Field | Required | Type | Description |
|-------|----------|------|-------------|
| `conversationId` | Yes | String | Unique conversation identifier, maximum 50 characters. |
| `agentEmail` | Yes | String | Must match a platform user account. |
| `conversationStartTime` | Yes | String | ISO 8601 UTC timestamp. |
| `conversationEndTime` | Yes | String | ISO 8601 UTC timestamp; must be after start time. |
| `channelType` | Yes | String | Always `voice`. |
| `recordingType` | Yes | String | Always `stereo`. |
| `chatScriptUrl` | Yes* | String | Full HTTPS URL to the JSON transcript. |
| `recordingUrl` | Yes | String | HTTPS URL to the audio recording. |
| `transcriptUrl` | Yes* | String | Full HTTPS URL to the JSON transcript. |
| `queueId` | Yes | String | Must exist in queue mapping. |
| `agentChannel` | Yes | Integer | Agent channel: `0` or `1`. |
| `customerChannel` | Yes | Integer | Customer channel: `0` or `1`. |
| `language` | No | String | ISO 639-1 language code. Defaults to `en`. |
| `asprovider` | No | String | Audio service provider. |

Confirm whether both `chatScriptUrl` and `transcriptUrl` are required for stereo recordings in the deployed connector version.

### Mono Voice

- `recordingType = mono`
- `channelType = voice`

Each conversation requires two CSV rows and two audio files. Both rows must share the same `conversationId`.

| Field | Required | Type | Description |

| `customerRecordings` | Yes | String | URL to the customer audio file. |

Example:

### Agent and Queue Validation

Additional processing rules for agent and queue onboarding.

| Agent Onboarded | Queue Onboarded | Processing Result |
|----------------|----------------|------------------|
| No | Yes | Conversation is processed. |
| Yes | Yes | Conversation is processed, even if the agent isn't mapped to the queue. |
| Any | No | Conversation is rejected. |

For transferred conversations:

- Use the queue where the conversation ended.
- Use the email address of the agent who closed the conversation.

## JSON Transcript Schemas

Detailed JSON transcript structure and mandatory fields.

### Voice Transcript

The root JSON object contains a `recognizedPhrases` array.

Each phrase can include:

- `recognitionStatus`
- `channel`
- `offset`
- `duration`
- `offsetInTicks`
- `durationInTicks`
- `durationMilliseconds`
- `offsetMilliseconds`
- `nBest`
- `words`

Each `nBest` alternative can include:

- `confidence`
- `lexical`
- `itn`
- `maskedITN`
- `display`
- `words`

Each word can include:

- `word`
- `offset`
- `duration`
- `offsetInTicks`
- `durationInTicks`
- `durationMilliseconds`
- `offsetMilliseconds`
- `confidence`
- `Required fields`

| JSON Level | Required Fields |
|------------|----------------|
| `Phrase` | `channel`, `offsetInTicks`, `nBest` |
| `nBest` | `lexical`, `words` |
| `Words` | `word`, `offsetInTicks`, `durationInTicks`, `confidence` |

### Chat Transcript

The root JSON object contains messages identified by numeric keys (for example, 1, 2, 3).

Each message requires the following fields:

| Field | Values | Description |
|-------|--------|-------------|
| `type` | `AGENT`, `USER`, `SYSTEM` | Identifies the speaker. |
| `text` | String | Message content. |
| `timestamp` | Unix time in milliseconds | Message timestamp. |
| `userId` | String | Agent email or customer ID. |

## Storage Structure Options

Choose a folder structure for your Azure Blob container before setting up the connector.

**Option A: Unified Path**

```text
container/
├── metadata.csv
├── audio/
│   ├── conv-123456.wav
│   ├── conv-123457-agent.wav
│   └── conv-123457-customer.wav
├── chat/
│   └── chat-123459.json
└── test.csv
```

**Option B: Separate Voice and Chat Paths**

```text
container/
├── voice/
│   ├── metadata.csv
│   ├── recordings/
│   └── test.csv
└── chat/
    ├── metadata.csv
    ├── transcripts/
    └── test.csv
```
**Azure Blob path format:**

`azure://your-container/your-folder/`

Important requirements:

- File and folder names must not contain spaces or special characters.
- Each configured ingestion path must contain a `test.csv` file.
- Metadata CSV files must contain the required headers.
- Mono recordings must have separate agent and customer files.
- All referenced files must be accessible to the connector.

## Set Up the Connector

Before you begin, verify that your Blob container is ready:

- Upload all required files to Azure Blob Storage.
- Metadata `.csv` files contain required fields and valid values.
- Mono conversations have separate agent and customer files.
- The container and folder paths are available.
- A `test.csv` file exists in each ingestion path.
- Blob permissions enable the connector to access the files.

<Note> File and folder names shouldn't contain any spaces or special characters.</Note>

### Step 1: Create the Connector

1. Navigate to **Quality AI** > **Configure** > **Connectors**.
1. Select **+ Add Connector** > **Azure Blob Storage** > **Connect**.
1. Enter a **Name** for the connector.
1. Select the **Azure Region** for the storage account.
1. Set **Authentication Type** to **Connection String**.
1. Enter the **Connection String** from your Azure Storage account.
1. Configure the storage paths:
   - **Unified Path**: Enter a single Blob path for both voice and chat data.
   - **Separate Paths**: Enter a **Voice Path** and a **Chat Path**.

### Step 2: Test the Connection

1. Select the **Test** tab.
1. Select **Test** to run the validation checks.
1. Verify that the following checks pass: **Authentication**, **File Path Access**, **File Format Validation**, and **Metadata Validation**.

### Step 3: Map Queues

1. Select the **Queue** tab.
1. Map each `queueId` from the `.csv` files to a **Quality AI Express** queue. Values must match exactly.
1. Select **Save**.

<Note>Every queue ID in the metadata file must map to an existing Quality AI Express queue before ingestion can run. Evaluation forms linked to mapped queues determine how interactions are evaluated.</Note>

### Step 4: Configure the Schedule

1. Select the **Schedule** tab.
1. Set the **Interval Type**, **Start Date**, **Repeat Every**, and **Start Time** (UTC).
1. Select **Save** to activate the schedule.

After saving, verify the setup is complete:

- Verify that the system saved and validated the queue mappings.
- Verify that the processing schedule is active.
- Verify that the first ingestion job appears in the Log tab.
- Verify that the system reports no processing errors.

The setup is complete when all conversations appear in **Quality AI Express** dashboards and analytics data is available for ingested interactions.

### Step 5: Monitor Ingestion Jobs

Use the **Log** tab to monitor ingestion activity.

| Column | Description |
|---|---|
| **Start Time** | Job start time. |
| **Finish Time** | Job completion time. |
| **Uploaded** | Number of uploaded files. |
| **Processing** | Number of processed files. |
| **Job Status** | Current processing status. |
| **View Details** | Opens job details. |

Ingestion is successful when the uploaded and processed file counts match, the job shows as completed, and no errors appear in the job details.

## Troubleshooting

### Authentication Issues

| Problem | Symptom | Resolution |
|---|---|---|
| **Authentication Failed** | Authentication error. | Verify the account key, connection string, and storage account name. Re-copy the credentials from the Azure portal and test again. |
| **Authorization Header Error** | Request rejected. | Generate a new access key and update the connector configuration. |

### Storage Access Issues

| Problem | Symptom | Resolution |
|---|---|---|
| **Container Not Found** | Container or path not found. | Verify the container name and folder structure. |
| **File Not Available** | Blob access denied. | Verify blob access permissions and storage access settings. |

### File Validation Issues

| Problem | Symptom | Resolution |
|---|---|---|
| **File Format Validation Error** | Unsupported or invalid file format. | Verify the CSV metadata structure and required headers. |
| **Metadata Validation Error** | Missing or invalid metadata. | Verify required metadata fields and timestamp values. |

### Data Processing Issues

| Problem | Symptom | Resolution |
|---|---|---|
| **Timestamp Validation Error** | Invalid timestamp format. | Use ISO 8601 UTC format (`YYYY-MM-DDTHH:MM:SSZ`). |
| **Queue Mapping Error** | Queue IDs not mapped. | Map all queue IDs before running ingestion. |

### Performance Considerations

Processing time depends on file size, conversation duration, audio duration, transcription latency, LLM processing time, AI analysis complexity, and number of conversations being ingested.
