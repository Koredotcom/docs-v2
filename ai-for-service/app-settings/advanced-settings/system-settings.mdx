## Overview

System Settings allow administrators to configure key platform features that control call handling, data management, and system behavior. From this section, administrators can manage Call Recording Control, configure whether calls are answered on the first Bot or AI Agent response, and set the Data Retention Period for stored information. These settings ensure consistent system operation, compliance with policies, and efficient handling of conversations.

Navigate to **Automation AI > App Settings > Advanced Settings > System Settings** to access and configure these functionalities.

![System Settings Page](/ai-for-service/app-settings/advanced-settings/images/system-settings.png)

## Call Recording Control

By default, Contact Center AI records all voice interactions. Administrators can disable call recording for all voice interactions.

### Steps to disable Call Recording Control

1. Click **Call Recording Control**.

   ![Call Recording Control](/ai-for-service/app-settings/advanced-settings/images/call-recording-control-option.png)

2. Turn off the toggle to disable call recording for all voice interactions.

   ![Call Recording Control Disabled](/ai-for-service/app-settings/advanced-settings/images/call-recording-control.png)

## Screen Recording Control

If enabled, agent screens are automatically recorded during inbound or outbound call interactions. [Learn more](/ai-for-service/contact-center/agent-console#screen-recording-for-voice-calls).

Steps to enable Screen Recording Control:

1. Select **Screen Recording Control**.

   ![Screen Recording Control](/ai-for-service/app-settings/advanced-settings/images/screen-recording-control.png)

2. Turn on the toggle to enable screen recording for all voice interactions.

## Video Call Recording Control

Video Call Recording settings control whether agent-user video calls are recorded, when recording begins, and how customer consent is handled. [Learn more](/ai-for-service/contact-center/agent-console#video-call-recording).

Steps to configure Video Call Recording:

1. Turn on **Enable Video Call Recording**.

2. Select a **Recording Start** option.

3. Select a **Recording Consent** option.

4. (Optional) Turn on the **Allow Agents to Pause/Resume Video Call recording** toggle to let them pause or resume the recording.

   ![Video Call Recording](/ai-for-service/app-settings/advanced-settings/images/video-call-recording-configuration.png)

The configured Recording Start and Recording Consent options work together as follows: 

| Recording Start | Recording Consent | What happens |
|:---------------------|:------------------------|:------------------|
| Manual | Display Consent Prompt | Agent selects **Start Recording** → Customer receives a consent prompt → If accepted, recording begins. If declined, the **Start Recording** option remains available for the agent to try again later. |
| Manual | Consent Managed Externally | Agent selects **Start Recording** → Recording starts. |
| Automatic | Display Consent Prompt | When the call connects, the consent prompt displays. If accepted, recording starts automatically. If declined, the **Start Recording** option displays to the agent for later use. |
| Automatic | Consent Managed Externally | When the call connects, recording starts. If consent is declined, recording is not initiated and the **Start Recording** option displays to the agent for later use. |

## Answer Call on First Bot/AI Agent Response

This feature plays a dial tone to the caller if there is a delay before the AI Agent delivers its first response on inbound calls. This improves the caller experience by indicating the call is still connected, preventing confusion or the impression of a dropped call. Administrators can enable or disable this behavior using a configuration flag.

### Steps to enable Answer Call on First Bot/AI Agent Response

1. Click **Answer Call on First Bot Response**.

   ![Answer Call on AI Agent Response](/ai-for-service/app-settings/advanced-settings/images/answer-call-option.png)

2. Turn on the toggle to enable the functionality.

   ![Answer Call Enabled](/ai-for-service/app-settings/advanced-settings/images/answer-call-bot-response.png)

When calls transfer from an existing telephony provider to the platform, a connection event triggers once the call connects and the bot begins responding. In rare cases, the AI Agent's response may be delayed due to processing or latency. This setting sends the connection event only when the AI Agent's first response plays, and plays a dial tone in the meantime to keep callers engaged.

## Maximum Bot Call Duration

The Maximum bot call duration setting limits the duration of a user-bot voice conversation. When the configured duration expires, the system plays the configured expiry message and ends the call gracefully.

The setting applies to inbound and outbound calls. The timer stops when a transfer to a human agent is initiated.

The setting includes the following options:

| Setting                        | Description                                                                                                                                                                                                                                                          |
| :----------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Maximum bot call duration      | Turns on or turns off the maximum duration timer for user-bot voice conversations.                                                                                                                                                                                   |
| Maximum duration               | Specifies the maximum duration of a user-bot voice conversation in seconds. The allowed range is 60 to 43,200 seconds. The default value is 7,200 seconds (2 hours). Only integer values are permitted.                                                              |
| Expiry Message (Optional)      | Specifies the message that the system plays to the caller when the maximum bot call duration is reached. The default message is: `This call has reached the maximum allowed duration and will now end. Thank you.`                                                    |

Steps to configure the maximum bot call duration:

1. Turn on the **Maximum Bot Call Duration** toggle.
2. Enter the Maximum Duration in seconds. Only whole numbers are accepted.
3. Enter the Expiry Message (optional) — the message played to the caller when the maximum duration is reached, before the call ends.
4. Select **Save** and publish the configuration.

   ![Maximum Bot Call Duration](/ai-for-service/app-settings/advanced-settings/images/maximum-bot-call-duration.png)

   Configuration changes take effect from the next call onwards. Active bot calls aren't affected by changes made after they begin.

   **Timer behavior**

   The maximum bot call duration timer follows these rules:

   * The timer starts when the Session New event triggers and the bot begins interacting with the caller.
   * When the timer expires, the system plays the configured expiry message completely and then ends the call.
   * If the caller hangs up while the expiry message is playing, the system retains the Smart Status, Reason, Mode, and Status associated with the maximum call duration timer. The Disconnecting Event is recorded as User Hangup.
   * The timer applies to both inbound and outbound calls.
   * The timer stops when a transfer to a human agent is initiated, including while the transfer is pending, queued, or in progress.

   **Returning from a human agent to a bot**

   When a human agent transfers the caller back to a bot:

   * The previous bot timer remains closed.
   * The returned bot interaction uses a new, independent timer.
   * The new timer starts when the new bot media session connects.
   * The new timer doesn't include the duration of the previous bot interaction or the human-agent interaction.
   * A single timer that spans multiple bot and human-agent segments isn't supported.

**Default configuration**

The default configuration depends on whether the app is new or existing:

| App Type      | Timer    | Maximum Duration | Action                    |
| :------------ | :------- | :--------------- | :------------------------ |
| New apps      | Turned on  | 2 hours          | End the call gracefully.  |
| Existing apps | Turned off | Not applicable   | Not applicable            |

<Note>
- App Owners and App Administrators with permission to edit Advanced Settings can modify, save, and publish the setting. View-only users can view the configuration but cannot modify, save, or publish changes.
- The maximum bot call duration applies only to user-bot voice conversations.
</Note>

## Data Retention Period

Use the **Data Retention Period** feature to configure how long voice call recordings are retained. Select a retention period from 1 day to 7 years. New applications use a default retention period of 3 months, which administrators can change. Enable email notifications before recording deletion. Email notifications are unavailable when the retention period is less than 1 month. Administrators must acknowledge recording deletion before the system deletes recordings. The system records retention setting changes, email preference updates, and successful and failed recording deletions in the audit logs. Only **App Owners** and **Supervisors** can modify these settings.

### Attachment Retention Period

The Attachment Retention Period feature allows administrators to configure a separate retention period for attachments in user-bot conversations. The attachment retention period must always be shorter than the conversation retention period, allowing attachments to be deleted earlier if required. All changes to attachment retention settings are recorded in audit logs for traceability and compliance. Only App Owners can modify these settings. 

### Steps to configure the Data Retention Period

1. Click **Data Retention Period**.

   ![Data Retention Period](/ai-for-service/app-settings/advanced-settings/images/data-retention-period-option.png)

2. Select the required retention duration for voice call recordings and voice automation session recordings.

3. Optionally, select the checkbox to enable email notifications 5 days before deletion of voice call recordings. Email notifications are available only for retention periods greater than 30 days.

4. Select the required retention period for attachments in user-bot conversations. The retention period can be configured in days, months, or years, up to a maximum of 7 years. However, the configured value can't exceed the conversation retention period set at the workspace level. 

   ![Define Data Retention Period](/ai-for-service/app-settings/advanced-settings/images/define-data-retention-period.png)

5. Select **Save** to apply the changes.

## Conversation Time Display Format

Choose how time appears in call recording transcripts. The system displays either actual timestamps or elapsed duration from the start of the call. [Learn More](/ai-for-service/analytics/overview/conversations#conversation-time-display-format)

### Steps to configure Time Display Format

1. Open **Conversation Time Display Format**.
2. Select **Standard Timestamps** or **Duration Markers**.
3. Select **Save**.
   ![Configure Time Display Format](/ai-for-service/app-settings/advanced-settings/images/conversation-time-display-format.png)
