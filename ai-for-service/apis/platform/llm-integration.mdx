Use the LLM Integration API to enable, update, and delete LLM Integrations for an app. You can configure System LLMs (Azure OpenAI, OpenAI, Anthropic, Amazon Bedrock, and Google Gemini), Custom LLMs, and Kore.ai XO GPT integrations through the API.

| Field | Value |
|---|---|
| **Method** | `PUT` – Enables a new LLM Integration or updates an existing configuration.<br />`DELETE` – Deletes an existing LLM Integration configuration. |
| **Endpoint** | `https://{{host}}/api/public/stream/{{streamId}}/llmIntegration/` |
| **Content Type** | `application/json` |
| **Authorization** | `auth: {{JWT}}` See [How to generate the JWT Token](/ai-for-service/apis/automation/api-introduction#generating-the-jwt-token). |
| **API Scope** | Bot Builder: LLM Integration (Automation AI) |

**The API supports:**

- System LLM integrations: OpenAI, Azure OpenAI, Anthropic, Gemini, Amazon Bedrock, and Kore.ai XO GPT.
- Custom LLM integrations.
- Token usage limits and usage notifications.
- Partial updates for existing integrations.
- Deletion of configured integrations.

### Path Parameters

| Parameter | Required | Description |
|---|---|---|
| `botId/streamId` | Required | App ID or Bot ID. Access it via **App Settings** → **App Profile**. |

### Body Parameters

For `PUT`, use the following parameters to configure or update an LLM Integration.

| Parameter | Required | Type | Description |
|---|---|---|---|
| `integrationId` | Required | String | Identifier of the LLM Integration. Supported values are `korexo`, `openai`, `azure`, `anthropic`, `gemini`, `amazon_bedrock`, and `custom_llm`. |
| `integrationName` | Conditional | String | Name of the LLM Integration. |
| `apiKey` | Conditional | String | API key for the LLM provider. |
| `previousName` | Conditional | String | To edit the existing multi-instance integration name. |

For `DELETE`, use the following parameters to delete an LLM Integration configuration.

| Parameter | Required | Type | Description |
|---|---|---|---|
| `integrationId` | Required | String | Identifier of the LLM Integration to delete. Supported values are `korexo`, `openai`, `azure`, `anthropic`, `gemini`, `amazon_bedrock`, and `custom_llm`. |
| `integrationName` | Conditional | String | Required only for OpenAI, Azure, Bedrock, and Custom LLM. |

### Sample Request for PUT

- In `dynamicModelConfig`, `name`, and `desc` shouldn't be passed for system models.
- To edit the name of an existing multi-instance integration (OpenAI, Azure OpenAI, Bedrock, Custom LLMs), pass the previous name as `previousName`, and the latest name as `integrationName`.

```bash expandable=true
curl --location --request PUT 'https://{{host}}/api/public/stream/{{streamId}}/llmIntegration/' \
--header 'auth: {{jwt-token}}' \
--header 'bot-language: {{language-code}}' \
--header 'Content-Type: application/json' \
--data-raw '{
  "integrationId": "openai",
  "integrationName": "newOpenAiIntegration",
  "apiKey": "<apiKey>",
  "previousName": "originalPreviousName",
  "dynamicModelConfig": [
    {
      "type": "custom",
      "name": "<modelName>",
      "modelId": "<modelId>",
      "desc": "<description>",
      "deploymentId": "<deploymentId>"
    }
  ],
  "tokenUsageConfig": {
    "isUsageLimitsConfigured": true,
    "usageNotifications": {
      "isUsageNotificationsEnabled": true,
      "percentageToNotify": 50,
      "mailIds": [
        "<mailIds>"
      ]
    },
    "tokenUsageMetrics": {
      "startDate": "2026-09-30T18:30:00.000Z",
      "maxTokens": 10000,
      "duration": 26,
      "cycleStartDate": "2026-09-30T18:30:00.000Z",
      "cycleEndDate": "2026-10-20T18:30:00.000Z"
    }
  }
}'
```

### Sample Request for DELETE

- Only `integrationId` is required for `korexo`, `gemini`, and `anthropic` integrations.

```bash expandable=true
curl --location --request DELETE 'https://{{host}}/api/public/stream/{{streamId}}/llmIntegration/' \
--header 'auth: {{jwt-token}}' \
--header 'bot-language: {{language-code}}' \
--header 'Content-Type: application/json' \
--data-raw '{
  "integrationId": "openai",
  "integrationName": "newOpenAiIntegration"
}'
```

### Enabling Token Usage

- Use the following sample token usage payload to enable token usage.

```json expandable=true
"tokenUsageConfig": {
  "isUsageLimitsConfigured": true,
  "usageNotifications": {
    "isUsageNotificationsEnabled": true,
    "percentageToNotify": 50,
    "mailIds": [
      "<mailId>"
    ]
  },
  "tokenUsageMetrics": {
    "startDate": "2026-09-30T18:30:00.000Z",
    "maxTokens": 10000,
    "duration": 20,
    "cycleStartDate": "2026-09-30T18:30:00.000Z",
    "cycleEndDate": "2026-10-20T18:30:00.000Z"
  }
}
```

- If you don't want to enable token usage, use the following payload.

```json
"tokenUsageConfig": {
  "isUsageLimitsConfigured": false
}
```

### Request Body Examples

**OpenAI**

- Use `openai` as the `integrationId`.
- In OpenAI, `dynamicModelConfig` is only for custom models.
- To enable custom models in OpenAI, the following fields are mandatory for first-time creation: `type`, `name`, `modelId`, `desc`.
- To edit the existing integration name, you need to pass `previousName`.

```json
{
  "integrationId": "openai",
  "integrationName": "newOpenAiIntegration-edited",
  "previousName": "newOpenAiIntegration",
  "apiKey": "<apiKey>",
  "dynamicModelConfig": [
    {
      "type": "custom",
      "name": "<modelName>",
      "modelId": "<modelId>",
      "desc": "<description>"
    }
  ],
  "tokenUsageConfig": {
    "isUsageLimitsConfigured": false
  }
}
```

**Azure OpenAI**

- Use `azure` as the `integrationId`.
- To enable system and custom models in Azure OpenAI, use `dynamicModelConfig`.
- `dynamicModelConfig` is mandatory when enabling Azure OpenAI for the first time.
- You can save the config only when at least one of the models is enabled (`toggle: true`).
- In the payload, the `tenant` is a subdomain.
- To enable custom models in Azure OpenAI, the following fields are mandatory for first-time creation: `type`, `name`, `modelId`, `desc`, `toggle`, `deploymentId`.
- To enable system models in Azure OpenAI, the following fields are mandatory for first-time creation: `type`, `modelId`, `toggle`, `deploymentId`.
- The following are the supported system model IDs for Azure OpenAI integration:
    
    - GPT-3.5 Turbo
    - GPT-4
    - GPT-4-32K
    - GPT-4 Turbo
    - GPT-4o
    - GPT-4o-mini
    - GPT-5.4
    - GPT-5-mini
    - GPT-5.1
    - GPT-5.2
    - GPT-5.4 Mini
    - GPT-5.4 Nano



```json expandable=true
{
  "integrationId": "azure",
  "integrationName": "newAzureOpenAiIntegration",
  "apiKey": "<apiKey>",
  "tenant": "<tenant>",
  "dynamicModelConfig": [
    {
      "type": "system",
      "modelId": "<modelId>",
      "toggle": true,
      "deploymentId": "<deploymentId>"
    },
    {
      "type": "custom",
      "name": "<modelName>",
      "modelId": "<modelId>",
      "desc": "<description>",
      "toggle": true,
      "deploymentId": "<deploymentId>"
    }
  ],
  "tokenUsageConfig": {
    "isUsageLimitsConfigured": false
  }
}
```

- To enable system and custom models in Anthropic, use `dynamicModelConfig`.
- `dynamicModelConfig` is mandatory when enabling Anthropic for the first time.
- To enable custom models in Anthropic, the following fields are mandatory for first-time creation: `type`, `name`, `modelId`, `desc`, `toggle`.
- To enable system models in Anthropic, the following fields are mandatory for first-time creation: `type`, `modelId`, `toggle`.
- The following are the supported system model IDs for Anthropic integration:
    
    - Claude Haiku 4.5
    - Claude Opus 4.6
    - Claude Sonnet 4.5
    - Claude Sonnet 4.6


```json
{

```

**Kore.ai XO GPT**

- Use `korexo` as the `integrationId`.
- Use the following flags to enable the respective models:
    - `textrephrase` – Text Rephrasing
    - `conversationsummary` – Summarizing Conversation
    - `aa_conversationsummary` – Summarizing AgentAI Conversation
    - `vectorGeneration` – Embeddings
    - `dialogGPT` – DialogGPT
    - `answerGeneration` – Answer Generation

```json
{
  "integrationId": "korexo",
  "textrephrase": true,
  "conversationsummary": true,
  "aa_conversationsummary": true,
  "vectorGeneration": true,
  "dialogGPT": true,
  "answerGeneration": true
}
```
