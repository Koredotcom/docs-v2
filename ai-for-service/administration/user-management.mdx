## Users

To manage users in your enterprise network navigate to **User Management > **Admin Console** > **Users**.

![User Management Module](/ai-for-service/administration/images/manage-users-new-admin-console.png)

The following list provides the columns details displayed for each user.

| Column | Description |
|--------|-------------|
| Name | Displays the username and selection box. |
| Email Id | Displays the registered email ID of the user. |
| Account Role | Displays the role of the user. |
| Status | Displays the user status. <br />• **Active**: The user is active and can interact with other Kore.ai users. <br />• **Inactive**: Users invited by the admin but have yet to join or accept the invitation. <br />• **Locked**: The user exceeded the maximum number of login attempts. The status of a locked user can be activated.|

Select the specific user row to view the **User Details** page to modify:

* **[User Profile](#profile)**
* **[Sessions/Devices](#sessionsdevices)**
* **[Manage Product Access](#manage-product-access)**

### Profile

Modify the user profile information of a specific user in your account, for example, to update their address or title.

![User Profile](/ai-for-service/administration/images/edit-user-new-admin-console.png)

You can access the following fields on this page:

* **Groups**: Select the group from the dropdown. [Refer here for more on Managing Groups](/ai-for-service/administration/groups-management).
* **Admin Role**: Select the admin role from the dropdown.
* **Product & App Creation Access**: Enable the toggles for **Builder Portal Access**, **App Creation Access**, and **Manage Data Tables**.
* **User Details**: View and modify the User details such as First Name, Last Name, and email ID.

<Note> The email ID is a read-only field and can't be modified. </Note>


### Sessions/Devices

This tab displays the User details, the device type, and their last activity timestamp on that session. Use the **Kill Session** button to end a mobile or desktop session for the user.

<Warning> When a session is terminated, no confirmation message is displayed, and the session is immediately and abruptly ended for the user. </Warning>


![Sessions - User Activity](/ai-for-service/administration/images/user-session-new-admin-console.png)

### Cross-Workspace Session Management

This platform manages user sessions at the platform level rather than the workspace level. When users log in, a single session is created for all workspaces. Administrators can monitor active sessions for their users across all workspaces and terminate any user session, regardless of workspace.

#### Security and Privacy Considerations

* **Privacy**: Users must be aware that their sessions in one workspace is visible to administrators of other workspaces they're part of.
* **Enhanced Security**: Cross-workspace monitoring helps detect suspicious activities.
* **Session Management**: When the administrator turns-off a session, users get logged out from the workspace.


#### Best Practices

For Administrators:

* Utilize the session management feature responsibly.
* Notify users before terminating sessions.
* Regularly review active sessions to ensure proper account usage.

For Users:

* Be aware that your sessions are visible across multiple workspaces.
* Log out from inactive sessions to maintain good security practices.
* Report suspicious session activity to the workspace administrator.

### Manage Product Access

This section displays the user's apps including their roles such as Owner, Developer, or Tester. As an admin, you can edit or delete the role of the User for an app. For more information, see [Bot roles](/ai-for-service/administration/role-management).

As an admin, you may edit or delete the role of the User for a given App. Note that you can't delete or modify the role of an App Owner; it's assigned at the time of App creation.

You can also select an App and assign an App role to the user. For more information, see [App roles](/ai-for-service/administration/role-management).

#### Reset a User Password

For users without SSO enabled, admins can send password reset emails to any user, including themselves, from the Admin Console. When the email is sent, a confirmation message appears. The email contains instructions to reset the password.

<Note> When SSO is enabled, password policies do not apply to admins or Kore.ai users because the SSO provider manages password policies.</Note>

<Tip>Even when SSO is enabled, admins can sign in to the Admin Console using their password credentials, bypassing SSO. For more information, see [Logging On Using Your Admin Password Instead of SSO](/ai-for-service/administration/single-sign-on#logging-on-using-your-admin-password-instead-of-sso). </Tip>


#### Delete User

Admins can delete users from the Admin Console using the more icon on the user's page and by selecting a user and clicking the **Delete Selected** button.

<Note> You can't delete the Users if they're owners of the App. You must change the respective app ownership to someone else to delete the user. </Note>

## User Settings

Use the user settings page to manage how users join the account, receive notifications, and get permissions.

### Self Sign-Up for Enterprise Users

Control whether users from your enterprise domain can discover and request access to the account.

You can:

* Block requests from new users.
* Allow discovery and requests from users in the account owner's domain.
  * Auto approve joining requests.
  * Do not auto approve


### Email Notifications

Select when users receive email notifications after being added to the account:

* When invited by an administrator.
* When added or synchronized through AD Server.
* When added through APIs.

### Default User Permissions

Configure the default permissions for new users, including:

* Create Apps.
* Manage Data tables and Views.
* Access Dialog Builder.

When you click **Configure** on the **User Settings** page, the **User Profile Field Controls** panel opens. Use this panel to manage which user profile fields are visible to domain users and which fields end users can edit.

![User Settings](/ai-for-service/administration/images/user-settings-new-admin-console.png)



| Controls | Description |
|----------|-------------|
| Default Fields Section | The user profile fields are displayed by default and can't be disabled from the User Profile page for the user. `First Name`, `Last Name`, `Profile Picture`. You can also select or clear `Allow Edits` to enable or disable the user from overwriting the data. Modifications to the user profile take effect when the user logs in next. |
| Controlled Fields Sections | The user profile fields are disabled by default and can be enabled by the Enterprise Admin or admin user: `Company`, `Department`, `Title`, `Mobile Number`, `Work Number`, `Address (Number & Street)`, `Address (Street/Suite #)`, `City`, `State`, `Zip`, `Country`, `Employee Organisation ID`. |
