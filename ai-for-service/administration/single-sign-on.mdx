Use the **Single Sign-On (SSO)** page in **Security & Control** to configure SSO, two-factor authentication (2FA), and enterprise security keys.


## Configure SSO

SSO lets users authenticate through an external identity provider (IdP) instead of using AI for Service credentials. This simplifies access management and improves security.

If SSO is disabled, users sign in with AI for Service credentials and passwords that are governed by the configured password policy.

AI for Service supports the following SSO protocols:

- OpenID Connect (OIDC)
- Security Assertion Markup Language (SAML)
- WS-Federation

![SSO Configuration](/ai-for-service/administration/images/sso-new-admin-console.png)

To configure SSO:

1. Navigate to **Security & Control** > **Single Sign-On**.
2. Select **Configure**.
3. Enable **SSO**.
4. Select the required authentication protocol.
5. Complete the provider-specific configuration and save the settings.


## Enable or Disable SSO

Enable SSO to require users to authenticate through the configured identity provider. If SSO is disabled or the authentication session expires, users must sign in with platform credentials. When no custom password policy exists, the default password policy applies automatically.

## Configure OIDC

To configure SSO using OpenID Connect:

1. Navigate to **Security & Control** > **Single Sign-On** and select **Configure**.
2. Enable **SSO**.
3. Select **OpenID Connect**.
4. Choose an identity provider, such as Google.
5. Select **Create**.

## Configure WS-Federation

To configure SSO using WS-Federation:

1. Navigate to **Security & Control** > **Single Sign-On** and select **Configure**.
2. Enable **SSO**.
3. Select **WS-Federation**.
4. Select an identity provider and provide the required settings.

### Azure AD

- **Sign-On Endpoint URL**: Endpoint used for sign-in and sign-out requests.
- **Federation Metadata URL**: Metadata document used for authentication.

### Other WS-Federation Providers

- **Sign-On Endpoint URL**: Endpoint used for sign-in and sign-out requests.
- **Identity Provider Issuer**: Entity that authenticates and issues user identities.

Configure the following values in your identity provider:

| Protocol | LDAP Attribute | Claim Attribute |
|----------|---------------|-----------------|
| SAML 2.0 | `nameId`       | `uri`           |
| SAML 1.1 | `nameId`        | `emailAddress`    |



- ACS/Callback URL: `https://idp.kore.com/authorize/callback`
- For ADFS integrations, pass the user's email address as an LDAP attribute.

Select **Create** to save the configuration.

## Configure SAML

Security Assertion Markup Language (SAML) is a standards-based protocol that enables secure web-based SSO by exchanging digitally signed authentication assertions between an identity provider and a service provider.

When a user attempts to access a SAML-enabled application:

1. The application redirects the user to the identity provider.
2. The identity provider authenticates the user.
3. The identity provider returns a signed SAML assertion.
4. The application validates the assertion.
5. The user gains access to the application.

![SAML Configuration](/ai-for-service/administration/images/sso-saml-new-admin-console.png)

## SAML Use Cases

### App Builder Authentication

Developers and administrators can access App Builder through enterprise SSO. After authentication by the identity provider, AI for Service validates the assertion and grants access.

### End-User Authentication

For embedded chat applications, developers can pass the user's SSO token through `secureCustomPayload` and use it for authenticated API requests in dialog tasks, service nodes, or webhooks.

## SAML Provider Configuration

AI for Service provides built-in support for:

- Okta
- OneLogin
- Bitium

<Note>The configuration process is similar for all providers.</Note>

Provide the following information:

- Single Sign-On URL or SAML Endpoint
- Identity Provider Issuer URL
- X.509 Certificate
- ACS URL for SP-initiated SAML flow
- ACS URL for IdP-initiated SAML flow

Optional settings include:

- Skip 2FA Authentication
   - Skip at the Identity Provider (IdP)
   - Skip at the Service Provider (SP)
   - Skip at both levels
- SAML Attribute Mapping
   - **Full Sync**: Replaces existing group and role assignments with values from the SAML response.
   - **Inclusion Only**: Retains existing assignments and adds new assignments from the SAML response.

Mapping options include:

- SAML Attribute Name
- SAML Attribute Value
- Attribute Type (Group Name or Role Name)

Supported role mappings include:

- Admin roles
- App Builder Access
- New App Creation
- Manage Data Tables and Views

Additional options:

- **Restrict Auto-Onboarding**: Prevents automatic onboarding of users who do not exist in the platform.
- **Exclude RequestedAuthnContext**: Removes `RequestedAuthnContext` from SAML authentication requests.

After completing the configuration, select **Save**.

## Configure Your Identity Provider

For Okta, OneLogin, and Bitium:

1. Add the AI for Service application to the identity provider.
2. Configure the ACS URL and Audience URI as required.
3. Copy the SSO URL, Issuer URL, and X.509 certificate into AI for Service.
4. Save the configuration.
5. Sign out and sign back in to verify the integration.

When copying certificates, paste only the content between:

- `BEGIN CERTIFICATE`
- `END CERTIFICATE`


## ADFS Attributes

When using Active Directory Federation Services (ADFS), AI for Service can receive additional user attributes through the SAML assertion.

Supported attributes include:

- `FirstName`
- `LastName`
- `DisplayName`
- `EmailAddress`

<Note>The `EmailAddress` attribute is required. All other attributes are optional.</Note>

**ADFS Attribute Mapping**

Configure the following claim rules:

| Protocol | LDAP Attribute | Claim Attribute |
|----------|---------------|-----------------|
| SAML 2.0 | `nameId`       | `uri`          |
| SAML 1.1 | `nameId`       | `emailAddress` |


## Exclude Users from SSO

Administrators can exclude specific users from mandatory SSO authentication.

Excluded users sign in with platform credentials, while all other users continue to authenticate through the configured identity provider. This option is useful for external users, contractors, or partners who are not provisioned in the organization's identity provider.

To exclude a user:

1. Search for the user's email address.
2. Add the user to the SSO exclusion list.

To restore mandatory SSO, remove the user from the exclusion list. Changes take effect the next time the user signs in.
